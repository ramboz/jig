## Slice 058-01 — `tdd.py` targeted-test support

**Goal:** `tdd.py` can run a single named test and return the normalized
exit code (0 green / 1 red / 2 env error) for *that test alone* — the
prerequisite the red→green teeth gate shells out to.

**DoR:**
- ✅ `tdd.py` exists with runner auto-detection (pytest > vitest > jest),
  the `.jig/test-command` override, and normalized exit codes (spec
  012 / tdd-loop).

**Acceptance Criteria:**

1. **`tdd.py run --test <selector>` runs only the named test** and the
   exit code reflects *that test's* result, not the whole suite: 0 when
   the named test passes, 1 when it fails.
2. **The selector maps per detected runner:** pytest node id
   (`path::test_name`), vitest/jest by test-name filter (`-t`) and/or
   file path. The mapping is covered by a fixture per runner.
3. **A selector matching no test returns exit 2 (env error)**, distinct
   from red (1) — so a caller cannot mistake "test missing/mis-named"
   for "test failing". The stderr names the unresolved selector.
4. **Whole-suite behaviour is unchanged when `--test` is omitted** (no
   regression to existing `tdd-loop` callers).
