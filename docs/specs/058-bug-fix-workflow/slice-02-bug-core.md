## Slice 058-02 — `bug.py` core: new / triage / numbering / board / claim

**Goal:** create and manage a bug record — `bug.py new` allocates a local
number and writes `docs/bugs/NNN-slug.md`, `triage` tiers it (and bows
out of trivial bugs), `status-board` renders `docs/bugs/README.md`, and
the 049-style claim/`--release` machinery is in place.

**DoR:**
- ✅ `_common/parsing.py` provides `clear_frontmatter_field` and
  `FRONTMATTER_TRUTHY` (specs 049 / 052).
- ✅ The 049 claim/release pattern exists in `workflow.py` to mirror.

**Acceptance Criteria:**

1. **`bug.py new <slug>` creates `docs/bugs/NNN-slug.md`** with the
   ADR-0016 frontmatter schema (`status: REPORTED`, `tier`, `severity`,
   `claimed_by`, `regression_test`, `red_confirmed_at`,
   `green_confirmed_at`, `fix_class`, `security_surface: false`,
   `escalated_to`) and the body section skeleton. The number is
   allocated **locally** by scanning `docs/bugs/` (mirrors 049
   local-by-default; `--push` reservation is 058-05).
2. **`bug.py triage <id>` classifies the tier** and, for **trivial**,
   **refuses to keep a record** — it prints the de-escalation guidance
   ("write the failing test with `tdd-loop`, fix, commit; no bug record
   needed") and exits non-zero so the caller can branch on it. Standard
   and gnarly tiers persist `tier:` to frontmatter.
3. **`bug.py status-board` (re)generates `docs/bugs/README.md`** with the
   columns ID / slug / severity / tier / status / reproduces? /
   regression test / claimed_by / escalated_to, and **preserves the
   Notes column** across regen (mirrors the spec board).
4. **Claim/release:** `bug.py new` (and pickup) stamps `claimed_by` with
   the current branch (or `JIG_CLAIM_ID`); a foreign still-open claim is
   **refused** (names the holder, points at `--release`);
   `--release --reason "<why>"` clears `claimed_by` and appends a
   `## Release log` entry.
