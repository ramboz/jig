## Slice 051-02 — worktree-aware ADR reservation

**Goal:** `adr.py new <slug>` reserves an ADR number on `origin/main`
from any branch in any worktree, mirroring slice 051-01's mechanism.

**DoR:**
- ✅ Slice 051-01 DONE: the worktree-aware reservation mechanism (and
  its ADR, if any) exists and is the reference implementation.

**Acceptance Criteria:**

1. **Runs off-main.** `adr.py new <slug>` from a linked worktree on a
   `claude/*` branch reserves an ADR number and exits 0 — no
   `must be 'main'` refusal.
2. **Shares 051-01's mechanism.** ADR reservation uses the same
   reservation primitive 051-01 introduced (extracted to a shared
   helper rather than copy-pasted between `workflow.py` and `adr.py`).
   The two call sites differ only in artifact path/template and commit
   message.
3. **Number from fresh origin/main.** Reserved `NNNN` is next-free
   computed from `git fetch origin main` + the `origin/main`
   `docs/decisions/` tree. An ADR number on `origin/main` but absent
   locally is skipped (the ADR-0010 double-claim this session would
   have been prevented).
4. **No working-state disturbance.** Same invariant as 051-01 AC #2 —
   `HEAD` unchanged, only the new `adr-NNNN-<slug>.md` appears.
5. **Push-failure classification + PR-fallback preserved**, reused from
   the shared helper.
6. **File materialized for editing**, and (per existing adr.py
   behavior) the index regen / accept flow is unaffected.
7. **`--no-push` / `--pr` flags** retain their documented semantics,
   now usable off-main.

**Edge cases to cover explicitly:**
- Offline fetch: refuse clearly (parity with 051-01).
- On-main backward-compat: existing primary-checkout flow must not
  regress.
- Slug collision against an `origin/main`-only ADR: refuses, as today.
