## Slice 051-03 — land-time collision guardrail

**Goal:** `land.py prepare` refuses to land a branch whose new spec or
ADR numbers already exist on `origin/main` under a different slug —
catching collisions that bypass reservation (hand-edits, `--no-push`
local picks, offline work).

**DoR:**
- ✅ `land.py prepare` already emits a readiness report (slice 009-01);
  this slice adds one more check to it.
- ✅ Independent of 051-01/02 — this is the backstop, valuable even if
  reservation is bypassed entirely.

**Acceptance Criteria:**

1. **Collision detected.** `land.py prepare` fetches `origin/main` and,
   for each spec dir / ADR file the branch *adds*, compares its number
   against `origin/main`. A number present on `origin/main` under a
   **different slug** is reported as a blocker naming both slugs and the
   colliding number.
2. **No false positive on the branch's own work.** A spec/ADR the
   branch is legitimately introducing (number absent on `origin/main`,
   or same number+same slug as an in-progress reservation) does **not**
   trip the check.
3. **Strictness per Open question.** A spec/ADR *number* clash is a
   blocker (non-zero readiness, refuses `execute`); softer drift, if
   surfaced at all, is a warning. The blocker integrates with the
   existing readiness-report blocker count.
4. **Offline-degrade.** If `git fetch origin main` fails, the check
   emits a warning ("collision check skipped: <reason>") rather than a
   false blocker — it must not block landing when it simply can't reach
   the remote.
5. **Report shape unchanged otherwise.** The new finding slots into the
   existing `prepare` report format; no restructuring of the readiness
   output.

**Edge cases to cover explicitly:**
- Branch renumbers an existing local spec to dodge a known collision
  (e.g., the 045→049 rescue): once renumbered, the check passes.
- Multiple colliding numbers on one branch: all reported, not just the
  first.
