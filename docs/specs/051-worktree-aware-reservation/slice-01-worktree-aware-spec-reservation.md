## Slice 051-01 — worktree-aware spec reservation

**Goal:** `workflow.py new <slug>` reserves a spec number on
`origin/main` from any branch in any worktree, without checking out
`main` and without disturbing the caller's working state.

**DoR:**
- ✅ Diagnosis confirmed (spec Overview): the `HEAD==main` preflight is
  the blocker; git forbids `main` in a linked worktree.
- ✅ Reservation mechanism chosen (Open question A/B/C) and, if
  load-bearing, recorded as an ADR before implementation. Lean (A) —
  plumbing commit via `git commit-tree`, no checkout.

**Acceptance Criteria:**

1. **Runs off-main.** `workflow.py new <slug>` invoked from a linked
   worktree on a `claude/*` branch reserves a number and exits 0 — it
   does **not** emit `refusing: current branch is ... must be 'main'`.
2. **No working-state disturbance.** Before vs after the reservation,
   `git symbolic-ref HEAD` is unchanged and `git status --porcelain`
   shows no newly-staged or modified entries other than the new
   reservation file. Pre-existing unrelated uncommitted changes in the
   worktree are untouched (the old clean-worktree refusal is gone).
3. **Number from fresh origin/main.** The reserved `NNN` is the
   next-free number computed from `git fetch origin main` + the
   `origin/main` tree, not the local `docs/specs/` listing. A spec
   number present on `origin/main` but absent locally is still skipped.
4. **Reservation lands on origin/main.** On success, a
   `docs(specs): reserve NNN-<slug>` commit is on `origin/main` (direct
   push when permitted).
5. **Push-failure classification preserved.** Non-fast-forward
   (lost-race) drops the stranded reservation commit + file and instructs
   re-run; protection/permission failure triggers the existing
   `reserve/NNN-<slug>` branch + `gh pr create` fallback. The existing
   classifier + guards (gh-on-PATH, github-remote) are reused, not
   reimplemented.
6. **File materialized for editing.** After a successful reservation,
   `docs/specs/NNN-<slug>/spec.md` exists in the caller's working tree.
7. **`--no-push` still works off-main.** Fetches `origin/main`, picks
   the next-free number from it, creates the file locally, performs no
   push. Refusal-on-dirty-worktree is removed here too.

**Edge cases to cover explicitly:**
- `git fetch origin main` fails (offline): refuse with a clear message
  naming the fetch failure; do not silently fall back to a local-view
  number (unless `--no-push`).
- Invoked from the primary checkout *on* `main`: still works
  (backward-compatible — the old happy path must not regress).
- Slug collision against an `origin/main`-only spec dir: refuses, same
  as today.
