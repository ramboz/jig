## Slice 106-01 — scaffold the protected plane and the identity-separation gate

**Goal:** A freshly scaffolded repo ships with real out-of-band protection of its
governing artifacts (CODEOWNERS + protected-path CI + a `protected_paths` config
the soft hooks read), and jig can determine whether the repo satisfies the
two-principal identity-separation precondition for autonomy.

**DoR:**
- ✅ [ADR-0051](../../decisions/adr-0051-autonomy-governance-plane.md) is the governing record.
- ⬜ Confirm current `scaffold-init` output surface + `scaffold.json` schema, and
  that `entry-gate` / `boundary-warn` hooks are the readers of a protected-path
  list.
- ⬜ Pin the environment signal used to compare run-identity vs merge-identity
  (token identity / configured merge principal) before writing the check.

**Acceptance Criteria:**

1. **CODEOWNERS scaffolded.** `scaffold-init` writes a `CODEOWNERS` naming the
   protected paths (`docs/conventions.md`, `docs/decisions/**`, `oracle.sh`,
   frozen `.servo/**/config.json`, and the governance workflow file itself) to an
   owner distinct from the autonomous agent. Observable: the file exists with
   those entries after a scaffold into a fixture repo.
2. **Protected-path CI scaffolded.** A `.github/workflows/` job is written that
   **fails a PR whose diff touches a protected path without owner approval**.
   Observable: on a fixture PR diff touching a protected path, the job's logic
   evaluates to failure; on a diff that does not, it passes. (The workflow file is
   itself a protected path — the self-reference must hold.)
3. **`protected_paths` in `scaffold.json`.** The key is written and is the single
   source of truth; `entry-gate` / `boundary-warn` read it to nudge when an edit
   lands in-boundary. Observable: a hook fixture reads the list and nudges on an
   in-boundary edit; CI (AC 2) enforces out-of-boundary.
4. **Identity-separation precondition.** A deterministic check reports whether the
   principal that would run the loop differs from the principal that can merge to
   the base branch / edit branch protection. When they coincide (single identity,
   e.g. a personal PAT), the check reports the repo **not** autonomy-ready and
   says why. Observable: the check returns distinct results for a two-identity
   fixture vs a single-identity fixture; the servo readiness gate (servo 023)
   consumes the same signal to return `unsafe_for_autonomy`.
5. **Governance-proposal routing is documented as scaffolded policy.** The
   scaffolded material states that a change to a protected artifact must open an
   ADR/spec (surface-and-stop, spec 102), never a self-edit. Observable: the
   scaffolded CODEOWNERS/CI/README material carries this rule.
