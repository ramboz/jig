## Slice 070-02 — hook-injection attribution

**Goal:** Extend the context-growth telemetry/report from read events to
hook-injected `additionalContext`, so we can see whether any hook is adding
repeated context noise worth trimming.

**DoR:**

- ✅ Slice 070-01 DONE; the context-growth JSONL log and `usage.py` report
  surface exist.
- ✅ The hook list that can emit `additionalContext` is verified:
  `jig-context-check`, `jig-memory-scan`, `jig-post-edit-verify`,
  `jig-task-capture`, and `jig-boundary-change-warn`.

**Acceptance Criteria:**

1. **Hook injections are logged.** Every hook path that emits
   `additionalContext` appends one bounded JSONL event to the context-growth
   log. The event includes `timestamp`, `session_id` when present,
   `event: "additional_context"`, `source_hook`, `hook_event_name`,
   `bytes`, estimated tokens, `spec`, and `slice` when `.jig/spec-ref` is
   present.
2. **No full prompt or injected body is logged.** The event may include a short
   `kind` / reason code (for example `memory_terms`, `post_edit_verify`,
   `context_growth`, `task_capture`, `boundary_change`) but must not store the
   full injected text, prompt, file contents, or user message.
3. **Hook behavior remains fail-open.** Logging failures never suppress the
   original `additionalContext`, never block a tool, and never write stderr in
   normal failure paths.
4. **Usage report rolls up injection sources.** The same report surface from
   070-01 shows hook-injection totals by hook/spec/session: event count,
   injected bytes, estimated tokens, and percentage share within the
   context-growth telemetry for the selected spec(s). `--require-marker`
   excludes events without exact marker attribution.
5. **Tests cover all emitting hooks.** Hook-integration tests prove each
   emitting hook writes one bounded event when it emits `additionalContext`,
   writes none when silent, and preserves its existing stdout JSON shape.
   Report tests cover multi-hook fixture aggregation and marker-required
   filtering.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Approach matched the planned shape.** The implementation reused the
   existing context-growth JSON Lines log and marker-based `.jig/spec-ref`
   attribution from 070-01 instead of adding a separate hook telemetry file.
   `hooks/scripts/lib/read_attribution.py` now owns both read-nudge metadata
   and `additionalContext` injection metadata, preserving the fail-open hook
   posture.

   `jig-memory-scan`, `jig-post-edit-verify`, `jig-task-capture`, and

   `scripts/usage.py read-attribution` now renders both existing read-nudge

   `continue: true` with a non-empty `additionalContext` string. The

   hook-injection log it actually ingests.
