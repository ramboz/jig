## Slice 047-01 - plugin-release-contract-validator

**Goal:** Make plugin and release-zip verification check the full
declared install contract instead of shallow existence counts.

**DoR:**
- The expected plugin skill, agent, hook, manifest, marketplace, and
  excluded-path contract is listed in one testable structure.
- Existing release build tests are green before the slice starts.

**Acceptance Criteria:**

1. **Manifest validation is meaningful.** Plugin and marketplace
   manifests require the fields the package manager and users rely on,
   including `name`, `version` where applicable, description, skill or
   plugin references, and valid relative paths.
2. **Hook validation follows jig conventions.** Each shipped hook entry
   invokes `bash ${CLAUDE_PLUGIN_ROOT}/hooks/scripts/...`, points at an
   existing executable script in the release zip, and does not use bare
   script names.
3. **Release zip inventory is explicit.** The smoke test checks expected
   skills, agents, hook scripts, manifest files, and excluded test-only
   paths rather than asserting only "at least one" artifact exists.
4. **Failures are actionable.** A missing skill, missing hook script,
   invalid manifest field, or forbidden included path produces a
   diagnostic naming the offending path and expected rule.

**DoD:**
- [ ] All ACs pass; full test suite green (no regressions).
- [ ] Implementer test coverage exercises each AC with at least one
      fixture. Edge cases listed in the slice are covered explicitly.
- [ ] Reviewed by `reviewer` subagent. Reviewer prompt built by
      `review.py`.
- [ ] Implementation review passed.
