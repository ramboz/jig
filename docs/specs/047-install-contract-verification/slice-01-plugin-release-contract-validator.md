## Slice 047-01 - plugin-release-contract-validator

**Goal:** Make plugin and release-zip verification check the full
declared install contract instead of shallow existence counts.

**DoR:**
- The expected plugin skill, agent, hook, manifest, marketplace, and
  excluded-path contract is listed in one testable structure.
- Existing release build tests are green before the slice starts.

**Acceptance Criteria:**

1. **Manifest validation is meaningful.** Plugin and marketplace
   manifests require the fields the package manager and users rely on,
   including `name`, `version` where applicable, description, skill or
   plugin references, and valid relative paths.
2. **Hook validation follows jig conventions.** Each shipped hook entry
   invokes `bash ${CLAUDE_PLUGIN_ROOT}/hooks/scripts/...`, points at an
   existing executable script in the release zip, and does not use bare
   script names.
3. **Release zip inventory is explicit.** The smoke test checks expected
   skills, agents, hook scripts, manifest files, and excluded test-only
   paths rather than asserting only "at least one" artifact exists.
4. **Failures are actionable.** A missing skill, missing hook script,
   invalid manifest field, or forbidden included path produces a
   diagnostic naming the offending path and expected rule.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

**What shipped.** New `scripts/install_contract.py` — the single
validator-facing plugin/release contract (stdlib-only, pure
`(ok, [diagnostics])` helpers): `EXPECTED_SKILLS` (15), `REQUIRED_AGENTS`,
hook helpers (`validate_hooks` / `_iter_hook_commands`), manifest validators
(`validate_plugin_manifest`, `validate_marketplace_manifest` incl.
relative-source-path enforcement), and `is_excluded_release_path`. Consumed by
`validate_manifests.py` (AC #1), `verify_install.py` plugin mode (full expected
skill set + new `check_hook_contract` — AC #2/#3), and
`test_build_release_zip.py` (explicit inventory + excluded-path scan — AC #3).
+60 tests at implementation (1857 → 1917 green); reconciliation nit-fixes kept
the count and suite green.

**Deviations from the planned approach:**

1. **Restate-plus-consistency-test instead of importing `_TIER_SKILLS`.** The
   plan steered toward *importing* `scaffold._TIER_SKILLS` for a single source
   of truth. `scaffold.py` lives at `skills/scaffold-init/scaffold.py` and
   imports `_common.atomic_io` at module load — not importable from a
   stdlib-only module on `scripts/`'s path. So `EXPECTED_SKILLS` is **restated**
   with a `# source of truth` pointer + a consistency test
   (`test_expected_skills_matches_tier_skills_union`) pinning it equal to the
   live `_TIER_SKILLS` union. Matches the existing `_EXPECTED_HOOK_SCRIPTS` /
   `_EXPECTED_DENY_GLOBS` convention in `verify_install.py`. `REQUIRED_AGENTS`
   and the exclusion predicate are pinned the same way.

2. **Pre-existing drift fixed (behavior change, not pure addition).**
   `verify_install._EXPECTED_HOOK_SCRIPTS` listed 8 scripts while
   `hooks/hooks.json` registers 9 — it was missing `jig-skill-trace.sh`. Fixed
   the constant and added `HookScriptDriftConsistencyTests` pinning it to the
   hooks.json-derived set. Verified scaffold copies hooks via `glob("jig-*.sh")`,
   so real scaffolds already include skill-trace — no scaffold-side gap (that
   surface stays 047-02's).

3. **Plugin-mode check count 4 → 5.** Plugin mode previously validated no hooks;
   this slice adds `check_hook_contract` to `_CHECKS`. `_make_fake_plugin_root`
   was extended to emit a full hooks.json + scripts so existing tests stay green.

4. **`validate_manifests.py` routed through the contract.** plugin.json /
   marketplace.json now validate via `install_contract` rather than the old bare
   `required_fields` mechanism (retained but unused by the two real manifest
   specs). This realizes the spec's Goal-1 "contract in one place"; not a
   divergence. _(Reconciliation note: the legacy bare `required_fields`
   field-check in `ManifestSpec` is now exercised only by synthetic tests — no
   real manifest spec uses it (the two manifests use `install_contract`
   validators; `hooks.json` carries neither). Left live + tested as a generic
   capability; flagged in `docs/inbox.md` as a future-cleanup candidate adjacent
   to design-principle 6, so it isn't mistaken for load-bearing.)_

**Scope decision (noted, no change):** marketplace plugin entries are not
required to carry a `version` (AC #1's "version where applicable") — the real
`marketplace.json` and Claude's marketplace schema carry no per-entry version.
plugin.json *does* require `version`.

**Craft-review nits:**
- **#1 (fixed in reconciliation):** `test_exclusion_predicate_matches_build_release_zip`
  only sampled `fixtures`/`__pycache__`; it now asserts
  `install_contract._EXCLUDED_DIR_NAMES == build_release_zip._EXCLUDE_DIR_NAMES`
  and iterates the real constant (so `.pytest_cache`/`.mypy_cache` are covered).
  Closing a drift-guard gap in a drift-prevention slice.
- **#3 (fixed in reconciliation):** `test_expected_skills_matches_tier_skills_union`
  now restores `sys.path` in a `finally`.
- **#2 (deferred — optional cleanup):** the `test_*.py`/`.pyc`/`.DS_Store`
  predicate is restated in both `install_contract` and `build_release_zip`
  rather than shared. The consistency test makes the duplication safe;
  consolidating is cosmetic, so it is not tracked in `refinement-todo.md`
  (cleanup, not a deferred decision).
