## Slice 047-02 - scaffold-contract-validator

**Goal:** Make scaffold verification prove that a generated target has a
coherent local jig install, including copied helpers and generated
settings.

**DoR:**
- Spec 046 has landed or this slice is paired with the fixes from spec
  046.
- A temporary scaffold fixture can run without network access.

**Acceptance Criteria:**

1. **Copied skill helper closure is verified.** Every helper referenced
   by copied scaffold skills exists in the target under the expected
   `.claude/skills/jig-*` path, and stale plugin-root-only paths fail
   verification.
2. **Generated settings are coherent.** `.claude/settings.json` hook
   entries point at copied hook scripts that exist, use the expected
   shell invocation, and match the scaffold install shape.
3. **Generated metadata is checked.** `scaffold.json` includes the
   fields required by scaffold-mode consumers, including the manifest
   version fixed by spec 046, and rejects stale or missing values.
4. **Docs command/link smoke checks are available.** The verifier can be
   run against a scaffolded target and report broken local helper
   commands or missing local Markdown links with path-specific
   diagnostics.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

**What shipped.** New `scripts/scaffold_contract.py` — the single
validator-facing **scaffold-target** contract (sibling to 047-01's
`install_contract.py`): tier tables (restated + consistency-pinned to
`scaffold._TIER_SKILLS` via `TierTableConsistencyTests`),
`expected_scaffold_skills`, `scaffold_skill_problems` (AC #1 — tier-gated
presence + helper closure + stale-`${CLAUDE_PLUGIN_ROOT}/skills/` detection),
`validate_scaffold_settings` (AC #2 — reuses `install_contract._iter_hook_commands`),
`validate_scaffold_manifest` (AC #3 — `jig_version` + `installed_tiers` /
`installed_skills` ADR-0007 invariants), and `scaffold_doc_problems` (AC #4).
Wired into `verify_install.py` scaffold mode via new
`check_scaffold_skill_closure` / `check_scaffold_manifest` /
`check_scaffold_docs` plus a strengthened `check_scaffold_settings_registration`.
+47 tests (1917 → 1964 green); no regressions.

**Deviations / decisions:**

1. **New sibling module `scaffold_contract.py` (not extending
   `install_contract.py`).** The scaffold contract differs enough (tier-gated
   subset, `.claude/` layout, local-path helper closure, `scaffold.json`, doc
   smoke checks) that a sibling keeps each contract coherent; shared
   hook-command iteration is reused from `install_contract._iter_hook_commands`
   (no duplication). No ADR (`adr_required: false`; the sibling-contract-module
   pattern was already set by slice 047-01).

2. **AC #4 link check scoped to the target's own docs.** The markdown-link
   check covers `docs/**` + `CLAUDE.md` (docs the target owns/renders); copied
   `SKILL.md` bodies are **excluded from the link check** but **included in the
   helper-command check**. Reason: spec 046-01's `_rewrite_skill_md_paths`
   rewrites only `${CLAUDE_PLUGIN_ROOT}/skills/<name>/` bash *helper* paths — NOT
   `../../docs/...` markdown links — so a copied SKILL.md carries source-plugin
   doc-links that resolve to `.claude/docs/...` (absent) in the target; scanning
   them would false-fail every real scaffold. The dangling SKILL.md doc-link is
   a known, deliberate 046 non-rewrite (parked as a 046 follow-up in
   `docs/inbox.md`), not a 047-02 contract violation.

3. **`docs` check gated behind `seed_expected` in `run_completion_summary`.**
   Scaffolded `CLAUDE.md` / `adoption-readiness.md` link into the worked-example
   seed; when the seed is legitimately skipped (non-greenfield `--force`), those
   links dangle. Mirrors the existing seed mode-awareness so a non-greenfield
   scaffold's completion summary doesn't false-fail (fixed two scaffold.py
   end-to-end tests). The standalone `--mode scaffold` verifier still runs `docs`
   unconditionally (correct for greenfield).

**Craft-review nits (deferred — peripheral robustness, parked in `docs/inbox.md`):**
- `_MD_LINK_RE` doesn't handle angle-bracket / reference-style / paren-in-target
  markdown links (low risk; the check is scoped to relative `[text](path)` local
  links and documented as such).
- `read_text()` uses the platform-default encoding rather than explicit
  `encoding="utf-8"` — inherited from `install_contract`; if tightened, do both
  modules together.
Neither is central to the contract's value (unlike 047-01's drift-guard nit), so
deferred rather than fixed inline.
