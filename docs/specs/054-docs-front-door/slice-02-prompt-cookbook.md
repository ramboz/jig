## Slice 054-02 — prompt-cookbook

**Goal:** Give a new user copy-paste reference prompts for the two journeys
that currently have none — scaffolding a project, and driving a spec
end-to-end — in a single discoverable `docs/prompts.md` cookbook.

**DoR:**
- ✅ `docs/workflow.md` (spec lifecycle), `docs/adoption-readiness.md`
  ("your first 30 minutes" skeleton), and the README Skills table are
  available as the canonical source for command names and phase order.

**Acceptance Criteria:**

1. **The cookbook exists and is self-contained.** `docs/prompts.md` (H1
   "Prompt cookbook") exists and is usable on its own. (The README link to it
   is wired in slice 054-03; this slice introduces no forward-broken links.)
2. **Scaffold recipe.** A "Scaffold a new project" recipe gives the exact
   copy-paste prompt and/or slash command to initialize jig in a fresh repo,
   states what the user should expect to happen, and names the immediate next
   step (vision-elicitation).
3. **Full spec-loop recipe.** A "Draft and implement a spec" recipe gives
   copy-paste prompts for each phase of jig's actual lifecycle — draft/clarify
   a spec, SPIDR-split, implement (implementer subagent), the
   post-implementation review passes, reconcile, and land — in the real order.
4. **Prompts are copy-pasteable and captioned.** Each prompt is a fenced block
   with a one-line "use this when" caption; a reader can copy a block verbatim
   without editing it to make it valid.
5. **Only real commands appear.** Every skill/command referenced
   (`/jig:scaffold-init`, `/jig:spec-workflow`, `/jig:slice-land`, etc.) is one
   that exists today per the Skills table — no invented commands, and the
   lifecycle phases match `workflow.py`'s `VALID_STATUSES` / `docs/workflow.md`.
