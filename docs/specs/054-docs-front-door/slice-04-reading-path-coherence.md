## Slice 054-04 — reading-path-coherence

**Goal:** Make the getting-started journey coherent across docs so a newcomer
is never unsure what to read next — surface the good-but-buried
`adoption-readiness.md` and establish one canonical reading order with
consistent "what's next" links.

**DoR:**
- ✅ Slice 054-03 landed — the README is a hub with a single getting-started
  entry, and `philosophy.md` + `prompts.md` exist.

**Acceptance Criteria:**

1. **One canonical reading order exists and is stated.** A new reader can
   follow an explicit sequence (README "Start here" → `philosophy.md` →
   `adoption-readiness.md` → `prompts.md` → `workflow.md` § session workflow)
   without guessing the next step.
2. **adoption-readiness.md is surfaced, not buried.** It is reachable from the
   README's main getting-started path (not only from a blockquote), and from
   `philosophy.md` where relevant.
3. **Cross-doc next-step links are consistent.** Entry docs point onward
   coherently; `adoption-readiness.md` (which predates `philosophy.md` and the
   cookbook) gains next-step / backlinks to them so the path is not
   one-directional or dead-ending.
4. **No orphaned or forward-broken links** across the entry-doc set (README,
   `philosophy.md`, `adoption-readiness.md`, `prompts.md`, `workflow.md`),
   verified by a link-reachability check — extend the existing
   `scripts/test_adoption_readiness.py` link-lint pattern (or add a small
   sibling) so the path stays reachable under future edits.
5. **No always-loaded prompt burden added.** `CLAUDE.md` is not bloated; this
   slice is doc cross-linking, not new hot-cache content.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Deliverables.** Wired the canonical reading path into
   `docs/adoption-readiness.md`: the intro now points to `philosophy.md` (lean
   why) alongside product-vision; a new "**The reading path**" line states the
   explicit order (Why jig → this guide → prompt cookbook → workflow); and
   "Your first 30 minutes" step 4 links the cookbook. New
   `scripts/test_docs_reading_path.py` is an anchor-aware link-reachability
   lint over the five entry docs.
2. **Anchor-aware lint (054-03 carry-forward).** The lint validates BOTH file
   existence AND `#anchor` resolution (GitHub-style heading slugs) across the
   entry-doc set — directly guarding the inbound-anchor class 054-03 hit — and
   pins the bidirectional wiring (README → philosophy + cookbook +
   adoption-readiness; adoption-readiness → onward to both).
3. **Sibling test, not an extension (allowed deviation).** AC#4 said "extend
   `test_adoption_readiness.py` or add a small sibling" — chose the sibling
   (`test_docs_reading_path.py`); the existing test is left intact. Minor
   overlap in link-lint responsibility between the two is acceptable.
4. **Lint hardening folded in (both reviewers, latent gaps).** Both passes
   flagged that the lint scanned raw text: (a) links inside ``` fenced blocks
   would be falsely checked — material because `prompts.md` is fence-heavy;
   (b) headings containing `[text](url)` would slug differently from GitHub.
   Fixed both inline — `_strip_code_fences` runs before link extraction AND
   slug computation, and `_slugs` reduces `[text](url)` → `text` (plus a
   per-file slug cache, the third trivial nit). Behavior is identical on
   current content (no in-fence links, no links-in-headings), so the test
   stays 3/3 green; the hardening is pure future-proofing for the "stays
   reachable under future edits" promise.
5. **Review outcome.** Compliance PASS (5/5 ACs; confirmed the lint genuinely
   guards the `#install-shapes` / `#choosing-an-install-shape` cross-links,
   not vacuously). Craft PASS — no blockers; 3 strengths (the anchor guard
   targets a real previously-unguarded class; the bidirectional-wiring tests
   encode intent; the front door reads coherently cold), nits folded in above.
6. **Reading-order wording nit (left as-is).** A reviewer noted the stated
   order in adoption-readiness reads slightly differently from philosophy.md's
   "See also" list. The path is non-circular and every doc reachable; a
   See-also index legitimately differs from a stated sequence, so forcing
   identical footer prose across docs isn't worth it.
7. **No always-loaded burden (AC#5).** `CLAUDE.md` untouched — doc
   cross-linking + one isolated test only.
8. **Tests.** Full suite 1527 green before the lint hardening; the hardening
   is confined to `test_docs_reading_path.py` (still 3/3, behavior-identical),
   so the total is unchanged. A final full-suite run is taken at spec close.
