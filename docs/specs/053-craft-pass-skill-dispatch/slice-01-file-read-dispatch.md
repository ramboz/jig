## Slice 053-01 — file-read-dispatch

**Goal:** The spec-workflow craft (`pr-review`) and arch (`arch-review`)
passes apply a user-installed richer skill when one exists, by detecting it
on disk and pointing the read-only reviewer subagent at its concrete path to
read-and-apply — instead of relying on a skill router the subagent cannot reach.

**DoR:**
- ✅ Spec 031 craft/arch passes exist and run a read-only `reviewer` subagent.
- ✅ Live probe confirmed the reviewer has no `Skill` tool but can `Read`
  `~/.claude/skills/`.

**Acceptance Criteria:**

1. **Deterministic detection.** `review.py detect_richer_skill(name)` returns
   the absolute path to `~/.claude/skills/<name>/SKILL.md` when that file
   exists, else `None`. It never raises (catches `OSError`/`ValueError`/
   `RuntimeError`) and resolves the home dir via `$HOME`.
2. **Richer branch.** When a richer skill is detected, the craft/arch prompt
   names its concrete path, instructs the reviewer to read it in full (plus any
   reference files) and apply its rubric, states it supersedes the baseline,
   and tells the reviewer to normalize findings into the verdict envelope.
3. **Baseline branch + envelope.** When none is detected, the prompt inlines
   jig's baseline buckets. Both branches preserve the VERDICT / REASONING /
   SPECIFIC ISSUES / RECONCILIATION NOTES envelope (with `[blocker]`/`[nit]`/
   `[strength]` tags for the craft pass).
4. **User-scope only.** A project-scope `.claude/skills/<name>/SKILL.md`
   (possibly jig's own `scaffold-init` baseline copy) does NOT trigger the
   richer branch — guarded against both the `cwd`- and `CLAUDE_PROJECT_DIR`-
   relative detection vectors.
5. **Prose honesty.** The "Claude's skill router resolves …" claims describing
   the reviewer/craft-pass path are corrected in `docs/workflow.md`,
   `skills/spec-workflow/SKILL.md`, both skill Gotchas, and the `review.py`
   docstrings — without breaking the accurate *interactive*-routing description.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Reverse order (implemented → reviewed → landed → spec'd).** This slice was
   built and landed (commit `734e424`) during the originating interactive
   session, then written up as this record afterward at the user's request.
   Honest exception to the normal DRAFT→…→DONE flow: the work originated as a
   "how do I guarantee this works?" question, was diagnosed with a live probe,
   fixed, dogfood-reviewed, and landed before a spec record existed.

2. **Design choice — file-read over a Skill-capable subagent.** Two fixes were
   possible: (a) give the craft/arch reviewer a `Skill` tool and have it invoke
   the skill via the router; (b) detect the skill on disk and have the existing
   read-only reviewer `Read` it. A live probe (a real `reviewer`-shaped subagent
   handed the actual `review.py pr-review` prompt) showed the reviewer has **no
   `Skill` tool** (so (a) needs a new agent) but **can `Read` `~/.claude/`** (so
   (b) works with the existing reviewer). Chose (b): minimal, deterministic
   detection, no new capability on the read-only reviewer. This is exactly spec
   031 Open-question-#1 option (b), promoted from deferred fallback.

3. **Scope — user-scope only.** Detection checks `~/.claude/skills/<name>/`
   only. Project-scope (`.claude/skills/`) is skipped because `scaffold-init`
   copies jig's own baseline skills there, indistinguishable by path from a
   richer project skill. Deferred in `docs/refinement-todo.md` with a resolution
   trigger and a `jig_scaffolded:` marker mitigation.

4. **Co-delivered with spec 041's observability hook.** The same landing commit
   added `hooks/scripts/jig-skill-trace.sh` (`PreToolUse`/`Skill` →
   `.claude/skill-usage.jsonl`). That belongs to spec 041 and is reconciled
   there (041 spec.md "Reconciliation note 2026-06-01"); not duplicated here.

5. **Three-pass review (dogfooded on itself).** Compliance + craft + arch ran
   on the diff via fresh read-only reviewers; the craft and arch passes were
   pointed at the richer `~/.claude/skills/` versions — **live-validating this
   very fix** (they successfully read and applied the richer rubrics).
   - **Compliance: needs-changes** → fixed: (a) the `review.py` *module*
