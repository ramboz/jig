## Slice 077-01 — pyright advisory probe

**Goal:** Add pyright to `health.py` as an `AdvisoryProbe` (per ADR-0017)
— resolved on PATH, else ephemerally, else "skipped" — so `code-health`
reports type findings without ever gating the 0/1/2 exit for scaffolded
projects.

**DoR:**
- ✅ `health.py` + the `AdvisoryProbe` mechanism (spec 060 / ADR-0017)
  are DONE and are the foundation.
- ✅ The ephemeral-pyright assumption (spec Assumptions) is probe-verified
  at implementation start.

**Acceptance Criteria:**

1. **Pyright runs as an advisory probe** — when a Python ecosystem is
   detected, `code-health check` includes a pyright findings summary
   (count + representative diagnostics) in its output.
2. **Never gates exit.** Type findings do **not** change the normalized
   exit code (0 clean / 1 lint-findings / 2 no-linter) — only the primary
   linter (ruff) maps it. (Fixture: a file with type errors but no ruff
   findings → exit 0, type findings reported.)
3. **Resolver chain + degrade.** Pyright is resolved on PATH, then
   ephemerally (`uvx`/`pipx run`); if none resolve, the probe reports
   `skipped (no type-checker)` and the runner swallows the error — no
   crash. (Fixtures: found-on-PATH; ephemeral fallback; none-available.)
4. **Summary, not raw dump.** Output is a tight count + top diagnostics
   (per spec 057's lean-output rule), not the full pyright log.
