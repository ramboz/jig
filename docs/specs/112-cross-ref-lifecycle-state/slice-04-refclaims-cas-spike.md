## Slice 112-04 — refclaims-cas-spike

**Goal:** Resolve ADR-0058 Assumption A1 before the Class-B remote path is built:
determine whether git hosts permit a custom `refs/claims/*` namespace pushed as a
compare-and-swap lock, and confirm the local-worktree mechanics.

**Question:** Can jig use `git push --force-with-lease=refs/claims/<N>: origin
HEAD:refs/claims/<N>` as a create-if-absent distributed mutex on the hosts jig
targets (GitHub personal + EMU at minimum), and does the same-machine
`git update-ref refs/claims/<N> HEAD ""` behave as an atomic local mutex visible
across linked worktrees (A2)?

**Time-box:** 4 hours.

**DoR:**
- ✅ ADR-0058 Accepted; A1/A2 identified as the load-bearing unknowns.

**Findings:** (probed on `origin = git@github.com:ramboz/jig.git`, SSH, default account)

- **A2 (worktree ref sharing) — HOLDS.** Linked worktrees share the ref store:
  `git rev-parse --git-common-dir` → the primary `.git`; this worktree's git-dir
  is under `.git/worktrees/<name>`. A `refs/claims/*` ref created in one worktree
  is enumerable via `git for-each-ref refs/claims/` from any sibling worktree
  **without a push** — so the same-machine concurrent-worktree race is detectable
  and lockable locally.
- **Local CAS — HOLDS.** `git update-ref refs/claims/<N> HEAD ""` (empty
  old-value = must-not-exist) creates the ref (rc 0); a racing second create
  fails atomically — `fatal: cannot lock ref … reference already exists` (rc
  128). A genuine local mutex.
- **A1 (host capability) — HOLDS on GitHub.** `git push origin
  HEAD:refs/claims/<N>` is accepted (`* [new reference]`) — GitHub permits the
  custom `refs/claims/*` namespace. A racing create via
  `git push --force-with-lease=refs/claims/<N>: origin <sha>:refs/claims/<N>`
  (lease expects the ref absent) is **rejected** (`! [rejected] … (stale info)`)
  once the ref exists — a working distributed compare-and-swap. `git push origin
  :refs/claims/<N>` deletes it cleanly (scratch ref removed after the probe).
- **Caveat (not blocking):** probed on GitHub **personal** (`ramboz/jig`) via SSH
  with the default account. EMU (`ramboz_adobe`) org accounts and org-level
  ref-namespace policy were NOT probed; branch protection targets `refs/heads/*`,
  not `refs/claims/*`, so it does not apply — but an org that restricts custom
  ref namespaces would fall back to the ADR-0053 `reserve/<N>` branch path. 112-05
  should keep that fallback available and treat the remote CAS as best-effort.

**Outcome:** `spec 112-05 unblocked` (A1 + A2 + local CAS all hold; the
`refs/claims/*` ref-CAS reservation path is viable, with the ADR-0053
reservation-branch fallback retained for restrictive hosts).
