## Slice 034-15 — federation-verification-profile

**Goal:** Add an optional verification profile so federations can encode
project-specific testing and rollout policy: which repo-specific tests,
integration checks, and deploy-order validations apply to a cross-repo
spec, without making a verification matrix mandatory for simple
federation users.

**DoR:**
- Slice 034-13 is DONE, so federated touchset/cache data exists.
- Slice 034-14 is DONE, so close-out drift reports can label actual
  repo/path changes.

**Acceptance Criteria:**

1. **Optional profile file documented.** Federation central may define
   `docs/federation/verification.yaml`. Absence is a no-op.
2. **Profile schema covers repo-scoped commands.** The schema supports
   project-defined per-repo unit/lint/build/integration/e2e commands,
   environment notes, known skip conditions, and whether a command is
   advisory or required by local policy.
3. **Profile schema covers contract/deploy dependencies.** The schema
   can express that a contract surface (npm package, OpenAPI file/path,
   DB migration/RPC, event topic, deploy unit) implies validation in one
   or more consumer repos and may require a merge/deploy order.
4. **Discovery can seed the profile through importer hints.** Slice
   034-00's adoption report may emit `verification.proposed.yaml` from
   generic signals such as `package.json` scripts, CI config, workspace
   docs (`TESTING.md`, `USE_CASES.md`), service-catalog metadata, and
   obvious repo conventions. Generated entries are marked `discovered`;
   humans can promote them to `declared`.
5. **Review/land integration is advisory by default.** `review.py` and
   `slice-land` include a "federated verification" section when a profile
   is present and the branch touches matching repos/surfaces. Missing or
   failing commands are warnings unless local policy marks the surface
   exclusive/required.
6. **No context blow-up.** The integration reads profile metadata and
   touch/contract caches only. It does not load full repo docs or hot
   caches unless the user explicitly runs `context-pull`.
7. **Standalone and small federation installs stay quiet.** No profile
   means no prompt, no warning, and no generated TODO.
