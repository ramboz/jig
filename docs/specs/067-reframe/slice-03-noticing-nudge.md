## Slice 067-03 — The noticing nudge (standing practice)

**Goal:** Add a soft, best-effort standing practice — "when you bring a new
load-bearing reference (design, vendor / API contract, test infra, compliance
regime, platform) into the project, run `/jig:reframe` before building on it" —
to `docs/workflow.md`, the scaffolded workflow template, and the lifecycle-skill
cross-references, so the common reframe trigger is surfaced as practice. It
*reduces* silent drift; it is explicitly **not** a detector (systematic noticing
is parked, ADR-0024 §4 / §7).

**DoR:**
- ✅ 067-01 landed — `/jig:reframe` exists to point at.
- ✅ The soft-nudge + scaffolded-doc pattern is proven (context-check,
  team-check; the spec 065-04 `docs/workflow.md` managed block carried by
  `scaffold()` / `copy_machinery()`).

**Acceptance Criteria:**

1. **Standing practice in jig's `docs/workflow.md`.** A subsection ("Bringing in
   a new load-bearing reference") states the practice, names the reference
   categories, and points at `/jig:reframe`.
2. **Downstream projects inherit it.** The same practice appears in the
   scaffolded `docs/workflow.md` template, so `scaffold-init` / `copy-machinery`
   carry it — consistent with the 065-04 forward-only doc path.
3. **Cross-reference from the lifecycle surfaces.** `spec-workflow` and
   `adr-workflow` (SKILL.md or `docs/workflow.md`) carry a one-line "if a
   load-bearing reference moved, reach for `/jig:reframe` first" pointer.
4. **Best-effort, labelled as such — no detector.** The practice text states it
   is a soft reminder; **no hook or automated trigger** is added (systematic
   detection parked, ADR-0024 §7). Matches the ADR-0011 / ADR-0013
   defense-in-depth posture: jig recommends, the human acts.

_Testability note: all four ACs are structural and unit-testable (the standing
