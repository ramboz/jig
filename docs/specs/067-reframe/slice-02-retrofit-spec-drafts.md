## Slice 067-02 — Retrofit spec drafts

**Goal:** Extend `/jig:reframe` so that, for every `retrofit` disposition in the
keystone manifest, it also mints a **retrofit spec draft** via `workflow.py new`
— one goaled "bring `<artifact/code>` in line with `<reference>`", its
`## Assumptions` citing the new reference — so the behaviour-change work the
reframe spawns is queued in the spec lifecycle, not left for the session to
hand-author.

**DoR:**
- ✅ 067-01 landed — the keystone ADR, the re-baselining manifest, and the
  `retrofit` disposition exist.
- ✅ `workflow.py new <slug>` reserves + scaffolds a spec that rides the full
  review-gated lifecycle.

**Acceptance Criteria:**

1. **One retrofit spec draft per `retrofit` disposition.** The SKILL.md specifies
   that for each `retrofit` row in the keystone manifest, the skill reserves a
   spec via `workflow.py new` and drafts it.
2. **Each retrofit spec is goaled on the reference.** The draft's overview /
   slice goal reads "bring `<artifact/code>` in line with `<reference>`", naming
   the moved reference.
3. **`## Assumptions` anchored on the new reference.** The retrofit spec's
   `## Assumptions` cite the new reference, so a future frame-critique on that
   spec is anchored correctly (ADR-0024 §3).
4. **No `retrofit` disposition is silently dropped.** Every `retrofit` row maps
   to a drafted spec, or to an explicitly-recorded reason it was not drafted that
   is surfaced to the user — the disposition→draft mapping is complete and
   visible. The keystone manifest is updated to link each `retrofit` row to its
   drafted spec number, closing the loop.

_Testability note: where ACs 1–4 govern what the SKILL.md specifies (the
per-`retrofit` `workflow.py new` flow, the goal + `## Assumptions` anchoring, the
complete-and-linked mapping) they are structural and unit-testable on the SKILL.md
surface; the *content quality* of a generated draft is judgment, like 067-01._
