## Slice 048-02 - adoption-readiness-guide

**Goal:** Add a concise adoption/readiness guide that helps a user decide
whether jig is the right scaffold for their repo and how to start safely.

**DoR:**
- Slice 048-01 has identified the public entry points that should link
  to the guide, or an implementation plan names the link locations.
- The guide scope is constrained to jig adoption, not broad
  organization-level AI-native leadership guidance.

**Acceptance Criteria:**

1. **A new adoption guide exists.** Add a docs page, proposed path
   `docs/adoption-readiness.md`, that answers: who jig is for, who
   should not use it yet, prerequisites, install shape choice, first
   30-minute workflow, and how to evaluate the first few slices.
2. **Readiness checklist is concrete.** The guide includes a short
   checklist covering at least: Git repo health, Claude Code access,
   Python 3 availability, test command availability or explicit absence,
   willingness to keep specs/ADRs in-repo, and human review expectations.
3. **The guide stays jig-sized.** It links out to broader concepts
   instead of recreating Mysticat-style leadership, leveling, or
   organization adoption curricula.
4. **Entry points link to it.** `README.md` and/or
   `docs/product-vision.md` point users to the guide from the setup or
   target-user sections.
5. **Docs lint protects the link.** A lightweight test or existing docs
   check verifies that the linked adoption guide exists and is reachable
   from README.
