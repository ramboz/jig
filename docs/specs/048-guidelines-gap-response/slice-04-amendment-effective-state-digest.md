## Slice 048-04 - amendment-effective-state-digest

**Goal:** Give readers a concise current-state view of amendment-bearing
artifacts while preserving ADR-0008's historical amendment policy.

**DoR:**
- ADR-0008 remains the accepted closed-spec drift policy.
- At least two closed artifacts with `## Amendments` exist, so the
  digest has real input data.

**Acceptance Criteria:**

1. **Digest generation exists.** Add a script or `workflow.py`
   subcommand that scans documented amendment-bearing artifacts and
   emits a concise digest of current overrides.
2. **Digest entries are actionable.** Each entry includes the artifact
   path, amendment date/title, short override summary, and link/path back
   to the source artifact.
3. **Historical artifacts remain untouched.** The implementation does
   not rewrite accepted ADRs or closed specs to erase original text.
4. **README/status-board path is discoverable.** The digest command or
   generated file is linked from README, the spec status board, or the
   closed-spec drift policy documentation.
5. **Tests cover both presence and absence.** Test fixtures include an
   artifact with amendments and an artifact without amendments; output is
   stable, sorted, and clear in both cases.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Deliverables:** a read-only `amendments` subcommand in
  `skills/spec-workflow/workflow.py` (`find_amendment_artifacts` /
  `amendment_digest` / `_amendments_section` + the `_AMENDMENTS_HEADING_RE`
  / `_AMENDMENT_ENTRY_RE` regexes, modeled on the `stale` precedent:
  returns a report string, informational, always exit 0). Scans
  `docs/specs/**/*.md` (spec.md + slice files) and `docs/decisions/*.md`,
  emits a path-sorted, date-sorted digest. Discoverability pointer added to
  `docs/workflow.md` § Reconciliation rules (AC #4) — phrased as a "run this
  command" line, NOT a `## Amendments` heading, so the `LiveProseHasNoAmendments`
  guard in `scripts/test_closed_spec_drift_sweep.py` stays green. 5 tests.
- **Blocker fixed (compliance review):** the first cut matched a `##
  Amendments` heading *inside* a ```` ```markdown ```` fence. ADR-0008
  documents the amendment *format* in exactly such a fence (lines 96-108:
  "the above is what a `## Amendments` block on spec 016 would look like"),
  so the digest false-positived ADR-0008 as carrying spec 016's "Hook
  count" override. **Fix:** `_strip_code_fences` removes fenced regions
  before scanning; added `test_ignores_fenced_amendments_example`
  reproducing ADR-0008's exact shape. The live digest now correctly reports
  **1 amendment across 1 artifact** (spec 016 only). This is the bug the
  independent compliance pass was for — the craft pass (logic-in-isolation)
  missed it.
- **DoR correction:** the slice DoR assumed "≥2 closed artifacts with `##
  Amendments`." In reality only **one** genuine one exists (spec 016);
  ADR-0008's is the fenced illustration above. The `grep -l '^## Amendments'`
  that suggested two counted that fenced example. The digest is correct with
  one real artifact; the multi-artifact path is covered by synthetic test
  fixtures.
- **Nits addressed (both reviewers):** (a) the digest heading is now a
  markdown link `## [path](path)` so it's a navigable link/path back (AC #2),
  not a bare path; (b) the date↔title separator char class widened to
  em-dash / en-dash / hyphen (`[—–-]`) to avoid a silent-skip on en-dash.
- **AC #2 interpretation (deliberate):** the amendment *title* (e.g. "Hook
  count: five → seven") serves as the "short override summary" — jig
  amendment titles ARE one-line override summaries, and the title is more
  concise current-state than the drift-explaining prose body. Both review
  passes flagged this as a defensible reading worth recording.
- **Review:** compliance (`jig:reviewer`) `needs-changes` → 1 blocker
  (fenced false-positive) fixed + retested → resolved; craft (`pr-review`)
  PASS (strengths: faithful `stale` idiom, section-boundary correctness,
  graceful read-error handling, absence + slice-file edges tested). Craft
  also noted the slice prose/DoR cites ADR-0008 as live policy while the
  code correctly cites ADR-0010 (which supersedes it) — the slice prose is
  pre-supersession, not a code issue.
- **No ADR:** additive, reuses the read-only `stale` pattern; no new
