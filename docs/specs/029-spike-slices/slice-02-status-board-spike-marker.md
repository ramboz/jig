## Slice 029-02 — status-board-spike-marker

**Goal:** Make spike slices visually distinct in `docs/specs/README.md`
(the status board) so risk-shaped decomposition is scannable. After
this slice lands, a reader skimming the status board can spot
every open spike across all specs at a glance — without having to
grep for `kind: spike` or open individual slice files.

**DoR:**
- ✅ Slice 029-01 DONE — `kind: spike` is a parseable, validated
  frontmatter field.
- ✅ `workflow.py status-board` already renders per-slice rows and
  preserves the Notes column across regens.

**Acceptance Criteria:**

1. **Spike slices carry a visible marker in the status board.** A
   slice with `kind: spike` renders with a leading marker (icon or
   short tag — pick during implementation; see Open questions in
   the spec) in its row. Non-spike slices render unchanged. Pick
   one form and use it consistently — no per-spec overrides.
2. **Marker survives regeneration.** Running `workflow.py
   status-board` regenerates the file with markers intact. The
   marker is derived from the slice's `kind:` field, not stored
   separately in the status-board — so manual edits to the status
   board can't desync it from the underlying slice.
3. **Marker does not break existing parsers.** The status board is
   read by `workflow.py` itself (and possibly downstream tools).
   Whatever marker form we pick survives the existing parsing
   round-trip. Tests confirm regenerate-then-re-parse produces an
   equivalent in-memory representation.
4. **Marker is documented.** The status board's preamble (or
   `docs/specs/README.md` header) explains what the marker means
   for new contributors who don't yet know the spike convention.
5. **Tests cover both presence and absence.** A test fixture with a
   `kind: spike` slice produces a status board where that slice
   carries the marker; a fixture without any spikes produces a
   status board with no markers; a mixed fixture renders both
   correctly.
6. **No regressions to existing column shape.** Existing columns
   (spec, slice, status, notes, etc.) keep their widths,
   alignments, and content. The marker is additive — a small
   prefix on one column, not a new column. Snapshot test pins the
   exact rendered shape.
7. **Status-board regen idempotency held.** Running
   `workflow.py status-board` twice in a row produces an identical
   file on the second run (no marker churn, no whitespace drift).
