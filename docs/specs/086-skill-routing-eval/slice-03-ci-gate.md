## Slice 086-03 — register the eval as a named ci_check gate

**Goal:** Make the routing eval a first-class, legible gate in `ci_check.py`
(alongside ruff / `spec_lint` / manifests / host-package drift), so a routing
regression is named as such in CI rather than surfacing only as an anonymous
`run_tests.py` failure.

**DoR:**
- ✅ 086-01 DONE — the eval + its `--min-rank1` ratchet exist and pass on the
  current tree.
- ✅ Probe-verified: `ci_check.py` composes named gate steps (e.g. it already
  runs `build_host_packages.py --check`); the routing gate slots in as one more.

**Acceptance Criteria:**

1. **Named gate.** `ci_check.py` runs the routing eval as an explicitly named
   step (invoking the `unittest` gate or `skill_routing.py --min-rank1 <floor>`)
   and lists it in its gate roster/output.
2. **Fails on regression.** A routing regression (a collision ≥ the error
   threshold, or a rank-1 rate below the floor) fails `ci_check.py` with a
   message that names the routing gate — verified by a test that induces the
   failure against a fixture.
3. **Green on current tree.** `ci_check.py` still passes end-to-end after the
   wiring.
4. **jig idiom.** Zero new dependencies; `ruff`/`pyright` clean; the wiring is
   covered by `scripts/test_ci_check.py` (or a sibling test).

### Deviation log (after reconciliation)

The original spec/ACs are preserved above.

1. **Ordering deviation from DRAFT.** The DRAFT said "register … as a named
   gate"; the as-built wiring places the routing gate **first** in both
   `ci_check.py` and `ci.yml`. Rationale (from the compliance re-review): the
   suite (`run_tests.py`) already enforces the floors via `test_skill_routing.py`,
   so a later-ordered named step would never fail on a regression (the anonymous
   suite fails first) — defeating AC2's "fail *by name*". Running it first (it is
   <1s) makes the named gate the step that fails. Also chose
   `skill_routing.py --min-rank1 <floor>` over an alternative "unittest-only"
   gate so the CI log carries the human-readable collision/routing report.
2. **Compliance re-review fix.** First compliance pass was needs-changes on AC2
   (ordering + missing induce-failure test). Reordered + added
   `test_routing_regression_fails_named_gate_before_suite`, which asserts the
   named gate runs and fails *before* the suite (stdout contains the step name).
3. **Craft nits folded in:** single-sourced the `ci_check.py` floor from
   `skill_routing.MIN_RANK1_RATE`; renamed the roster test honestly
   (`test_ci_steps_roster_and_order`) with a note that it does not parse `ci.yml`;
   reworded the induce-failure test comment.
4. **Logged, not fixed here:** the `ci.yml` `--min-rank1 0.85` literal can't
   import the module constant (a YAML step can't), so it can lag a future
   ratchet — backstopped by the suite's own floor check and annotated inline. The
   real fix (a test that diffs `ci.yml`'s `run:` lines against `ci_steps()`,
   including the floor) is logged in `refinement-todo.md` ("guard ci_check.py ↔
   ci.yml step parity"), which also covers the pre-existing "Code-health floor
   (ruff)" name divergence.
5. **ADR trigger:** none (thin CI integration; no rejected-alternative decision
   beyond the ordering rationale captured above).
