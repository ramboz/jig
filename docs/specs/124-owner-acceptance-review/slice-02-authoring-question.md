## Slice 124-02 — authoring question

**Goal:** When a slice looks UI-related and nobody has said whether the owner
wants to try it, jig asks, so the owner does not have to remember the
`owner_review` flag.

**DoR:**
- ✅ Slice 124-01 defines the flag and the pass.
- ✅ The design-fidelity authoring nudge (step 5a in
  `skills/spec-workflow/SKILL.md`, spec 104-02) was read; this question sits
  next to it.

**Acceptance Criteria:**

1. **`workflow.py owner-review-status <spec> <slice>` classifies the
   slice.** The first word of its output is one of: `required` (flag
   truthy), `declined` (flag present with any other value), `ask` (flag
   absent and the slice is UI-related), `not-applicable` (flag absent, not
   UI-related). For `ask` the line also gives the reason (the matched words,
   or `design_review`) and, when the slice sets `design_review: true`, that
   the recommended answer is yes.
2. **"UI-related" is a stated, cheap rule.** A slice is UI-related when it
   sets `design_review: true`, or when its text (frontmatter and HTML
   comments excluded) contains at least one term from a single word list
   defined in one place in `workflow.py`. Matching is case-insensitive on
   whole words, with an optional plural `s`. The same list is printed in
   `skills/spec-workflow/SKILL.md`.
3. **The question is on the authoring path.**
   `skills/spec-workflow/SKILL.md` "Creating a new spec" has a step next to
   5a that tells the author to run `owner-review-status` for each slice and,
   on `ask`, to ask the owner whether they want to try the slice themselves
   before it is reconciled, then write `owner_review: true` or
   `owner_review: false` from their answer. It says the agent does not
   answer for the owner, and that `design_review: true` makes yes the
   recommended answer without setting the flag.
4. **The careless path still gets the question.** `workflow.py transition`
   into `READY_FOR_REVIEW`, `READY_FOR_IMPLEMENTATION`, `IN_PROGRESS` or
   `REVIEWED` for a slice classified `ask` writes a note to stderr naming
   the slice, the reason and the two ways to answer. The transition's result
   and exit code are unchanged. No note is written for `required`,
   `declined` or `not-applicable`, or for a slice with no frontmatter.
5. **`workflow.py session-plan` shows the open question.** A slice
   classified `ask` gets one line saying the owner has not been asked, with
   the reason. Other slices' plans are unchanged from 124-01.
6. **The slice template carries the flag.**
   `templates/docs/specs/slice-template.md` has a commented
   `owner_review:` line that says when to set `true`, when to set `false`,
   and that the owner's check belongs with the review batch, not in the DoD.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Scan scope narrower than AC2's wording.** AC2 says the slice text
   minus frontmatter and HTML comments. The scan covers the title, goal,
   DoR and acceptance criteria only: it stops at the first `###`–`######`
   heading or the DoD, because the template's optional scenario text
   ("CLI, service, and UI scenarios") and DoD boilerplate would otherwise
   ask on every slice. SKILL.md states the narrower rule, and a test pins
   that the untouched template is not UI-related. Known gap: a `###` inside
   a code fence before the ACs ends the scan early.
2. **An empty `owner_review:` counts as not asked** (AC1 said any other
   present value is `declined`). A blanked template line must not silence
   the question (craft finding).
3. **Multi-word terms match across a line wrap** (compliance/craft
   finding): spaces in a term match any whitespace run.
4. **One wording of the question** shared by the transition note, the CLI
   and `session-plan`; the `design_review` recommendation is appended after
   it.
5. **`session-plan` skips `DONE` slices** for the "NOT ASKED YET" line
   (compliance finding: 12 finished slices in this repo classify `ask`).
6. **Plurals are the optional `s` only**, as AC2 states: `checkboxes` does
   not match `checkbox`.
7. **The transition note prints before later gates run**, so a transition
   that is then refused still shows it; result and exit code unchanged.
8. **No frontmatter means `not-applicable`** (beyond AC4, which only says
   no note is written): such a slice has nowhere to carry an answer. A
   hyphen counts as a word boundary (`UI-related` matches `ui`); SKILL.md
   says so.
9. **Dogfood.** This slice classifies `ask` itself (it mentions "UI"); the
   flag is left absent because only the owner may answer it.
10. **Reviews.** Compliance round 1 `needs-changes` (wrapped terms, scope
   deviation unrecorded, DONE slices), round 2 `pass`; craft `pass` with
   nits. All folded in above.
