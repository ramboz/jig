## Slice 097-01 — append-only accepted decisions convention

**Goal:** Every newly scaffolded jig project inherits a stated convention that
**accepted** decision records are append-only — struck-and-dated, never erased —
while **proposed/draft** ones stay freely editable, closing the decision-erasure
hole (issue #124 instance 1) at the scaffold rather than each project
rediscovering it.

**DoR:**
- ✅ Maintainer approved question 1 scoped to accepted decisions only.
- ✅ Target file identified: `templates/docs/conventions.md.template`.
- ✅ Host-mirror regeneration path known (`scripts/build_host_packages.py`).

**Acceptance Criteria:**

1. **The scaffolded conventions template states the rule.**
   `templates/docs/conventions.md.template` carries a decisions convention, in
   the file's existing **Rule → Why → How to apply** format, that says accepted
   decision records are immutable: correct them by striking-and-dating (or
   superseding), never by deleting or overwriting the original wording.
2. **The rule is scoped to accepted records — drafts stay editable.** The
   convention explicitly says a **Proposed / draft** decision record's body may
   be edited inline, so it does not contradict the maintainer's ruling on
   question 2. A reader cannot come away thinking a draft ADR is frozen.
3. **The host mirrors match source.** `hosts/claude/templates/docs/conventions.md.template`
   and `hosts/codex/plugins/jig/templates/docs/conventions.md.template` are
   regenerated so `python3 scripts/build_host_packages.py --check` passes.

**Notes:** This ports a rule jig already holds for itself
(`docs/conventions.md:75-77`) into the scaffold. Keep it lean — one Rule block
under a `## Decisions` section — per the template's own "add rules as the project
encounters real decisions" framing and the context-cost discipline (specs
055/057). The rule must not assert anything about *proposed* ADRs being locked;
that is question 2, which the maintainer declined.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **No deviation from the planned shape.** All three ACs were implemented as
   specified: a single `## Decisions` Rule/Why/How block in
   `templates/docs/conventions.md.template`, scoped to `Accepted` records, with
   an explicit `Proposed`/draft carve-out.
2. **Reviewer finding folded in (craft nit).** The craft pass flagged that
   `test_template_keeps_proposed_records_editable` asserted only the bare token
   `"edit"`, which an inverted "must never be edited" phrasing would also satisfy
   — a half-vacuous test in a spec about vacuous tests. Strengthened to require
   the editable *sense* (`"edit freely"` / `"edit its body inline"`), and
   mutation-verified (inverting the carve-out now reddens it).
3. **AC #3 (host-mirror parity) verified via the CI drift-guard, not a unit
   test** — consistent with the spec's stated approach. `python3
   scripts/build_host_packages.py --check` ran green after regenerating both
   mirrors.
