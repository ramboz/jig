## Slice 052-05 — security-review-baseline

**Goal:** Ship a slim Tier-1 `jig:security-review` skill so a user with no
other security skill installed still gets a heuristic security review pass —
one that orchestrates real scanners when present and defers to any richer
installed skill when one exists.

**DoR:**
- ✅ Slice 052-01's ADR is Accepted (baseline-skill deferral shape + Tier
  placement decided).
- ✅ The `contracts` (orchestrate-if-present) and `pr-review` (slim
  baseline + description-based deferral) skills are confirmed as the
  structural precedents to mirror.

**Acceptance Criteria:**

1. **The skill exists and auto-triggers.** `skills/security-review/SKILL.md`
   ships a Tier-1 judgment skill (no heavy `.py` helper, like
   `pr-review` / `arch-review`) that auto-triggers on security-review
   phrasings ("review this for security", "any vulnerabilities here",
   "security pass on this diff") and is explicitly invocable.
2. **Defers to richer installed skills.** Its description carries a
   category-based deferral hint so Claude's router prefers any user /
   project / built-in skill identifying as security review / SAST /
   vulnerability analysis (the `pr-review` / `contracts` pattern). When
   such a skill is present, jig's baseline yields to it.
3. **Orchestrates installed scanners, never bundles.** When it is the
   active skill, it detects common scanners on `PATH` (e.g. `semgrep`,
   `bandit`, `gosec`, `npm audit` / `osv-scanner`), runs the ones present,
   and folds their output into the review. It installs nothing and degrades
   gracefully to heuristic-only when none is present.
4. **Heuristic baseline floor.** With no scanner and no richer skill, it
   still produces a structured pass over the diff across named categories
   (secrets, injection, authn/authz, crypto misuse, input validation,
   unsafe deserialization, dangerous functions, dependency risk), in the
   four-bucket verdict envelope jig's other review skills use (summary /
   blockers / nits / strengths).
5. **Honest framing.** The SKILL.md states it is a best-effort heuristic
   baseline — not a guarantee, and not a substitute for CI security
   scanning or a dedicated security review — and points to richer skills +
   out-of-band scanning (consistent with 052-01 / ADR-0011).
6. **Tier bookkeeping is consistent.** Adding the skill updates
   `_TIER_SKILLS` (the `scaffold.py` Tier-1 constant) and the tier lists in
   `README.md`, `docs/product-vision.md`, and
   `skills/vision-elicitation/worked-example-jig.md`; the 038-03
   `TierSkillSetTests` doc↔code consistency tests pass with Tier 1 = 8
   skills.
7. **Tests cover it.** Skill-surface tests (description + deferral-hint
   present, like `pr-review`'s) + an orchestration test (scanner-present
   vs scanner-absent paths) + the tier-consistency tests.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **New skill.** `skills/security-review/SKILL.md` (judgment skill, **no
   `.py` helper**, like `pr-review`/`arch-review`/`contracts`) + a pure-file
   surface test `test_security_review_skill_surface.py` (40 tests, 11
   classes). Mirrors the `pr-review` precedent's structure + depth.
2. **Category-based deferral (AC2).** The description defers to "any other
   installed skill whose description identifies it as handling security
   review, SAST, or vulnerability analysis" — category-based, not
   name-locked (names the user's own / `adobe-security-*` / a built-in
   `security-review` only as examples). Cleanly separated from
   `/jig:pr-review` (general craft), `/jig:independent-review` (spec
   compliance), and the `jig-secret-scan` hook (secret *prevention* vs this
   skill's *review*) — the craft reviewer singled out the four-way
   "rule of thumb" + the triple-reinforced review-vs-prevention boundary as
   strengths.
3. **Orchestration (AC3).** Documents both the scanner-present path (detect
   `semgrep`/`bandit`/`gosec`/`npm audit`/`osv-scanner` on `PATH`, run the
   present ones, fold output in as *input to judgment*, install nothing) and
   graceful degradation to a heuristic-only pass when none is present. The
   concrete invocation table (`semgrep --config auto`, etc.) is
   **illustrative** — ADR-0013 leaves the exact roster/order tunable
   (tracked in `docs/refinement-todo.md` "Scanner set + detection order"),
   not a new commitment.
4. **Eight categories + envelope (AC4) + honest framing (AC5).** Secrets /
   injection / authn-authz / crypto misuse / input validation / unsafe
   deserialization / dangerous functions / dependency risk, each with
   "what triggers a finding" bullets, in the Summary/Blockers/Nits/Strengths
   envelope + a worked example. Honest-framing section: best-effort
   heuristic, not a guarantee, not a substitute for CI scanning / dedicated
   review / a richer skill; real controls out-of-band (ADR-0013 / ADR-0011).
5. **Tier bookkeeping (AC6) — Tier 1 = 8, total = 15.** Updated
   `_TIER_SKILLS["tier-1"]` (scaffold.py) + three hardcoded parallel lists:
   `TierSkillSetTests.EXPECTED_TIER_1` (test_scaffold.py), **and
   `TierUpgradeTests.TIER1` (`skills/migrate/test_migrate.py`)** — the
   latter was **not** in the implementer brief (the brief assumed the
   tier-gated copy tests read `_TIER_SKILLS` directly; migrate's upgrade
   test keeps its own hardcoded copy). Plus the docs: `docs/product-vision.md`
   ("8 Tier 1" + new numbered item 15), `skills/vision-elicitation/worked-example-jig.md`
   (count + two lists; pinned by `test_..._tier_line_in_sync`), and
   `README.md` ("15 skills total" / "all 15 skills"). So the floor's
   "fixed-size" identity is now 7 Tier 0 + 8 Tier 1.
6. **Review scope.** Compliance (`jig:reviewer`) + craft (`general-purpose`
   via the `pr-review` router) both `pass`, no blockers. Craft nits were
   cosmetic and left as-is for house-style consistency with `pr-review`:

   `cart.py` example); one surface assertion uses slightly generic
   substrings; the `~/.claude/skills/security-review/` example path is
   name-anchored but framed as an example. No arch pass (judgment skill, no
   new module boundary; ADR-0013 governs). No new deferrals (the deferred

   refinement-todo from 052-01). Full suite green: 1582 tests, OK
