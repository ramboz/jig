## Slice 052-01 — security-floor-policy-adr

**Goal:** Record, in an ADR, exactly what the jig security floor contains,
what it defers to richer security skills, whether the secret-scan hook
blocks or warns, and the honest enforcement boundary — so the build slices
(052-02/03/04) work against a decided scope instead of inventing it.

**DoR:**
- ✅ [Spec 048](../048-guidelines-gap-response/spec.md) Gap inventory C
  lists the security floor as P1 (the scope source).
- ✅ The Adobe `adobe-security-*` skill family is confirmed available as
  the depth-deferral target (foundations / lang / cloud / services /
  client).
- ✅ [ADR-0011](../../decisions/adr-0011-spec-gate-model.md) is on hand as
  the precedent for a gate that is a *deliberateness / defense-in-depth*
  control, not a human-only firewall.

**Acceptance Criteria:**

1. **The policy ADR is Accepted.**
   [ADR-0013](../../decisions/adr-0013-security-floor-policy.md) (drafted
   `Proposed` alongside this slice) is reviewed and moved to `Accepted` via
   `/jig:adr-workflow accept`, and the index is regenerated.
2. **Floor scope is enumerated.** The ADR lists exactly what jig *ships*
   (secret-ignore `.gitignore` patterns, an agent-time secret-scan hook,
   conservative `permissions.deny` defaults, a lean security MUST-rules
   block, **and a slim `security-review` baseline skill** that
   orchestrates-if-present + defers-if-richer) and what it explicitly *does
   not ship* (a bundled SAST engine, deep IaC / exhaustive per-language
   rulesets). Depth defers to **any richer installed security skill** — the
   user's own, `adobe-security-*`, or a built-in `security-review` — not a
   single vendor, per the per-skill deferral pattern (design principle #5).
3. **Block-vs-warn is decided** for the secret-scan hook, with rationale.
   The leading option to evaluate: **block** on a high-confidence secret
   pattern, overridable by a deliberate env var mirroring
   `JIG_CONVENTIONS_APPROVED`, so the hook is a deliberateness gate, not a
   hard sandbox.
4. **The honesty boundary is stated.** The ADR records that the floor is
   agent-time prevention + defense-in-depth, **not** a guarantee against
   secret leakage, and names the out-of-band real-enforcement channel (CI
   secret-scanning, server-side git hooks, branch protection) — mirroring
   ADR-0011's framing.
5. **The `security-review` baseline shape is decided.** The ADR fixes that
   `jig:security-review` is a slim Tier-1 (default-on) judgment skill that
   orchestrates installed scanners (never bundles them) and defers to any
   richer installed skill via a description-based deferral hint (the
   `pr-review` / `contracts` pattern), and that wiring it into the
   post-implementation review flow is deferred until signal.
6. **Any deferred decision is captured.** If implementation of
   052-02/03/04/05 is expected to surface an open question (e.g., the
   secret-pattern ruleset source, or the scanner set the baseline shells
   out to), it is recorded in `docs/refinement-todo.md` with a resolution
   trigger and linked from the ADR.
