## Slice 052-03 — destructive-command-guardrail

**Goal:** A freshly scaffolded project's `settings.json` denies the
dangerous git/file commands by default, so an accidental force-push /
hard-reset / `rm -rf` is refused without relying on the agent reading a
rule.

**DoR:**
- ✅ Slice 052-01's ADR is Accepted (floor scope incl. the permissions
  posture decided).
- ✅ `scaffold.py`'s marker-based `settings.json` merge (slice 016-02) is
  the integration point.

**Acceptance Criteria:**

1. **Conservative deny defaults are scaffolded.** `scaffold-init` writes a
   `permissions.deny` array into `.claude/settings.json` covering at least
   force-push, hard-reset, and `rm -rf` (the guidelines `permissions.md`
   conservative project default), using deny-glob shapes that match the
   documented dangerous forms.
2. **Merge is non-destructive + marker-tracked.** The deny rules merge into
   an existing `settings.json` without dropping user-added `permissions`
   entries, using the same jig-managed marker mechanism as the hooks block;
   re-running scaffold is idempotent.
3. **Honest framing.** The accompanying comment/doc states deny-globs are
   defense-in-depth — they can miss flag permutations (e.g.
   `git push origin main --force`) — so the primary control remains
   behavioral + out-of-band, per `permissions.md` ("deny rules are
   defense-in-depth, not a firewall") and 052-01.
4. **Tests cover it.** Scaffold tests assert the deny array is present in a
   fresh scaffold and is preserved/merged (not duplicated, not clobbering
   user entries) when `settings.json` pre-exists.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Deliverables.** `skills/scaffold-init/scaffold.py` gains the
   `_PERMISSIONS_DENY_DEFAULTS` constant (8 globs + an honest-framing
   comment) and `_merge_permissions_deny`, called from `_merge_settings`.
   `templates/CLAUDE.md.template`'s `## Security (MUST)` block gains one
   line on the deny defaults (block stays ≤12 lines). Tests:
   `PermissionsDenyTests` in `test_scaffold.py`.
2. **Marker = set-membership (faithful adaptation, AC2).** `permissions.deny`
   is a plain string array, so it can't carry the hooks block's per-entry
   `metadata.managed_by_jig` marker. jig-ownership is therefore membership
   in `_PERMISSIONS_DENY_DEFAULTS`: the merge keeps every non-jig deny entry
   (user denies survive verbatim + in order), then appends jig's full set —
   idempotent, no duplicates, never drops user `allow`/`ask`/custom-`deny`.
   Pure function (asserted non-mutating).
3. **Migrate inherits via the shared path (pre-wires 052-04).** Because the
   merge lives in `_merge_settings` — on the shared `_copy_hooks_and_register`
   path used by both `scaffold()` and `migrate copy-machinery` — the deny
   defaults already flow into a migrated project. 052-03 only built +
   verified the greenfield path and did **not** touch `migrate.py`; 052-04
   still owns the migrate-parity assertion + install verification. Both
   reviewers confirmed this is sound design, not scope leakage.
4. **Deny set extends beyond AC1's three named forms (allowed — "at least").**
   Ships force-push permutations (`--force`, `-f `, `* --force`,
   `*--force-with-lease*`), `git reset --hard`, and three `rm` recursive-force
   forms (`-rf`, `-fr`, `-r -f`). `--force-with-lease` (the *safer* push) is
   denied because the prefix-glob model can't express "deny `--force` but
   allow `--force-with-lease`" (the `--force*` prefix matches both); the
   conservative floor denies all force-push. Recorded as a craft-reviewer
   judgment call.
5. **Accepted non-exhaustive gaps (deliberate, defense-in-depth per ADR-0013).**
   Both reviewers (correctly) flagged forms the globs miss: bare
   `git push -f` (the `-f ` glob needs a trailing arg), mid-command short
   `-f`, and macOS BSD uppercase `rm -Rf`/`-fR`. These are NOT fixed — the
   floor is non-exhaustive by design (the honest-framing comment + AC3 say
   so), exactly as 052-02 treated secret-pattern false-negatives. The
   tuning surface + these specific gaps are parked in
   `docs/refinement-todo.md` ("Destructive-command deny-set tuning") with a
   resolution trigger. Chasing exhaustive globs would contradict the
   "floor, not firewall" principle.
6. **One existing 016-02 test updated (live-prose inline correction, ADR-0010).**
   `test_scaffold_mode.py::test_j_existing_non_hook_field_preserved` asserted
   `permissions` passes through entirely untouched; since `permissions.deny`
   is now jig-managed, that contract changed. Switched its pure
   untouched-field assertion to `env` and added "allow preserved verbatim +
   deny gains jig defaults" assertions, pointing to `PermissionsDenyTests`
   for the full contract. Necessary, not optional.
7. **Reconciliation hardening (post-review).** Both reviewers noted the
   dedup-of-a-user-supplied-jig-exact-glob path was only *implicitly* tested
   (via re-scaffold idempotency). Added a direct unit test
   (`test_merge_dedups_user_supplied_jig_exact_glob_unit`) seeding a
   jig-exact glob as a user entry and asserting it appears exactly once.
8. **Review scope.** Compliance (`jig:reviewer`) + craft (`general-purpose`
   via the `pr-review` router) both `pass`, no blockers. No arch pass (same
   reasoning as 052-02: arch-shaped decisions live in ADR-0013 / 052-01;
   this reuses the existing settings-merge machinery). Full suite green:
   1526 tests, OK (skipped=3). (A stray `.claude/review-queue.json` the
   implementer subagent wrote — against spec 039's removal of that
   mechanism — was caught by `test_review_queue_cleanup` on the
   orchestrator's independent re-run and removed; it is gitignored and was
   never committed.)
