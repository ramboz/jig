## Slice 052-02 — secret-prevention-floor

**Goal:** A freshly scaffolded project ships secret-ignore patterns, an
agent-time secret-scan hook, and a lean security MUST-rules block — so the
agent is blocked from writing an obvious secret and `.env`-style files are
git-ignored from day one.

**DoR:**
- ✅ Slice 052-01's ADR is Accepted (floor scope + block-vs-warn decided).
- ✅ `scaffold.py`'s hook-copy + marker-based `settings.json` merge (slice
  016-02) is the integration point for wiring a new hook.

**Acceptance Criteria:**

1. **Secret-ignore patterns are scaffolded.** `scaffold-init` writes or
   merges a target `.gitignore` containing at least `.env`, `.env.*`,
   `*.pem`, `*.key`, `secrets/`, `credentials/`. An existing `.gitignore`
   is appended to, not clobbered; re-running scaffold is idempotent (no
   duplicate blocks).
2. **An agent-time secret-scan hook exists and is wired.** A new
   `hooks/scripts/jig-secret-scan.sh` is registered as a `PreToolUse` hook
   on `Edit|Write|MultiEdit` in `hooks/hooks.json` and in the scaffolded
   `.claude/settings.json`. On a high-confidence secret pattern in the
   pending content it acts per the 052-01 decision (block with the
   deliberate-override env var), emitting a **structured** message: the
   offending file, the matched rule, and how to override (aci-design
   "structured, specific, fixable" error shape).
3. **The hook is precise (false-positive guard).** Given fixtures it
   flags an obvious AWS access key, a PEM private-key block, and a `.env`
   assignment with a real value; it does **not** flag placeholder/example
   forms (`API_KEY=<your-key>`, `${VAR}`, `xxxxx`) or `*.example` files.
4. **A lean security rules block is scaffolded.** `templates/CLAUDE.md.template`
   gains a short `## Security (MUST)` block (≈≤ 12 lines) stating the
   no-secrets MUST rules and pointing to `adobe-security-*` / user skills
   for depth — keeping CLAUDE.md within its lean budget (design principle
   #2).
5. **Honest framing.** The hook docstring, the block message, and the rules
   block all state the floor is agent-time + defense-in-depth, not a
   guarantee, and name the out-of-band channel (per 052-01 / ADR-0011).
6. **Tests cover it.** Hook unit tests (block / allow / override fixtures,
   in the style of `scripts/test_post_edit_verify.py`) plus scaffold tests
   asserting the `.gitignore` patterns, the settings registration, and the
   rules block all land in a fresh scaffold.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Deliverables.** New: `hooks/scripts/jig-secret-scan.sh` (the PreToolUse
   hook) + `hooks/scripts/test_jig_secret_scan.py` (31 tests). Modified:
   `hooks/hooks.json` (joined the existing PreToolUse `Edit|Write|MultiEdit`
   group — no new matcher group), `skills/scaffold-init/scaffold.py`
   (`_write_gitignore_secret_block` / `_render_gitignore_block` + the
   `_GITIGNORE_SECRET_PATTERNS` constant, wired into `scaffold()` as step
   5b before the `scaffold.json` sentinel), `templates/CLAUDE.md.template`
   (a 7-line `## Security (MUST)` block after `## Development conventions`),
   and `skills/scaffold-init/test_scaffold.py` (`SecurityFloorTests`).
2. **Hook registration auto-propagates.** Because `_build_jig_hook_entries`
   derives the scaffolded `settings.json` from `hooks/hooks.json` and
   `_copy_hooks_and_register` globs `jig-*.sh`, registering the hook in
   `hooks/hooks.json` + dropping the script was sufficient for AC2 — the
   scaffold picks it up automatically (pinned by the SecurityFloorTests
   settings/registration assertions).
3. **Roster-sync edits (consequence, not scope creep).** Adding a new hook
   script forced one-line additive updates to three `_EXPECTED_HOOK_SCRIPTS`-
   style rosters: `skills/scaffold-init/test_scaffold_mode.py` and
   `scripts/test_verify_install.py` (without them those suites fail on the
   extra script) and `scripts/verify_install.py` (kept honest so the
   floor's hook is in the verified set — this also gives 052-04 a head
   start; 052-04 still owns asserting floor presence end-to-end).
4. **Curated-minimal ruleset + override (ADR-0013 / refinement-todo).**
   Three high-confidence rules: AWS access-key id (`(?:AKIA|ASIA)[0-9A-Z]{16}`),
   PEM private-key block, and a secret-named `.env`-style assignment to a
   non-placeholder value. Override env var: **`JIG_SECRET_SCAN_APPROVED=1`**
   (mirrors `JIG_CONVENTIONS_APPROVED`). Blocks with `exit 2` + a structured
   stderr message (file + matched rule + fix + override); fails **open** on
   any internal error, like `jig-spec-gate.sh`.
5. **Bootstrapping-hazard handling.** The plugin's hooks are live in the
   authoring session, and this hook becomes a live PreToolUse Edit|Write
   gate. Both test files therefore assemble every secret-shaped literal at
   runtime by concatenation, so no source file contains a contiguous
   secret-shaped match — the tests can't trip the very hook they test, and
   no real-looking secret is committed (also best practice).
6. **Out-of-AC tuning decisions (within the curated-set tradeoff).** The
   `.env` rule requires a value ≥ 6 chars and accepts `=` and `: `
   (env + light YAML) separators; the placeholder allowlist expands the
   AC's named examples with `fixme`/`redacted`/`sample`/`test-`/`fake`/etc.
   All chosen to keep false positives near zero. The location of this
   tuning surface is now referenced from the `docs/refinement-todo.md`
   "Secret-pattern ruleset source" entry.
7. **Accepted false-negatives (deliberate, per ADR-0013).** Substring
   placeholder collisions (a real value that merely *contains* `sample` /
   `test-` is treated as a placeholder) and JSON `"key": "value"` (`:`
   without a trailing space) assignments are not caught. This is the
   curated-minimal-set tradeoff — the escape valve is the override var and
   the documented out-of-band enforcement (CI / git-hooks / branch
   protection). Flagged by both reviewers; no fix (by design).
8. **Reconciliation fixes applied after the review passes:**
   - **(compliance finding — internal consistency)** `.env.*` would have
     git-ignored the very `.env.example` the hook's block message tells
     users to commit. Added `!.env.example` / `!.env.sample` /
     `!.env.template` / `!.env.dist` negations (after `.env.*`, matching the
     hook's skipped placeholder suffixes) + a regression test
     (`test_gitignore_reincludes_env_placeholder_templates`).
   - **(craft nit)** Cleaned the block-message construction in
     `jig-secret-scan.sh` — replaced the vestigial-`f'…' + var + f'…'`
     blend with direct `{rule_name}` / `{where}` f-string interpolation
     (output verified identical; tests still green).
   - **(craft nit)** Replaced the dense one-line `.gitignore` append-separator
     ternary with an explicit three-case `if/elif/else` + comment.
9. **Review scope.** Compliance pass (`jig:reviewer`) and craft pass
   (`general-purpose` via the `pr-review` router) both returned `pass` (no
   blockers). No arch pass: the architecture-shaped decisions (the hook's
   existence, block-vs-warn, floor scope, honesty boundary) are recorded
   and already reviewed in ADR-0013 / slice 052-01, and this slice is a
   faithful implementation reusing the existing hook-registration
   machinery — so the slice's `arch_review` hint was left OFF. Full suite
