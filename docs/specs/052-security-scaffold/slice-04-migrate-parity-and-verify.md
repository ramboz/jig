## Slice 052-04 — migrate-parity-and-verify

**Goal:** Existing jig projects can adopt the security floor via
`migrate copy-machinery`, and install-contract verification fails when the
floor is absent — so the floor isn't only a greenfield benefit.

**DoR:**
- ✅ Slices 052-02 + 052-03 have landed (the floor artifacts exist:
  secret-scan hook, `.gitignore` patterns, `permissions.deny` defaults).
- ✅ Spec 038-04's `copy-machinery` / `--add-tier` machinery is the copy
  path; the floor is infra (never tier-gated → always copied).
- ✅ Coordination checked with [spec 047](../047-install-contract-verification/spec.md)
  (install-contract verification): if 047 has landed, extend its validator;
  if not, this slice adds a minimal floor-presence check rather than
  blocking on it.

**Acceptance Criteria:**

1. **Migrate brings the floor.** `migrate copy-machinery` copies + registers
   the secret-scan hook, writes the `.gitignore` secret patterns, and merges
   the `permissions.deny` defaults into an existing jig project —
   idempotently and without clobbering user edits.
2. **The floor is ungated infra.** The security artifacts are copied
   regardless of `installed_tiers` (consistent with 038-02 "infra never
   gated").
3. **Install verification asserts the floor.** `scripts/verify_install.py`
   (or the spec-047 contract validator, if landed) checks that a
   scaffolded/migrated project has the secret-scan hook registered, the
   `permissions.deny` defaults, and the `.gitignore` patterns; it reports a
   failure when any is missing.
4. **Tests cover presence and absence.** Fixtures for a project with the
   full floor (passes) and one missing each artifact (fails), plus a
   migrate-parity test confirming an already-scaffolded project gains the
   floor on `copy-machinery`.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Most of the floor already flowed to migrate via the shared path.** The
   secret-scan hook (`_copy_hooks_and_register` globs `jig-*.sh`) and the
   `permissions.deny` defaults (`_merge_settings`) already reached
   `migrate copy-machinery` after 052-02/03, since `migrate.py` delegates to
   `scaffold.copy_machinery`. The **only** missing piece was the
   `.gitignore` floor, which lived solely in `scaffold()`.
2. **`.gitignore` wired into `copy_machinery` (AC1) — exactly-once invariant.**
   `_write_gitignore_secret_block(target)` now runs inside `copy_machinery`
   (after `_copy_hooks_and_register`, **ungated** — AC2), and `scaffold()`'s
   former unconditional step-5b call moved into the `--plugin-only` `else`
   branch. Result: the floor is written **exactly once** on all three paths
   — greenfield `--with-machinery` (via `copy_machinery`), greenfield
   `--plugin-only` (via the `else`), and `migrate copy-machinery` (via
   `copy_machinery`). The block is idempotent regardless, so any double-call
   would be a harmless no-op. `test_gitignore_written_in_plugin_only_mode`
   guards the `else` branch.
3. **Install verification (AC3) landed in `verify_install.py`, not spec 047.**
   Spec 047 (install-contract-verification) is still **DRAFT/not landed**, so
   per the slice DoR's fallback the three floor-presence checks
   (`check_scaffold_secret_scan_registered`,
   `check_scaffold_permissions_deny_floor`,
   `check_scaffold_gitignore_secret_floor`) were added to
   `scripts/verify_install.py` (`_SCAFFOLD_CHECKS`, so
   `run_completion_summary` picks them up). The `secret-scan-registered`
   check is **stronger** than the generic `check_scaffold_settings_registration`:
   it pins a jig-managed `Edit|Write|MultiEdit` entry referencing
   `jig-secret-scan.sh`, not just *any* jig hook. **When 047 lands, fold
   these three checks into its validator rather than duplicating them.**
4. **Floor-marker constants are duplicated (justified, stdlib-only).**
   `verify_install.py` is stdlib-only and must not import `scaffold.py`, so
   the representative deny-glob subset, the `.gitignore` marker, and the
   secret patterns are hardcoded there (mirroring the pre-existing
   `_EXPECTED_HOOK_SCRIPTS` precedent) and again in the two test fixtures
   (`test_verify_install.py`, `test_migrate.py`). **Lockstep-edit surface:**
   renaming `_GITIGNORE_BLOCK_BEGIN` or a named deny glob in `scaffold.py`
   requires updating those literals in four places. The dogfood test
   (`test_verify_install_scaffold_mode_all_checks_pass`, which runs the
   checks against a real scaffold) catches any drift, so the risk is bounded.
5. **Test-fixture decisions (non-AC).** `_make_fake_scaffold_root` was
   extended to carry the full floor (a "complete scaffold" now includes it)
   and aliased as `_make_full_floor_scaffold_root`; each absence test strips
   **one** artifact off that complete fixture and asserts the matching check
   fails (so the fold-in does not mask absences). The dogfood PASS-line
   assertion switched from a literal `4` to `len(_SCAFFOLD_CHECKS)` so it
   won't need re-pinning when later slices add checks.
6. **Review scope.** Compliance (`jig:reviewer`) + craft (`general-purpose`
   via the `pr-review` router) both `pass`, no blockers. Craft praised the
   single-write if/else, the strip-one-off absence technique, and the
   registry-bound dogfood count; its only nits were the justified
   constant-duplication noted in §4. No arch pass (reuses the existing
   `copy_machinery` / `_merge_settings` machinery; arch-shaped decisions are
   in ADR-0013). No new deferrals surfaced (the floor's open items are
   already parked under 052-01/02/03). Full suite green: 1542 tests, OK
   (skipped=3). (Implementer wrote no stray `.claude/review-queue.json`
   this time — confirmed absent.)
