## Slice 052-04 — migrate-parity-and-verify

**Goal:** Existing jig projects can adopt the security floor via
`migrate copy-machinery`, and install-contract verification fails when the
floor is absent — so the floor isn't only a greenfield benefit.

**DoR:**
- ✅ Slices 052-02 + 052-03 have landed (the floor artifacts exist:
  secret-scan hook, `.gitignore` patterns, `permissions.deny` defaults).
- ✅ Spec 038-04's `copy-machinery` / `--add-tier` machinery is the copy
  path; the floor is infra (never tier-gated → always copied).
- ✅ Coordination checked with [spec 047](../047-install-contract-verification/spec.md)
  (install-contract verification): if 047 has landed, extend its validator;
  if not, this slice adds a minimal floor-presence check rather than
  blocking on it.

**Acceptance Criteria:**

1. **Migrate brings the floor.** `migrate copy-machinery` copies + registers
   the secret-scan hook, writes the `.gitignore` secret patterns, and merges
   the `permissions.deny` defaults into an existing jig project —
   idempotently and without clobbering user edits.
2. **The floor is ungated infra.** The security artifacts are copied
   regardless of `installed_tiers` (consistent with 038-02 "infra never
   gated").
3. **Install verification asserts the floor.** `scripts/verify_install.py`
   (or the spec-047 contract validator, if landed) checks that a
   scaffolded/migrated project has the secret-scan hook registered, the
   `permissions.deny` defaults, and the `.gitignore` patterns; it reports a
   failure when any is missing.
4. **Tests cover presence and absence.** Fixtures for a project with the
   full floor (passes) and one missing each artifact (fails), plus a
   migrate-parity test confirming an already-scaffolded project gains the
   floor on `copy-machinery`.
