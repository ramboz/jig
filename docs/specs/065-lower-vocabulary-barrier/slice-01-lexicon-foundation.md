## Slice 065-01 — Lexicon foundation (shipped data + overlay loader)

**Goal:** Ship jig's canonical vocabulary as a structured data file plus a
`_common/` loader that merges the consuming project's glossary on top (project
wins), so all downstream consumers read one definition per term from one place.
Implements [ADR-0021](../../decisions/adr-0021-lexicon-home-and-overlay.md).

**DoR:**
- ✅ Lexicon format decided (structured JSON) and overlay rule decided
  (project glossary wins) — clarify Q1/Q2.
- ⬜ [ADR-0021](../../decisions/adr-0021-lexicon-home-and-overlay.md) accepted
  (currently Proposed) — it fixes the lexicon home + overlay-precedence contract
  this slice implements.
- ✅ `skills/_common/` exists as the home for shared stdlib-only helpers
  (`parsing.py`, `atomic_io.py`, …) and is copied by scaffold / `copy-machinery`.
- ✅ `docs/memory/glossary.md` exists as the seed + the per-project overlay source.

**Acceptance Criteria:**

1. **A shipped structured lexicon exists.** `skills/_common/lexicon.json` is
   valid JSON, keyed by term, each entry carrying at least `short` (one-line) and
   `plain` (a junior-readable paragraph), plus optional `example` and `see_also`
   (list of term keys). It is seeded with the jig vocabulary currently in
   `docs/memory/glossary.md` (e.g. SPIDR, ADR, vertical slice, reconciliation,
   deviation log, DoR, AC, DoD, frontmatter, Tier 0/1/2). A schema/shape test
   asserts every entry has the required fields and that `see_also` keys resolve.
2. **The loader merges shipped + project overlay, project wins.**
   `lexicon.py load(project_dir)` returns a dict `term → entry`. The project
   overlay is parsed from `docs/memory/glossary.md` in its **documented canonical
   format** — `## Term` (H2) heading + first paragraph as the definition (per the
   `glossary.md.template` directive *"Format: `## TERM`, followed by definition
   prose"*; **not** H3). A term present only in the shipped lexicon appears; a
   term present only in the project glossary appears; a term in **both** resolves
   to the **project** definition. Covered by a fixture glossary using `## Term`
   headings that overrides one shipped term and adds one new term — and a
   negative fixture using the wrong heading level asserts it is ignored (no false
   override).
3. **Missing / malformed project glossary is fail-soft.** When `docs/memory/
   glossary.md` is absent, `load` returns the shipped lexicon unchanged; when it
   is present but unparseable, `load` degrades to shipped-only without raising.
4. **Stdlib-only, hook-safe.** `lexicon.py` imports only the Python 3 standard
   library (no third-party deps) and exposes a function callable from the
   `python3 -c` environment a hook runs in (no package-root import gymnastics).
   A test imports and calls it the way the hook will.
5. **Travels as machinery.** The new files live under `skills/_common/`, a tree
   already copied by `scaffold-init` and `migrate copy-machinery`; a test (or the
   migrate manifest) asserts `lexicon.json` + `lexicon.py` are within the copied
   set, so existing projects pick them up on their next `copy-machinery` with no
   new copy path.
