## Slice 035-01 — exclude-fixtures-from-installs

**Goal:** Add `fixtures` to the directory deny lists in both install
surfaces (scaffold copy + release zip) so a `fixtures/` dir at any
depth under a skill subtree is skipped, and pin both surfaces with
regression tests.

**DoR:**
- ✅ `find skills -type d -name fixtures` shows only
  `skills/migrate/fixtures/`. Re-verify at pickup — cheap insurance
  against drift since the 2026-05-23 audit (per spec Q5).

**Acceptance Criteria:**

1. **Scaffold copy skips `fixtures/`.** After
   `scaffold.py:_copy_skill_dir` runs over a source tree containing
   `skills/migrate/fixtures/conflict/…`, the destination has no
   `fixtures/` directory anywhere under the copied skill dirs.
   Observable: a regression test asserts the absence of any
   `fixtures` path component in the destination tree.
2. **Release zip excludes `fixtures/`.** After
   `scripts/build_release_zip.py` packages the plugin, the resulting
   zip contains no entry with a `fixtures/` path component anywhere
   under `skills/`. Observable: a regression test inspects the zip
   manifest.
3. **Exclusion matches at any depth.** A `fixtures/` directory nested
   below the skill root (e.g. `skills/foo/sub/fixtures/`) is also
   skipped on both surfaces (per spec Q1). Observable: at least one
   regression test uses a nested-fixtures input.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Plan adherence.** Implementation followed the spec's Option A
   single-slice plan exactly — extend the two existing deny lists,
   add regression tests on each surface. No design deviations.

2. **Craft-review refactor folded in.** The first-pass implementation
   carried two near-identical `any(part == X for part in rel.parts)`
   clauses in `_copy_skill_dir` (one for `__pycache__`, one for
   `fixtures`). Craft review flagged this as a maintainability nit;
   consolidated into a module-level `_SKILL_DIR_EXCLUDES` frozenset
   driving a single membership check. Mirrors the structural shape
   already used by `_EXCLUDE_DIR_NAMES` in `build_release_zip.py`.
   Tests unchanged and still green.

3. **Comment-provenance correction.** First-pass comments at both
   deny-list sites cited "clarification Q4" as the source of the
   any-depth rule. Q4 covers the reserved-name / no-escape-hatch
   policy; the any-depth rule is from Q1. Comments updated to cite
   both Q1 (any-depth) and Q4 (reserved-name) explicitly.

4. **Test coverage.** Spec asked for "at least one regression test
   per surface, with at least one nested-fixtures input." Delivered:
   4 tests total — 2 on the scaffold side (root + nested in one;
   sibling-survives sanity in the other), 2 on the zip side
   (real-source regression against live `skills/migrate/fixtures/`;
   synthesized nested-fixtures test). Over-coverage, not under.

5. **No refinement-todo entries.** No decisions were deferred during
   implementation. Clarifications Q1–Q5 covered every choice that
   came up.

6. **No new ADR needed.** The reserved-name policy is a small
   convention captured inline in the deny-list comments; it does
   not rise to the level of an architectural decision warranting
   its own ADR.
