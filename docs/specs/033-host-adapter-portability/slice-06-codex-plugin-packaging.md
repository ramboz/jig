### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Docs and local contract re-verification.** Codex plugin packaging was
   re-checked against the current Codex plugin surface before implementation:
   `.codex-plugin/plugin.json` is the manifest, plugin skills live under
   root `skills/`, plugin hooks are discovered from root `hooks/hooks.json`,
   and plugin hook commands receive `PLUGIN_ROOT` with `CLAUDE_PLUGIN_ROOT`
   compatibility. Local CLI sanity check used `codex-cli 0.133.0`; the docs
   cross-check used the official Codex plugin build docs and custom-agent
   docs.
2. **Codex plugin is a generated package, not a second source tree.**
   The checked-in source stays canonical for Claude plugin/scaffold and Codex
   scaffold. `.codex-plugin/plugin.json` is checked in, while
   `scripts/build_codex_plugin.py` materializes the installable Codex plugin
   tree into `dist/codex-plugin/plugins/jig`, renders Codex skill copies with
   plugin-root helper paths, and writes the generated Codex marketplace
   descriptor beside the package.
3. **AC #3 deviation: custom-agent discovery.** Current Codex plugin docs
   cover plugin manifest, skills, and hooks, but current Codex custom-agent
   docs define discoverable agents as TOML files under project-local or
   user-local `.codex/agents/`. This slice therefore bundles the canonical
   `agents/*.md` prompts once in the generated Codex plugin package as
   non-discoverable prompt source. It does not add an unsupported `agents`
   field to `.codex-plugin/plugin.json`, and it does not claim the Markdown
   prompts are discoverable Codex custom agents. Rendering `.codex/agents/*.toml`
   from the canonical prompts is deferred and tracked in
   `docs/refinement-todo.md`.
4. **Manifest validation now covers Codex.** `scripts/validate_manifests.py`
   now includes `.codex-plugin/plugin.json` in the CI preflight and checks the
   Codex-required manifest fields used by this package.
5. **Release packaging now covers both manifests.** The release zip includes
   `.codex-plugin/plugin.json` alongside `.claude-plugin/plugin.json`, and
   release-please version lockstep updates both plugin manifests.
6. **Safety fix from craft review.** `build_codex_plugin.py` now refuses
   unsafe output directories before deleting an existing destination, covering
   the source root, source-owned runtime paths, and ancestors of the source
   tree.
7. **Review nits to watch.** The Codex plugin skill renderer intentionally
   duplicates some Codex scaffold rewrite policy in a build-time shape; keep
   this as a drift watch item if future Codex path or wording rules change.
