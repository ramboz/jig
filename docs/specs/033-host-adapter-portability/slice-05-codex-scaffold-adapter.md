### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Current Codex surface was re-verified locally before implementation.**
   The scaffold target follows Codex 0.133's observed project-local
   surfaces: `AGENTS.md`, `.codex/skills/`, `.codex/agents/*.md`, and a
   top-level `.codex/hooks.json`. Stale candidate shapes such as
   `.agents/` and TOML hook config were not implemented.
2. **Runtime support files were broader than the AC wording.** Copied
   helpers need source-relative fallbacks, so Codex scaffold mode also
   materializes `.codex/templates/`, a raw `.codex/hooks/hooks.json`, and
   non-discoverable unprefixed helper aliases under
   `.codex/skills/<name>/` without `SKILL.md`. The aliases preserve
   existing peer-helper imports while avoiding duplicate Codex skill
   registrations.
3. **Codex hook protocol currently mirrors Claude's practical contract.**
   The adapter registers all seven logical hooks in `.codex/hooks.json`
   and rewrites copied hook scripts to `CODEX_PROJECT_DIR` /
   `CODEX_HOME` paths. Tests execute generated Codex warning and
   blocking hooks with stdin payloads and assert `additionalContext` /
   exit-2 behavior, matching the local Codex-compatible hook convention
   available during implementation.
4. **Codex hook safety uses a file-level marker.** Claude settings merge
   safety is per-entry (`hooks.*.metadata.managed_by_jig`), while Codex
   hook config is generated as one `.codex/hooks.json` with top-level
   `metadata.managed_by_jig: true`. Scaffold refuses existing unmarked
   Codex hooks before copying any runtime files unless `--force` is
   passed.
5. **Codex agents are capability notes, not capability enforcement.**
   `implementer`, `reviewer`, and `architect` render into
   `.codex/agents/jig-*.md` with an adapter note because Codex Markdown
   agent files cannot enforce the same tool isolation expressed in
   Claude agent frontmatter.
6. **`migrate copy-machinery` remains Claude-only in Codex scaffolds.**
   The Codex `migrate` skill can run `report`, `rename-decisions`, and
   `split-slices` from the copied `.codex/skills/jig-migrate/` helper
   path, but `copy-machinery` still delegates to Claude scaffold
   machinery and is documented as Claude-only. `rename-decisions` also
   keeps the helper's Claude-shaped cross-reference scan scope
   (`docs/`, `CLAUDE.md`, `.claude/`). This deliberate limitation is
   tracked in `docs/refinement-todo.md` as the host-aware migrate
   machinery decision.
7. **Two maintainability nits are accepted for this slice.** Codex
   currently subclasses `ClaudeScaffoldRenderer`, and Codex `SKILL.md`
   rendering relies on broad prose rewrites plus a migrate-specific
   restoration block. Both were review-flagged as future maintainability
   concerns, not current correctness blockers.
8. **Architecture docs were updated instead of an ADR.** The
   host-adapter boundary, concrete Claude/Codex scaffold surfaces,
   managed-file metadata policy, and Codex hook marker are recorded in
   `docs/architecture.md`; no external API/schema contract changed.
