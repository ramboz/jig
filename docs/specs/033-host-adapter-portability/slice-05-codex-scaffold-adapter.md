## Slice 033-05 - codex-scaffold-adapter

**Resolution trigger:** A real user asks to use jig from Codex, or a dogfood comparison shows Codex support is needed for an active project.

**Goal:** Add Codex scaffold-mode output using the host-adapter boundary
created in v1.

**DoR:**
- Slices 033-01 through 033-04 are DONE.
- The current Codex docs for `AGENTS.md`, skills, hooks, custom agents,
  and plugin structure have been re-verified.
- A user or dogfood project exists that will actually exercise the Codex
  scaffold output.

**Acceptance Criteria:**

1. **Codex scaffold target added.** The scaffolder can render Codex
   project-local files without also requiring Claude scaffold output.
2. **Codex skills materialized.** Jig skills render into Codex's
   project-scoped skill directory with helper paths rewritten to the
   Codex project/runtime location.
3. **Codex agents materialized.** `implementer`, `reviewer`, and
   `architect` render into Codex custom-agent files, with capability
   limitations documented where Codex cannot enforce the same isolation
   as Claude.
4. **Codex hooks registered.** The seven logical jig hooks are registered
   in Codex's hook configuration using the adapter's `warn` / `block`
   translation.
5. **Hook protocol fixtures pass.** Tests cover Codex hook input/output
   payloads for at least one warning hook and one blocking hook.
6. **Golden fixture tests pass.** A fake project scaffolded for Codex
   produces the expected generated tree and does not create Claude-only
   files unless explicitly requested.
7. **No Claude regression.** Existing Claude plugin and scaffold tests
   remain green.
