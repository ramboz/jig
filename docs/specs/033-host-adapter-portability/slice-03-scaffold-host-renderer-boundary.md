## Slice 033-03 - scaffold-host-renderer-boundary

**Goal:** Refactor scaffold-mode generation behind a host renderer while
preserving the current Claude scaffold output.

**DoR:**
- Slices 033-01 and 033-02 are DONE.
- Existing scaffold-mode tests are green before the refactor begins.

**Acceptance Criteria:**

1. **Host renderer abstraction exists.** `scaffold.py` or a companion
   module has an explicit representation for the logical adapter
   operations documented in slice 033-01.
2. **Claude renderer preserves output.** The default scaffold path still
   produces the Claude project tree expected today: `.claude/skills/`,
   `.claude/agents/`, `.claude/hooks/scripts/`, and
   `.claude/settings.json`, plus the primer files from slice 033-02.
3. **Plugin-only behavior preserved.** `--plugin-only` keeps its current
   meaning for Claude plugin mode and does not create host-scaffolded
   runtime machinery.
4. **Path rewriting is scoped to renderer.** Claude-specific rewrites
   such as `${CLAUDE_PLUGIN_ROOT}` to `${CLAUDE_PROJECT_DIR}/.claude/...`
   live in the Claude renderer, not scattered through shared scaffold
   logic.
5. **Golden fixture tests added.** At least one generated-tree fixture
   or equivalent exact-output assertion pins the Claude scaffold output
   after the refactor.
6. **No Codex files generated.** This slice creates the boundary only;
   it does not emit `.codex/`, `.agents/`, or `.codex-plugin/` files.
