## Slice 033-03 - scaffold-host-renderer-boundary

**Goal:** Refactor scaffold-mode generation behind a host renderer while
preserving the current Claude scaffold output.

**DoR:**
- Slices 033-01 and 033-02 are DONE.
- Existing scaffold-mode tests are green before the refactor begins.

**Acceptance Criteria:**

1. **Host renderer abstraction exists.** `scaffold.py` or a companion
   module has an explicit representation for the logical adapter
   operations documented in slice 033-01.
2. **Claude renderer preserves output.** The default scaffold path still
   produces the Claude project tree expected today: `.claude/skills/`,
   `.claude/agents/`, `.claude/hooks/scripts/`, and
   `.claude/settings.json`, plus the primer files from slice 033-02.
3. **Plugin-only behavior preserved.** `--plugin-only` keeps its current
   meaning for Claude plugin mode and does not create host-scaffolded
   runtime machinery.
4. **Path rewriting is scoped to renderer.** Claude-specific rewrites
   such as `${CLAUDE_PLUGIN_ROOT}` to `${CLAUDE_PROJECT_DIR}/.claude/...`
   live in the Claude renderer, not scattered through shared scaffold
   logic.
5. **Golden fixture tests added.** At least one generated-tree fixture
   or equivalent exact-output assertion pins the Claude scaffold output
   after the refactor.
6. **No Codex files generated.** This slice creates the boundary only;
   it does not emit `.codex/`, `.agents/`, or `.codex-plugin/` files.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Renderer boundary materialized as an explicit contract.**
   `skills/scaffold-init/scaffold.py` now defines `HostRenderer` as an
   abstract scaffold-runtime boundary with the logical operations from
   033-01: primer rendering, skill install, agent install, hook install,
   hook protocol translation, path binding, managed metadata, and
   verification fixtures. `ClaudeScaffoldRenderer` implements the contract
   without adding Codex output.
2. **Claude behavior stayed behind compatibility facades.** Existing
   underscored helper entrypoints and public `copy_machinery()` remain,
   but delegate to the Claude renderer. This keeps `migrate copy-machinery`
   and the existing scaffold tests on the same behavior while moving
   Claude-specific path rewrites and `.claude/settings.json` merging into
   one renderer-owned surface.
3. **Plugin-only behavior tightened during review.** Compliance review
   caught that an unconditional directory-prep step created an empty
   `.claude/hooks/` directory under `--plugin-only`. Runtime directory
   preparation now runs only inside the machinery path after the unmanaged
   hooks safety check passes, so plugin-only creates no host-scaffolded
   runtime machinery.
4. **Golden output is pinned by exact generated-tree assertions.**
   `HostRendererBoundaryTests` checks the default Claude scaffold tree
   across primers, skill directories, agent files, hook scripts, and hook
   event keys. It also pins that plugin-only emits no `.claude/skills`,
   `.claude/agents`, `.claude/hooks`, `.claude/settings.json`, `.codex/`,
   `.agents/`, or `.codex-plugin/` paths.
5. **Hook protocol translation is a boundary pin for future adapters.**
   The Claude renderer exposes `translate_hook_protocol()` so the host
   contract includes hook-result translation. Current Claude hook scripts
   still encode their stdout/stderr/exit behavior directly; wiring generated
   hook wrappers through that method belongs with the later non-Claude hook
   adapter work, not this boundary-only slice.
6. **Review and verification results.** Final compliance, craft, and arch
   review passes all returned `VERDICT: pass`. Validation passed with
   `python3 scripts/run_tests.py` (1391 tests OK, 3 skipped), focused
   scaffold/migrate tests (259 tests OK), spec lint for 033-03, and
   `git diff --check`. No new deferred decisions were added, so
   `docs/refinement-todo.md` did not need a content change.
