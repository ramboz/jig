## Slice 033-07 - codex-custom-agent-toml-adapter

**Goal:** Ship jig's canonical role prompts as supported Codex custom-agent
TOML files for scaffold users and as an explicit plugin install helper for
global Codex plugin users.

**DoR:**
- Slice 033-06 is DONE.
- Current Codex custom-agent docs have been re-checked: discoverable custom
  agents are TOML files under project-local or user-local `.codex/agents/`.
- The user approved the TOML adapter + explicit plugin install helper approach.

**Acceptance Criteria:**

1. **Codex scaffold emits discoverable agent TOML.** `--host codex` writes
   `.codex/agents/jig-*.toml` files that parse as TOML, preserve each
   canonical `agents/*.md` role prompt, and encode the intended sandbox
   posture for implementer/reviewer/architect roles.
2. **Codex plugin users get an explicit install helper.** A shipped helper can
   install the same generated TOML agents into a requested Codex agents
   directory, refuses to overwrite user-owned files by default, and documents
   the default global install target.
3. **Codex plugin package carries TOML agent templates.**
   `scripts/build_codex_plugin.py` materializes the generated TOML agent files
   into the plugin package without adding an unsupported `agents` field to
   `.codex-plugin/plugin.json`.
4. **Docs describe the honest support shape.** README, architecture docs, and
   the refinement TODO explain that plugin-level custom-agent discovery is not
   documented today, and that jig ships agents through project-local TOML or an
   explicit global-copy helper.
5. **Claude behavior is unchanged.** Claude scaffold and Claude plugin outputs
   continue to use the existing Markdown agent files and release manifest
   surface.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- Codex 0.133 was re-checked locally: custom agents are TOML role files
  under `.codex/agents/`, and no documented plugin manifest `agents` field is
  available. The implementation therefore keeps the plugin manifest honest and
  ships explicit TOML materialization instead.
- `--host codex` now renders `.codex/agents/jig-*.toml` from the canonical
  `agents/*.md` role prompts, stripping Claude frontmatter into TOML metadata
  while preserving the rewritten prompt body as `developer_instructions`.

  source and generated `agents/jig-*.toml` templates. The explicit helper
  `--install-codex-agents` installs those TOML files into a requested agents
  directory, defaults to `~/.codex/agents`, and preflights user-owned
  conflicts before writing anything.
- Review nits were resolved during implementation: unknown future Codex agent
  roles now fail closed unless they have an explicit sandbox mapping, global
  agent install conflicts are detected before mutation, and the generated
  plugin helper path has a smoke test.
