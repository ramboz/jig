## Slice 033-01 - support-matrix-and-adapter-contract

**Goal:** Establish the host-adapter architecture and support matrix in
the docs without changing runtime behavior.

**DoR:**
- Spec 033 overview accepted as the working framing.
- No implementation slices have started.

**Acceptance Criteria:**

1. **Product vision reframed.** `docs/product-vision.md` describes jig as
   an AI-native workflow scaffold with Claude as the v1 supported host,
   not only as a Claude Code plugin.
2. **Architecture boundary documented.** `docs/architecture.md` names a
   host-adapter boundary and describes the logical adapter contract:
   primer rendering, skill installation, agent installation, hook
   installation, hook protocol translation, path/environment binding,
   managed metadata, and verification fixtures.
3. **Support matrix explicit.** The docs state that v1 supports Claude
   plugin and Claude scaffold modes; Codex scaffold and Codex plugin are
   deferred v2 targets.
4. **Deferred Codex trigger preserved.** `docs/refinement-todo.md`
   either links to this spec or is updated to mark the old AGENTS.md
   portability decision as tracked here, without claiming Codex is
   implemented.
5. **No behavior changes.** No scaffold output, hook behavior, helper
   CLI, or plugin manifest changes land in this slice.
