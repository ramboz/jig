## Slice 033-04 - generated-file-metadata

**Goal:** Add compact managed-file metadata for scaffolded runtime files
so future update tooling can distinguish jig-managed output from
user-owned edits.

**DoR:**
- Slice 033-03 is DONE.
- The scaffold renderer boundary identifies every generated file family.

**Acceptance Criteria:**

1. **Managed file policy documented.** Architecture docs define which
   generated files get inline markers, which are tracked only in a
   manifest, and why.
2. **Compact metadata implemented.** Scaffolded managed files or
   `scaffold.json` record enough information to identify the source
   jig version, host renderer, source template/path, and content hash.
3. **Token budget respected.** Large prose files do not gain noisy
   banners when the same metadata can live in a manifest without
   reducing update safety.
4. **Existing Claude output remains readable.** The metadata does not
   make `CLAUDE.md`, `AGENTS.md`, skills, or agent prompts meaningfully
   harder for an LLM to use.
5. **Rerun behavior tested.** Re-running scaffold over untouched managed
   files is idempotent; re-running over user-edited managed files either
   preserves the edit or refuses with a clear message according to the
   documented policy.
6. **Future update path captured.** Any remaining work for `jig update`
   is parked in `docs/refinement-todo.md` with a resolution trigger.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- Metadata lives under root `scaffold.json.managed_files` with a
  manifest-only default. Each managed file entry records relative path,
  source template/path, `jig_version`, `host_renderer`, metadata location,
  and `sha256` content hash.
- Inline ownership markers remain limited to Claude hook entries in
  `.claude/settings.json`, where the native merge surface needs
  per-entry `metadata.managed_by_jig`. Large prose/prompt files keep their
  existing readable shape and do not gain metadata banners.
- Managed runtime metadata is derived from plugin source trees using the
  same inclusion rules as install/copy behavior, not by scanning arbitrary
  target directories. A regression keeps pre-existing user-owned
  `.claude/skills`, `.claude/agents`, and hook script files out of
  `managed_files`.
- `--force` re-runs check existing managed-file hashes before writing and
  refuse edited managed output with a clear error; missing managed files
  may regenerate. Legacy or malformed `scaffold.json` files without
  readable `managed_files` bypass this new check for compatibility.
- `scaffold.json` is intentionally not self-hashed because it is both the
  completion sentinel and the manifest root. The full `jig update`
  reconciliation workflow remains deferred in `docs/refinement-todo.md`
  with a resolution trigger.
