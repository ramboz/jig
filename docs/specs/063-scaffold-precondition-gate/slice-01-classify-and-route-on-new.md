## Slice 063-01 — classify-and-route-on-new

**Goal:** Replace `workflow.py new`'s weak, dead-end `docs/specs/`-presence
check with a three-way, `scaffold.json`-first scaffold-state
classification that **routes** an unscaffolded project to
`/jig:scaffold-init` (greenfield) or `/jig:migrate` (adoptable), while a
scaffolded project reserves exactly as it does today.

**DoR:**
- ✅ Open questions in `spec.md` resolved: bypass env var (yes/no + name),
  "scaffolded" = `scaffold.json` only, shared-helper home/signature.
- ✅ Existing `new` / `reserve_spec` test suite identified as the
  no-regression baseline.

**Acceptance Criteria:**

1. **Shared classifier exists and is `scaffold.json`-first.** A helper in
   `skills/_common/` exposes
   `classify_scaffold_state(project_dir) -> "scaffolded" | "adoptable" |
   "greenfield"`: returns `scaffolded` iff `scaffold.json` is present;
   else `adoptable` iff the shared ≥3-of-4-triggers predicate fires
   (spec/slice dir + decision/adr dir + workflow.md + architecture.md);
   else `greenfield`. The interrupted-scaffold case (jig CLAUDE.md
   watermark present, `scaffold.json` absent) classifies as `greenfield`.
2. **`greenfield` → route to scaffold-init.** `workflow.py new <slug>`
   in a directory with no `scaffold.json` and no spec-driven layout
   refuses with a non-zero exit and a message that (a) names the detected
   state, (b) gives the exact next command (`/jig:scaffold-init`), and
   (c) does **not** create `docs/specs/NNN-<slug>/` or any reservation
   commit.
3. **`adoptable` → route to migrate.** `workflow.py new <slug>` in a
   directory with no `scaffold.json` but a spec-driven layout (≥3
   triggers) refuses with a non-zero exit naming `/jig:migrate`, and
   creates no reservation.
4. **`scaffolded` proceeds unchanged.** In a `scaffold.json`-bearing
   project, `new` runs the existing reserve flow (number computation,
   stub write, commit, push/no-push routing) with identical observable
   output to today. The full pre-existing `new`/`reserve_spec` test set
   stays green.
5. **Shared trigger predicate, not a third copy.** The ≥3-of-4 trigger
   logic lives in exactly one place under `skills/_common/`; the
   classifier consumes it. No new inline reimplementation of trigger
   counting in `workflow.py`. (Retrofitting scaffold-init / migrate to
   the shared predicate is explicitly out of scope — see spec non-goals.)
6. **Bypass honored iff adopted.** If the resolved open question is
   "yes," `JIG_SCAFFOLD_PRECONDITION=0` (also `false`/`off`/`no`) skips
   the precondition and runs the legacy reserve flow; the bypass is a
   deliberateness signal, not human-only (ADR-0011). If "no," this AC is
   struck at reconciliation with the rationale logged.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Deliberate transient duplication of the trigger predicate (per spec
  non-goals, NOT a defect).** `skills/_common/scaffold_state.py`'s
  `looks_spec_driven()` re-implements the ≥3-of-4 trigger count (empty
  spec/slice dirs DO count). This duplicates scaffold-init's
  `_looks_already_spec_driven()` semantics. The spec's non-goals
  explicitly forbid retrofitting scaffold-init's `_looks_already_spec_driven`
  / `_is_jig_partial_state` or migrate's `compute_verdict` (they have
  deliberately different tuned semantics; rewriting them is a separate
  behavior-change risk). So the new `_common` predicate is the third
  trigger-counting copy by design — the rule-of-three EXTRACT for the two
  tuned call sites is a future, out-of-scope refactor. AC5's "exactly one
  place" is satisfied *within the new precondition code* (the classifier
  consumes the single `looks_spec_driven`); it does not claim repo-wide
  deduplication.
- **`_common` stays a leaf.** `scaffold_state.py` imports only stdlib +
  `GATE_DISABLE_VALUES` from `_common.review_evidence` (the shared bypass
  vocabulary, so the spec-precondition gate and the review-evidence gate
  can't drift on what "disabled" means). It does NOT import from
  `skills/scaffold-init/`. The jig CLAUDE.md watermark string
  (`"Generated by [jig]"`) is replicated as a module constant for the same
  leaf reason, mirroring scaffold-init's `_JIG_CLAUDE_MD_WATERMARK`.
- **Existing reserve fixtures gained a `scaffold.json` sentinel (AC4
  no-regression).** Four pre-existing test fixtures built `docs/specs/`
  without `scaffold.json` (`ReserveSpecTests`,
  `NewSpecScaffoldsFilePerSliceTests`, `ReserveSpecAgainstOriginTests`, and
  the real-git `ReserveSpecFromLinkedWorktreeE2E`). Under the new
  classification a bare `docs/specs/` (1 trigger) is `greenfield`, so each
  setUp now writes a `scaffold.json` so the project classifies as
  `scaffolded` and the legacy reserve flow runs exactly as before. No
  production-path change to those flows.
- **The old `test_new_refuses_when_specs_dir_absent` was repurposed.** It
  previously asserted the dead-end `"docs/specs"` message; it now asserts
  the new `greenfield` → `/jig:scaffold-init` routing (the bare-dir case is
  greenfield). The legacy weak refusal is still covered — under bypass — by
  `test_bypass_preserves_legacy_weak_refusal`.
- **Bypass preserves today's behavior exactly.** When
  `JIG_SCAFFOLD_PRECONDITION` is falsey (`0`/`false`/`off`/`no`),
  `reserve_spec` skips classification and runs the legacy path *including*
  its original weak `docs/specs/`-absent refusal — so a deliberate actor
  sees identical output to pre-063 jig.
- **Scope held to `new` / `reserve_spec`.** No other subcommand
  (`transition`, `status-board`, `session-plan`, `stale`, …) was touched.
  No `.claude/review-queue.json` (removed in spec 039) was created.
