## Slice 063-02 — skill-step0-precondition

**Goal:** Add a "Step 0: confirm the project is scaffolded" precondition
to the `spec-workflow` skill's creation flow so an auto-triggered run
verifies scaffold state — and routes to `/jig:scaffold-init` or
`/jig:migrate` — **before** improvising any structure, closing the
no-helper path that produced the reported loose `slices/` folder.

**DoR:**
- ✅ 063-01 DONE: `workflow.py new` already classifies and routes, so the
  prose points at that behavior instead of duplicating logic in prose.

**Acceptance Criteria:**

1. **Step 0 precondition documented in SKILL.md.** The
   `spec-workflow` SKILL.md "Creating a new spec" section gains an
   explicit first step: before reserving a number or drafting any
   `docs/specs/` / slice structure, confirm scaffold state. If not
   scaffolded, route to `/jig:scaffold-init` (greenfield) or
   `/jig:migrate` (existing spec/`slices/` layout) and **do not
   hand-roll directories**.
2. **Points at the helper, no duplicated logic.** The prose tells the
   orchestrator that `workflow.py new` will itself classify-and-route
   (063-01), so the human-readable instruction and the deterministic
   gate agree; the SKILL.md does not restate the trigger heuristic.
3. **Names the loose-`slices/` failure explicitly.** The guidance calls
   out the observed anti-pattern (improvising a `slices/` folder when
   scaffold was skipped) so the model recognizes and avoids it.
4. **Guard test pins the precondition.** A doc/guard test asserts the
   SKILL.md "Creating a new spec" flow contains the Step 0 precondition
   and the two routing targets (`scaffold-init` / `migrate`), so the
   guidance can't silently regress.
5. **Template/scaffold parity preserved.** If the SKILL.md is one copied
   into scaffolded targets, the scaffold-mode copy carries the same Step
   0 text (no drift between plugin and scaffolded prose).
