## Slice 093-01 — discover installed providers and explain absence

**Goal:** Select an installed supported provider for unconfigured projects and
give a bounded, actionable recommendation when none is available.

**DoR:**
- ✅ Spec 080 is DONE and its provider/overlay boundaries are covered by tests.
- ✅ Mystique's `provider_missing` telemetry and local Scout installation were
  reproduced on 2026-07-15.

**Acceptance Criteria:**

1. **Implicit public-provider discovery.** With no state file/provider field,
   jig selects the first detected public candidate in stable registry order;
   it does not stop at an absent `tokensave`.
2. **Explicit choice is authoritative.** A configured provider never silently
   falls through; its missing/failure outcome names that provider.
3. **Scout remains gated.** Scout is considered only when the internal overlay
   is explicitly allowed; an installed but disallowed Scout is neither selected
   nor recommended by public output.
4. **No-provider guidance is actionable and rate-limited.** When no eligible
   provider exists, host adapters emit at most one compact recommendation that
   names the state file and supported public candidates; no install/download is
   executed.
5. **Telemetry distinguishes selection.** Events record whether the provider
   was explicit, auto-discovered, or absent without repository content.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Lifecycle provenance (honest note).** Shipped as a single commit on
   `codex/jig-workflow-closure` (PR #104), not through jig's step-by-step gated
   transitions. These records were reconstructed during a post-implementation
   docs-alignment pass; `test_semantic_index.py` and the `jig-semantic-index`
   hook test were re-verified green on 2026-07-15 before marking DONE.

2. **Explicit-choice provenance is runtime-only.** Added
   `ActivationState.provider_explicit` (`compare=False`, `repr=False`, not
   serialized). `load_state` sets it from the presence of a truthy `provider`
   key so an explicit choice is distinguished from the legacy `tokensave`
   default; `write_state` drops the `provider` key when it equals the
   unconfigured default, keeping the public state schema unchanged (AC #2, #5).

3. **Implicit selection is capability-based.** `_select_provider` now returns a
   3-tuple that adds a `provider_selection` tag (`explicit` /
   `auto_discovered` / `absent`). Unconfigured projects probe
   `PUBLIC_PROVIDER_CANDIDATES` in stable order via `detect()`, then any
   injected public provider, then an allowed overlay — never stopping at an
   absent `tokensave` (AC #1).

4. **Scout stays gated.** Overlay-requiring providers are considered only when
   `_overlay_allowed`; an installed-but-disallowed Scout is neither selected nor
   named in public output (AC #3).

5. **Missing-provider outcome is actionable.** `action` switches from `detect`
   to `recommend` and a bounded `_missing_provider_recommendation()` names the
   state file + public candidates (naming the configured provider on an
   explicit miss). Rate-limiting stays the adapters' one-suggestion behavior
   (AC #4).

6. **Telemetry records `provider_selection`** without repository content (AC #5).

7. **Serialization blocker (reviewer finding, folded back).** An initial cut
   serialized `provider_explicit` into state; review flagged the schema drift.
   Fixed by excluding it from `asdict()`/equality and reconstructing it from key
   presence on load — the fix was re-reviewed clean (per PR).

8. **Docs updated.** `templates/docs/workflow.md.template` (discovery prose +
   provider-optional JSON example) and spec 080's `## Amendments`.
