## Slice 093-01 — discover installed providers and explain absence

**Goal:** Select an installed supported provider for unconfigured projects and
give a bounded, actionable recommendation when none is available.

**DoR:**
- ✅ Spec 080 is DONE and its provider/overlay boundaries are covered by tests.
- ✅ Mystique's `provider_missing` telemetry and local Scout installation were
  reproduced on 2026-07-15.

**Acceptance Criteria:**

1. **Implicit public-provider discovery.** With no state file/provider field,
   jig selects the first detected public candidate in stable registry order;
   it does not stop at an absent `tokensave`.
2. **Explicit choice is authoritative.** A configured provider never silently
   falls through; its missing/failure outcome names that provider.
3. **Scout remains gated.** Scout is considered only when the internal overlay
   is explicitly allowed; an installed but disallowed Scout is neither selected
   nor recommended by public output.
4. **No-provider guidance is actionable and rate-limited.** When no eligible
   provider exists, host adapters emit at most one compact recommendation that
   names the state file and supported public candidates; no install/download is
   executed.
5. **Telemetry distinguishes selection.** Events record whether the provider
   was explicit, auto-discovered, or absent without repository content.

### For `kind: spike` slices

When the slice's frontmatter has `kind: spike`, the body carries four
extra labelled blocks alongside the standard Goal / DoR / AC / DoD
scaffolding. Spike slices are timeboxed investigation, not feature
work — they reduce an unknown before committing to a design.

```markdown
**Question:** _One sentence stating the open question. Set at DRAFT._

**Time-box:** _Explicit budget — e.g., "1 day", "4 hours". Set at DRAFT._

**Findings:** _Bullet evidence collected during the spike. Filled
during IN_PROGRESS._

**Outcome:** _One of: `ADR-NNNN created` / `spec NNN-NN unblocked` /
`abandoned (reason)`. Multiple outcomes separated by `;`
(e.g., `ADR-0007 created; spec 030-02 unblocked`). Set at DONE._
```

`spec_lint.py` validates the `kind:` enum (allowed values: `spike`,
`feature`) and soft-warns when a `kind: spike` slice is missing any of
the four labels. Mid-flight spikes legitimately have empty Findings /
Outcome, so this is a warning, not a hard error.

See `skills/spec-workflow/SKILL.md` (Spike slices subsection) and
`docs/spec-workflow/spidr-primer.md` for the always-nested rule (spike
slices live inside a real spec, never as standalone `docs/spikes/`
artifacts) and the abandoned-outcome manual-reshape failure mode.
