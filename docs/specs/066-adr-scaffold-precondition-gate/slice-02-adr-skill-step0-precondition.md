## Slice 066-02 — adr-skill-step0-precondition

**Goal:** Add a "Step 0: confirm the project is scaffolded" precondition to
the `adr-workflow` skill's "Author a new ADR" flow so an auto-triggered run
verifies scaffold state — and routes to `/jig:scaffold-init` or
`/jig:migrate` — **before** improvising any `docs/decisions/` structure.
The ADR-side mirror of 063-02.

**DoR:**
- ✅ 066-01 DONE: `adr.py new` already classifies and routes, so the prose
  points at that behavior instead of duplicating logic.

**Acceptance Criteria:**

1. **Step 0 precondition documented in SKILL.md.** The `adr-workflow`
   SKILL.md "Author a new ADR" section gains an explicit first step: before
   reserving an ADR number or drafting any `docs/decisions/` structure,
   confirm scaffold state. If not scaffolded, route to `/jig:scaffold-init`
   (greenfield) or `/jig:migrate` (existing layout) and **do not hand-roll
   directories**.
2. **Points at the helper, no duplicated logic.** The prose tells the
   orchestrator that `adr.py new` will itself classify-and-route (066-01),
   so the human-readable instruction and the deterministic gate agree; the
   SKILL.md does not restate the trigger heuristic.
3. **Names the anti-pattern explicitly.** The guidance calls out the
   observed failure (improvising a `docs/decisions/` skeleton when scaffold
   was skipped) so the model recognizes and avoids it.
4. **Guard test pins the precondition.** A doc/guard test asserts the
   `adr-workflow` SKILL.md "Author a new ADR" flow contains the Step 0
   precondition and the two routing targets (`scaffold-init` / `migrate`),
   so the guidance can't silently regress.
5. **Template/scaffold parity preserved.** The scaffold-mode copy of
   `adr-workflow` SKILL.md carries the same Step 0 text (no drift between
   plugin and scaffolded prose); pinned by a parity test.
