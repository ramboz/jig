## Slice 087-01 — investigation guidance in code-review prompts + reviewer agent

**Goal:** The code-reviewing reviewer prompts and the standing reviewer agent
definition carry diff/deliverable-anchored, narrow-first investigation guidance,
so the read-only reviewer investigates like a reviewer (locate → read focused
ranges) instead of a repo explorer — and the prose/framing passes deliberately
do not.

**DoR:**
- ✅ Prompt builders identified: `build_implementation_prompt`,
  `build_pr_review_prompt`, `build_bug_review_prompt`,
  `build_arch_review_prompt`, `build_code_health_review_prompt` (code passes);
  `build_reconciliation_prompt`, `build_frame_critique_prompt`,
  `build_design_review_prompt` (prose/framing passes — excluded).
- ✅ Test harness exists (`skills/independent-review/test_review.py`,
  subprocess-invokes `review.py <mode>` and asserts on stdout).
- ✅ Host-package mirroring understood (`scripts/build_host_packages.py` syncs
  `agents/` + `skills/` into `hosts/`; drift test enforces it).

**Acceptance Criteria:**

1. **Guidance present in the compliance prompt.** `review.py implementation …`
   output contains a distinct investigation-discipline block instructing the
   reviewer to anchor to the deliverable, locate with Grep/Glob before reading,
   batch discovery before reads, read focused ranges rather than whole files,
   and retry a failed search with a simpler query before guessing paths.
2. **Guidance present in every other code-review prompt.** The same block
   appears in `review.py pr-review …`, `review.py arch-review …`,
   `review.py code-health …`, and `review.py bug-review …` output.
3. **Guidance absent from the prose/framing prompts.** The block does NOT
   appear in `review.py reconciliation …`, `review.py frame-critique …`, or
   `review.py design-review …` output — locking the task-shaped scoping
   decision (blanket application would be the article's mistake in reverse).
4. **Guidance present in the reviewer agent definition.** `agents/reviewer.md`
   carries an equivalent "how to investigate efficiently" section.
5. **Host packages consistent.** The `hosts/claude/` and
   `hosts/codex/plugins/jig/` copies of the edited files match source (the
   host-package drift test passes).

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Delivered as specified.** A shared `_INVESTIGATION` constant in
   `review.py` (defined once, ADR-0002 no-copy-paste) interpolated into the five
   code-review builders (`build_implementation_prompt`, `build_pr_review_prompt`,
   `build_bug_review_prompt`, `build_arch_review_prompt`,
   `build_code_health_review_prompt`) between each "What to read" block and
   `_PROHIBITIONS`; an equivalent section in `agents/reviewer.md`; tests in
   `test_review.py` asserting presence in all 5 code passes, absence in all 3
   prose passes (`reconciliation` / `frame-critique` / `design-review`), the five
   narrow-first moves, and the agent section.
2. **Load-bearing scoping is guarded in-code.** The code-vs-prose split is
   documented both in the spec Overview and in a block comment above
   `_INVESTIGATION`, so a future agent doesn't "helpfully" add the block to the
   prose passes (which would be the article's mistake in reverse). Considered a
   standalone jig ADR for this choice; decided the spec record + guarding comment
   are sufficient durable capture — the choice is narrow (prompt authoring),
   cheaply reversible, and touches no module boundary or public contract.
3. **`agents/reviewer.md` carries 3 of 5 moves — deliberate (craft nit #2, not
   folded).** The standing agent prompt governs *every* pass including the prose
   ones, so it holds only the generally-correct moves (anchor / locate-before-read
   / focused ranges); the code-navigation specifics (batch discovery,
   retry-with-simpler-query) live in the per-pass `review.py` block, scoped to the
   code passes. Both reviewers confirmed this satisfies AC4's "equivalent".
4. **Craft nit #1 folded in.** The shared block's first bullet said "Start from
   the listed files and the acceptance criteria"; since bug-review has no ACs and
   pr/arch/code-health are told not to re-evaluate ACs, it was reworded to "the
   change under review" so it reads correctly across all five code passes.
   Re-tested + host packages rebuilt after the fold-in (all green).
5. **Process — implemented in the orchestrator, not via an implementer subagent.**
   The change was small and the relevant code was already loaded; a fresh
   implementer subagent would have re-read it (specs 055/057 context-cost). The
   independent-reviewer gate (compliance + craft subagents, no implementation
   context) was preserved — that is the part that needs isolation.
6. **Process — stale worktree baseline required a rebase onto `origin/main`.**
   The worktree forked from a local `main` predating two landed commits: the
   `jig.png → jig.jpg` logo swap in host packages and spec 051-04. Building host
   packages on the stale baseline dropped the committed logo and churned READMEs.
   Rebased the branch onto `origin/main` (clean, no conflicts) before rebuilding
   `hosts/`, which then reflected only the review.py/reviewer.md/jig-reviewer.toml
   changes. The logo asset itself was left untouched (out of scope).
7. **Process — `## Assumptions` sentinel.** `workflow.py frame-review-needed`
   derives `true` from any real-prose line in `## Assumptions`. An initial
   attempt listed *verified* premises there (which read as real assumptions),
   flipping `frame_review` on. Those probe-verified facts were moved to a
   `## Current state (verified)` section and `## Assumptions` reduced to a bare
   `None.`, correctly keeping the adversarial frame-critique pass off for a
   low-risk prompt-text change.
