## Slice 045-01 - review-evidence-adr

**Goal:** Accept an ADR that defines the durable evidence model for
jig's review and reconciliation lifecycle gates.

**DoR:**
- The current lifecycle gap has been verified against `review.py`,
  `workflow.py transition`, the Stop-hook documentation, and
  `agents/implementer.md`.
- Spec 031's three-pass review flow is treated as current policy.

**Acceptance Criteria:**

1. **ADR compares at least three evidence models.** Options include a
   per-slice `reviews/` directory, a single slice-local review ledger,
   and a repo-level `.jig/reviews/` ledger. The ADR states tradeoffs for
   reviewability, merge conflict risk, scaffold-mode portability, and
   future CI use.
2. **ADR defines required passes by transition.** The decision states
   which artifacts are required before `REVIEWED`, `RECONCILED`, and
   `DONE`, including the optional arch-review branch.
3. **ADR defines verdict semantics.** The decision states allowed
   verdict values, whether failed verdicts block transition, how
   superseded review artifacts are represented, and what timestamp or
   command provenance is required.
4. **ADR defines the docs and hook stance.** The decision explicitly
   chooses whether hooks block, warn, or stay out of reconciliation
   enforcement, and names every doc/agent file that must be aligned in
   later slices.

   `adr.py accept` + `adr.py index` ran normally (those subcommands carry

   (#26, commit `84bee7b`) landed `adr-0013-security-floor-policy.md` on

   021→022 renumber in `docs/refinement-todo.md`), this ADR renumbered to
