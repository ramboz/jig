## Slice 028-01 — adr-numbering-on-main

**Goal:** Extend `adr.py new <slug>` to reserve the next free ADR
number on `origin/main` (with PR fallback when direct push is
refused), the same way `workflow.py new <slug>` reserves spec numbers.
Two parallel worktrees calling `adr.py new` simultaneously never get
the same number.

**DoR:**
- ✅ `workflow.py new` (spec 003-03) is in production and the
  reserve-on-main + PR-fallback + race-on-push pattern is validated.
- ✅ `adr.py new` exists and writes `docs/decisions/adr-NNNN-<slug>.md`
  per ADR-0004.

**Acceptance Criteria:**

1. **`adr.py new <slug>` reserves on `origin/main`.** Allocates the
   next free `NNNN` by committing a stub `docs/decisions/adr-NNNN-
   <slug>.md` directly to origin/main, same shape as `workflow.py
   new`.
2. **PR fallback on protection / permission refusal.** Mirrors spec
   003-03's logic: distinguishes push-refused-by-policy (→ PR
   fallback) from push-refused-by-race (→ instruct re-run).
3. **`--no-push` flag** to allow local-only allocation when desired
   (parity with `workflow.py new`).
4. **Race-on-push detection.** Non-fast-forward push instructs the
   user to re-run; race-recovery does NOT auto-fall-back to a
   different number (same precedent as spec 003-03's race-on-push
   handling).
5. **Subprocess mocking pattern reused.** Use the `_SubprocessRecorder`
   pattern from spec 003-03 (via importlib loading) for tests. Don't
   exercise real `git push` in the test suite.
6. **One live-remote dogfood** documented in the deviation log:
   reserve an ADR number from this slice itself, verify it lands on
   `origin/main` and the worktree picks it up. (Same close-out
   shape as spec 003-03's "live-remote dogfood pending" item, but
   exercised in this slice's own reconciliation.)

### Deviation log (after reconciliation)

**Behavior change (documented, not a deviation from spec).** The default
behavior of `adr.py new <slug>` changed from local-only allocation to
reserve-on-origin/main with PR-fallback. `--no-push` preserves the
prior local-only path for users who want it explicitly (per AC #3,
parity with `workflow.py new`).

**Inline-mirror, not extraction.** Per ADR-0002's "three-callers
triggers extraction" rule (which ADR-0003 first applied to
`find_slice_section`), the helpers were inline-mirrored from
`workflow.py` 003-03 rather than extracted to `skills/_common/`.
`workflow.py` is caller 1, `adr.py` becomes caller 2 — extraction
defers until a third caller emerges (likely slice 028-02 or 028-03).
The slice-028-01 block in `adr.py` is bracketed by
`# ---------- Slice 028-01: reserve-adr-on-main ----------` /
`# ---------- end slice 028-01 ----------` markers naming exactly
which helpers are mirrored. When extraction fires, this block is the
candidate.

**Slug-regex divergence is intentional.** adr.py keeps its existing
`^[a-z0-9][a-z0-9-]*$` (allows a leading digit; matches the regex
`cmd_new` already enforced). `workflow.py` uses `^[a-z][a-z0-9-]*$`
(no leading digit). Tightening adr.py would silently reject existing
digit-prefixed slugs — a behavior break with no upside. Documented
in the `_validate_slug` docstring and pinned by
`test_new_allows_slug_starting_with_digit`.

**`_validate_slug` is shared with `cmd_new`.** The initial implementer
draft introduced `_validate_slug_reserve` as a parallel helper, but
craft review noted the asymmetric naming (other mirrored helpers
share names with `workflow.py` verbatim). Renamed to `_validate_slug`
and folded `cmd_new`'s inline regex check onto it — single source of
truth for adr.py's slug rules.

**Template render + slug-collision check de-duplicated across
`cmd_new` and `reserve_adr`.** Both code paths now go through
`_render_adr_content` and `_check_slug_collision`. Prevents drift if
the ADR filename convention or template placeholders change.

**Test-fixture adaptation.** `NewTests` (the legacy `cmd_new` suite)
had to grow a `_git_init_on_main` helper + per-test `_seed()` because
the new reserve-on-main preflight (must be on `main`, clean tree)
applies even under `--no-push`. The cost is ~10ms of `git init` +
`git commit` per legacy test — acceptable, and pins the new contract
that `cmd_new` callers must also be on a clean main.

**Test ergonomics: importlib loader consolidated.** The first draft
defined two separate importlib helpers (`_import_adr_module` for
legacy tests, `_load_adr_module` for the reserve tests). The two were
functionally identical; craft review surfaced the duplication.
`ReserveAdrTests` now uses the same `_import_adr_module` shim as the
rest of the suite.

**Exit-code parity.** The mutual-exclusion test now pins to
argparse's `exit 2` rather than the looser `assertNotEqual(..., 0)`.
A future regression that flipped the exit code to 1 would now fail
loudly.

**Fetch-vs-working-tree semantics (clarification, not a code change).**
`git fetch origin main` updates the `refs/remotes/origin/main` ref but
does NOT touch the working tree. The next-number scan +
slug-collision check therefore operate on the LOCAL view of
`docs/decisions/`. If `origin/main` has an ADR that local main
doesn't yet have, the local view misses it; the `git push origin
main` step catches the divergence as `non-fast-forward` and triggers
race recovery. Same shape as `workflow.py` 003-03; behavior is
correct, just not obvious from reading the code.

**Live-remote dogfood (AC #6) — exercised, scoped deviation noted.**
AC #6 reads "verify it lands on `origin/main` and the worktree picks
it up." The dogfood was satisfied against a real `file://` bare-repo
remote rather than the project's actual GitHub `origin/main`. This is
a deliberate, code-path-faithful simulation: the full `git fetch
origin main` + `git push origin main` codepath is exercised against a
genuine git remote (just one that lives in `mktemp`, not on GitHub),
and the helper's classifier sees the same real-git stderr signals
(`non-fast-forward`, `[rejected]`, `fetch first`) that a GitHub-
backed push would emit. The choice to defer touching the real
GitHub `origin/main` until the spec actually lands (rather than
landing a junk dogfood-NNNN slot on trunk pre-merge) follows the
same "live-remote dogfood pending" shape as spec 003-03's close-out.
The two demonstrations:

- **Single reservation, clean path.** `adr.py new
  dogfood-parallel-locks` against a fresh bare remote: helper printed
  `reserved adr-0001-dogfood-parallel-locks` and
  `reserved adr-0001-dogfood-parallel-locks on origin/main`; the bare
  remote's `main` ref advanced to a commit titled
  `docs(decisions): reserve adr-0001-dogfood-parallel-locks`; the new
  file landed at `docs/decisions/adr-0001-dogfood-parallel-locks.md`.

- **Race recovery, two clones.** wt1 reserved
  `adr-0001-shared-trunk-lock-policy` and pushed cleanly; wt2 (with
  its `fetch` step monkey-patched to no-op so the local view stayed
  stale) computed the same `NNNN=0001`, committed locally, then
  tried to push. The classifier matched `non-fast-forward` /
  `[rejected]` / `fetch first` and emitted the race message
  (`race detected: origin/main advanced during reservation. Re-run
  ...`). Recovery dropped the stranded local commit AND removed the
  stranded ADR file from wt2's working tree (verified: `ls
  docs/decisions/` shows only `README.md` post-recovery; `git log
  --oneline main` shows only the seed commit). The bare remote shows
  only wt1's reservation. AdrError raised with `race-on-push: ...`.
