# Spec 028: parallel-session locks for shared mutable artifacts

## Overview

Spec 003-03 (`workflow.py new`) closed the parallel-worktree numbering
collision class by reserving the next free spec number on `origin/main`
with PR fallback. That validated a real failure mode (the 014/015 →
016/017 renumber, the parallel 021 collision) and demonstrated the
right *shape* of the fix: claim the resource on a shared coordination
surface before writing locally.

The same failure mode exists for **other shared mutable artifacts**
that multiple worktrees write concurrently:

- **`docs/inbox.md`** — every reconciliation may append; concurrent
  writes from two worktrees overwrite each other on git merge (or
  silently lose one).
- **`docs/refinement-todo.md`** — same shape as inbox.
- **`docs/specs/README.md`** (status board) — regenerated by
  `workflow.py status-board`; concurrent regens from two worktrees
  produce conflicting line orderings even when the underlying spec
  frontmatter is consistent.
- **ADR numbering** — `adr.py new` allocates the next `NNNN` from
  the local `docs/decisions/` directory. Two worktrees can each
  allocate ADR-0007 simultaneously and not discover the collision
  until merge.
- **`CLAUDE.md`** hot-cache writes (post spec 025) — same shape.

Today the mitigation is "merge conflicts catch it." That works for
text appends but silently picks one of two regenerated status boards,
and ADR-number collisions surface as a `git merge` conflict on the
filename, not as a refusal to allocate.

This spec extends the spec 003-03 reserve-on-main pattern to these
five artifacts: each gets an explicit collision-detection mechanism
appropriate to its write shape (append vs regenerate vs allocate-and-
write).

## Why now

- **Pattern is validated.** Spec 003-03 shipped the reservation logic
  and the rollback-on-race semantics. The cost of extending it to
  another artifact is *small* relative to inventing it from scratch.
- **The user runs many parallel worktrees.** Observable from `git
  worktree list` — 30+ active branches at the time of this spec
  draft. Collision risk is empirically present, not theoretical.
- **Spec 025 introduces another write surface.** CLAUDE.md hygiene
  (spec 025) reframes the close-out rule to *compress* CLAUDE.md.
  Compression writes that race two worktrees are exactly the failure
  this spec prevents.

## Goals

1. **Lock pattern for appends.** `inbox.md` + `refinement-todo.md`:
   appends serialize via a file lock OR a reserve-on-main shim,
   whichever turns out cheaper. Concurrent appends from two worktrees
   never lose content.
2. **Refusal on stale regen.** Status-board regeneration refuses to
   overwrite if the on-disk status board doesn't match the
   pre-regen baseline (e.g., another worktree just regen'd). Surface
   a re-run instruction.
3. **ADR numbering reserved on main.** `adr.py new <slug>` allocates
   on `origin/main` the same way `workflow.py new` reserves spec
   numbers — including PR-fallback when direct push is refused.
4. **CLAUDE.md hot-cache writes serialized.** Either via the same
   file-lock pattern as appends, or via an explicit "post-25 CLAUDE.md
   writes go through `workflow.py status-board`" convention. Pick
   one in the slice.
5. **Race-on-push detection.** Same shape as spec 003-03's
   non-fast-forward handling: distinguish "I lost the race" (re-run)
   from "I don't have permission" (PR-fallback). Don't conflate.
6. **Dogfood.** At least one of the five artifacts is dogfooded by
   running two parallel worktrees against it during slice
   implementation. Don't ship the spec without proving the lock
   holds under contention.

## Non-goals

- **No new spec for each artifact.** All five artifacts get extension
  in one spec — same shape as the SPIDR Rules axis (spec 003-03 is
  the pattern; this spec is the rules-extension).
- **No new helper skill.** Locks live inside the helpers that already
  write each artifact (`workflow.py status-board`, `adr.py new`,
  whatever writes inbox / refinement-todo).
- **No protection for unilateral text edits via the Edit tool.**
  Direct `Edit` calls on inbox / refinement-todo / CLAUDE.md from a
  human or agent are out of scope — they merge-conflict naturally.
  This spec protects helper-driven writes.
- **No protection for `docs/memory/*` files.** Memory layer writes
  are rare and structured (`memory-sync`); no observed collision
  risk yet.
- **No cross-repo locks.** Each project has its own lock state. Out
  of scope.

## Open questions

- **File-lock vs reserve-on-main per artifact.** File-lock (e.g.,
  `fcntl.flock` on a sentinel file) is local-only — won't help across
  worktrees that share the same filesystem but write different
  branches. Reserve-on-main is the safer pattern but pays a network
  round-trip per write. Decide per artifact in implementation. Lean:
  reserve-on-main for ADR numbering (already the spec 003-03 pattern);
  file-lock for inbox/refinement-todo appends (low rate, local-only
  is fine when the worktrees share a filesystem).
- **Status-board regen race detection.** Two options: (a) checksum
  the pre-regen file and refuse if it changed mid-regen, (b)
  reserve on main before regen. (a) is cheaper and catches the
  observed failure mode (concurrent regens producing different
  orderings). Lean (a); revisit if (a) is insufficient.
- **CLAUDE.md write surface.** Today, CLAUDE.md is hand-edited.
  Spec 025 reframes close-out to compression but doesn't introduce
  a helper. If spec 025-02 (the deferred `workflow.py audit-claude-md`
  helper) ever ships, that's the natural lock point. Until then,
  CLAUDE.md hot-cache writes remain human-driven and out of this
  spec's scope.
