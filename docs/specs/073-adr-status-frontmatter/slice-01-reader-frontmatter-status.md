## Slice 073-01 — reader honors frontmatter status

**Goal:** Make `_lookup_adr_accepted` (the `adr-NNNN` dependency reader in
`workflow.py`) read the ADR's frontmatter `status:` first and fall back to the
prose `## Status` scan for legacy ADRs — and in **both** paths treat
`Superseded` as *not* accepted — so a dependency on a superseded ADR is
correctly refused.

**DoR:**
- ✅ [ADR-0026](../../decisions/adr-0026-adr-status-frontmatter.md) Accepted —
  defines the frontmatter-first + `Superseded ≠ Accepted` rulings.
- ✅ `_common.parsing.parse_frontmatter` available (already used across
  helpers) for reading the ADR frontmatter.

**Acceptance Criteria:**

1. **Frontmatter `status: Accepted` → satisfied.** When the ADR's frontmatter
   carries `status: Accepted`, `_lookup_adr_accepted` returns satisfied
   without consulting prose. (Fixture: ADR with `status: Accepted` in
   frontmatter.)
2. **Frontmatter `status: Superseded` or `Proposed` → not satisfied**, with a
   human-readable reason naming the state — and, for `Superseded`, the
   superseder pulled from the prose `Superseded by` line when present.
   (Fixtures: frontmatter `status: Superseded`; `status: Proposed`.)
3. **No frontmatter `status:` → prose fallback.** When the frontmatter has no
   `status:` field (every legacy ADR), the reader falls back to the existing
   prose `## Status` scan — unchanged for a plain Accepted ADR.
4. **Prose fallback recognizes `Superseded`.** In the prose-fallback path, an
   ADR whose `## Status` section contains a `Superseded by` line returns not
   satisfied (reason names the superseder) even though an `Accepted (date)`
   line is also present. **This fixes the existing bug** for the prose-only
   corpus (e.g. `adr-0002`, `adr-0008`). (Fixture: prose-only ADR with both
   `Accepted (date)` and `Superseded by …`.)
5. **Diagnostic parity.** The not-satisfied reasons stay human-readable and
   name the ADR file, consistent with today's `_validate_dependencies` output.

   `status:` case-sensitively against `Accepted` / `Superseded` / `Proposed`.
3. **Reviewer findings (compliance + craft both PASS; two non-blocking nits
   deferred):**
   - *Empty-`status:` guard asymmetry* (both passes, Low/cosmetic): the
     frontmatter branch keys on `"status" in fields`, whereas the sibling
     `_lookup_slice_status` also checks truthiness (`and fields["status"]`). A
     bare empty `status:` would emit `"<name> is  (not Accepted)"` instead of
     falling back to prose. **Unreachable** — 073-02's writer always stamps a
     value and legacy ADRs lack the key entirely. Deferred as cosmetic; the
     optional one-line guard alignment can ride along with **073-02** (which
     owns the writer side).
   - *Bracketed-only superseder detection* (craft, nit/defer): the prose-branch
     `Superseded by` detection keys off the bracketed `[ADR-NNNN]` link form —
     exactly what `adr.py supersede` writes. A hand-edited, *unbracketed*
     `Superseded by ADR-NNNN` line in a legacy prose-only ADR would fall
     through to the `^Accepted` check → satisfied. Out of scope (hand-edited
     prose diverging from the writer); accepted as-is for the canonical corpus.
4. **Docs.** No architecture or convention changes — ADR-0026 already records
   the decision; this slice implements its read side. No
   `docs/refinement-todo.md` entry needed (no new deferred decision; the two
   nits are scoped above).
5. **Tests / CI.** `workflow.py` test classes green (17/17: 11 new + 6 existing
   dependency-gate); ruff clean on changed files. The full *local* suite shows
