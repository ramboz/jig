## Slice 082-01 — manifest shape and transition gate

**Goal:** Define the reconciliation sweep manifest body shape and make
`workflow.py transition … RECONCILED` require its presence alongside the
deviation log.

**DoR:**
- ✅ [ADR-0029](../../decisions/adr-0029-reconciliation-sweep-manifest.md)
  is accepted or explicitly approved for implementation.
- ✅ Current reconciliation gate behavior is verified against
  `skills/spec-workflow/workflow.py`.
- ✅ The slice template and existing deviation-log detection helpers are
  identified before implementation starts.

**Acceptance Criteria:**

1. **Manifest section is canonical.** The slice template documents a
   `### Reconciliation sweep` subsection adjacent to the deviation log. The
   template names the core surfaces from ADR-0029 and shows the three
   dispositions: `updated`, `no-op`, and `deferred`.
2. **Transition gate checks presence.** `workflow.py transition` refuses
   `RECONCILED` and `DONE` when review evidence is otherwise present but the
   slice lacks a `### Reconciliation sweep` subsection. The diagnostic names
   the missing subsection and says the reviewer judges content quality.
3. **Gate remains shape-only.** The helper does not require every core
   artifact to be touched, and it does not try to semantically prove doc
   freshness. A sweep section with `no-op` and `deferred` rows can pass the
   deterministic gate.
4. **Legacy / bypass behavior is explicit.** The existing
   `JIG_REVIEW_EVIDENCE_GATE=0` bypass disables the new shape check exactly
   like it disables the deviation-log/review-evidence gate, and tests cover
   that behavior.
5. **Regression coverage exercises the new gate.** Tests cover: missing sweep
   blocks `RECONCILED`; missing sweep blocks `DONE`; present sweep passes;
   bypass disables the check; and legacy deviation-log behavior still works.
