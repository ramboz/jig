## Slice 082-02 — reconciliation reviewer omission check

**Goal:** Teach the reconciliation-review prompt to judge the sweep manifest,
including missing artifacts and weak `no-op` / `deferred` rationales.

**DoR:**
- ✅ Slice 082-01 has landed the manifest subsection and transition shape gate.
- ✅ `review.py build_reconciliation_prompt` is the prompt builder used for
  reconciliation reviews.

**Acceptance Criteria:**

1. **Reviewer reads the sweep.** The reconciliation prompt tells the reviewer
   to read both `### Deviation log` and `### Reconciliation sweep` for the
   target slice.
2. **Omissions are in scope.** The Evaluate block asks whether any obvious
   drift-prone artifact is missing from the sweep, especially front-door docs,
   primers/templates, inbox, refinement todo, memory, ADR index, and generated
   status board.
3. **Disposition quality is judged.** The prompt asks whether each `updated`,
   `no-op`, or `deferred` rationale is credible, whether `deferred` entries
   name an owner or trigger, and whether `no-op` claims conflict with touched
   files or landed behavior.
4. **Scope creep remains guarded.** The existing warning against unrelated doc
   expansion stays intact: reviewers should reject cleanup that smuggles new
   product or architecture decisions into reconciliation.
5. **Prompt tests pin the behavior.** Tests assert that the prompt names the
   sweep subsection, omissions, dispositions, and the core artifact families
   without adding unrelated implementation-review or test-quality checks.
