## Slice 081-01 — post-land main worktree sync

**Goal:** After a successful landing to `origin/main`, jig updates the
canonical local `main` worktree to that same remote tip, or clearly reports
why the local sync was skipped.

**DoR:**
- ✅ Spec 051 / ADR-0015 establish `origin/main` as the authority for
  reservations and worktree-safe mainline transactions.
- ✅ `docs/workflow.md` already documents that pushed claims/reservations do
  not automatically advance local `main`.
- ✅ Before implementation, identify the slice-land helper chokepoint that
  runs after the authoritative push to `origin/main` succeeds.

**Acceptance Criteria:**

1. **Successful direct landing syncs canonical `main`.** When the direct
   landing path successfully pushes to `origin/main`, it finds the local
   worktree checked out at `refs/heads/main`, fetches `origin/main`, and
   fast-forwards that worktree to the pushed tip. The command output includes
   a compact confirmation naming the synced path and commit.
2. **Caller worktree remains stable.** The sync runs via `git -C
   <main-worktree> ...` or equivalent. A landing invoked from a linked,
   detached, or feature worktree does not switch the caller's checkout, move
   the caller's branch, or stage files in the caller's worktree.
3. **Skipped syncs are explicit and non-destructive.** If no canonical
   `main` worktree exists, or if it is dirty, locked, diverged from
   `origin/main`, or cannot be fast-forwarded, the landing command exits with
   the same success/failure status it would have used for the remote landing
   and prints `local main sync skipped: <reason>` or equivalent. It does not
   reset, stash, rebase, or merge.
4. **PR-shaped landings do not claim a sync before merge.** A landing mode
   that creates a PR rather than updating `origin/main` directly reports that
   local `main` sync is pending on merge, unless the implementation can prove
   the PR was merged and `origin/main` advanced during the command.
5. **Docs record the invariant.** `docs/workflow.md` and slice-land guidance
   state that reservation/landing correctness depends on `origin/main`, and
   that local `main` sync is the final housekeeping step after a successful
   authoritative push.
6. **Regression coverage exercises success and skip paths.** Tests cover at
   least: normal fast-forward, missing main worktree, dirty main worktree,
   and invocation from a non-main worktree.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Direct mode no longer runs `git checkout main`.** The implementation
   changed the direct execute path to run `git push origin <branch>:main`
   from the caller worktree after the fast-forward guard passes, leaving the
   caller's feature/detached worktree untouched. The canonical local
   worktree checked out at `refs/heads/main` is used only for post-push sync
   housekeeping; if it is missing, the already-successful landing remains
   successful and reports `local main sync skipped: no local worktree checked
   out at refs/heads/main`.
2. **Post-push local sync is explicit housekeeping.** After a successful
   direct push, `land.py` checks that the local main worktree exists, is not
   locked by `git worktree list --porcelain`, and is clean; then it fetches
   `origin main`, verifies fast-forward ancestry, runs
   `git merge --ff-only origin/main`, and reports either
   `local main synced: <path> @ <commit>` or
   `local main sync skipped: <reason>`. A skipped sync does not change the
   already-successful authoritative push result.
3. **PR mode reports pending sync.** `execute --mode pr` now states that
   local main sync is pending on PR merge; it does not claim local `main`
   moved before `origin/main` changes.
4. **Docs and guidance updated.** `docs/workflow.md`,
   `skills/slice-land/SKILL.md`, and `prepare --mode direct` guidance now
   describe the origin-authority invariant and the post-land local-main sync
   step.
5. **Verification.** Added `LocalMainSyncTests` plus updated direct-mode
   sequence expectations. Focused verification:
   `python3 -m unittest test_land` from `skills/slice-land` passed
   (120 tests, 1 skipped). Full verification:
