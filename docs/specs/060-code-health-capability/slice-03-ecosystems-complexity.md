## Slice 060-03 — Broaden ecosystems + complexity dimension

**Goal:** Extend `health.py` beyond Python — drive Node's linter/formatter (eslint + prettier-check) and make ecosystem detection table-driven so a new language is an entry, not a fork — and add the **complexity** check dimension (ruff `C901` / `PLR09xx` for Python; the ecosystem's equivalent elsewhere), still normalized and degrading gracefully.

**DoR:**
- ✅ 060-01 DONE (the detect → run → normalize → summary spine exists for one ecosystem).

**Acceptance Criteria:**

1. **Ecosystem detection is data-driven and extensible.** `health.py` detects Python and Node projects by marker files (`pyproject.toml` / `*.py`; `package.json`) and selects the ecosystem's linter from a table; adding an ecosystem is a table entry with no control-flow fork.
2. **Node: drive eslint (+ prettier check).** On a Node project with eslint resolvable, `health.py check` runs it and normalizes to 0 / 1 / 2.
3. **Complexity dimension.** `health.py check` surfaces a per-function complexity signal where the ecosystem's tool supports it (ruff `C901` / `PLR09xx` for Python) — **advisory** (reported, not gating) by default.
4. **Mixed / unknown ecosystems degrade,** never crash (exit 2 + a one-line recommendation).
