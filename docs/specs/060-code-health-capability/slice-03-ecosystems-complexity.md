## Slice 060-03 — Broaden ecosystems + complexity dimension

**Goal:** Extend `health.py` beyond Python — drive Node's linter/formatter (eslint + prettier-check) and make ecosystem detection table-driven so a new language is an entry, not a fork — and add the **complexity** check dimension (ruff `C901` / `PLR09xx` for Python; the ecosystem's equivalent elsewhere), still normalized and degrading gracefully.

**DoR:**
- ✅ 060-01 DONE (the detect → run → normalize → summary spine exists for one ecosystem).

**Acceptance Criteria:**

1. **Ecosystem detection is data-driven and extensible.** `health.py` detects Python and Node projects by marker files (`pyproject.toml` / `*.py`; `package.json`) and selects the ecosystem's linter from a table; adding an ecosystem is a table entry with no control-flow fork.
2. **Node: drive eslint (+ prettier check).** On a Node project with eslint resolvable, `health.py check` runs it and normalizes to 0 / 1 / 2.
3. **Complexity dimension.** `health.py check` surfaces a per-function complexity signal where the ecosystem's tool supports it (ruff `C901` / `PLR09xx` for Python) — **advisory** (reported, not gating) by default.
4. **Mixed / unknown ecosystems degrade,** never crash (exit 2 + a one-line recommendation).

### Deviation log (after reconciliation)

**Design decisions (within scope, recorded per the slice contract):**

- **Unified advisory-probe mechanism.** Prettier (Node) and complexity
  (Python) are both modeled as `AdvisoryProbe` descriptors run by one
  `_run_advisory_probes` helper. This makes the exit-code contract uniform:
  the *primary* linter alone determines 0/1/2; advisory probes only append
  summary lines. AC3's "reported, not gating" is therefore structural, not
  per-call discipline.
- **Prettier as advisory, not gating (AC2/AC3).** `prettier --check` exits
  non-zero when files need formatting; treating that as a finding would have
  made formatting gate the lint result. Instead it is an advisory probe — a
  clean eslint run stays exit 0 even when prettier reports unformatted files.
  The summarizer is forgiving about prettier's banner lines (it counts
  candidate file lines, falling back to "some file(s)" when it can't).
- **Complexity rule-code selection (AC3).** The Python complexity probe runs
  `ruff check --select C901,PLR0911,PLR0912,PLR0913,PLR0915` (cyclomatic +
  the too-many-{returns,branches,args,statements} family), exactly as the
  slice specified. It reuses the ruff/uvx/pipx launcher chain. Best-effort:
  any failure to start or unparseable output is swallowed (`_run_advisory_probes`
  catches `Exception` broadly) and contributes nothing — never crashes.
- **Mixed → degrade, never guess (AC4).** With 2+ ecosystem markers, `check`
  exits 2 with a recommendation naming the detected ecosystems and pointing
  at `.jig/lint-command`. Zero markers → "no recognized ecosystem". One
  marker but no resolvable linter → the ecosystem-specific message (Python
  keeps the verbatim 060-01 ruff/pipx wording; Node names eslint/npx).
- **Override bypasses detection entirely.** `.jig/lint-command` is resolved
  before ecosystem detection and short-circuits it (preserving 060-01
  semantics, and why jig's own committed override is unaffected). Verified by
  running `health.py check .` from the worktree root → exit 0 via the
  committed pipx-ruff override, not a degrade.

**Principled test update (called out by the slice as NOT a workaround):**

- The 060-01 Python tests that used a *bare* tmp dir and expected ruff to
  resolve now seed a `pyproject.toml` marker (`_seed_python`) in their
  `setUp`. Ecosystem detection is now a real gate (AC4) — a bare empty dir is
  legitimately "unknown" and correctly exits 2. Affected: `ResolverTests`,
  `DetectTests`, `DegradationTests` (the latter seeds Python so it still
  exercises the *single-ecosystem-no-linter* path rather than the new
  no-ecosystem path). Tests that mock `resolve_lint_command` directly were
  unaffected and left untouched. All other existing tests stayed green.

**Minor / cosmetic:**

- For a `.jig/lint-command` override the `detect`/summary "resolved name" is
  derived generically from the override's first tokens (e.g. jig's own
  `pipx run --spec` override renders as `pipx run --spec`). This is unchanged
  060-01 behavior for overrides (the override path has no ecosystem to name)
  and is cosmetic only — the run itself is honored verbatim and the exit code
  is correct.

**Reconciliation-time craft fixes (from the craft review's nits):**

- Extracted `_ruff_launcher(args)` so the ruff/uvx/pipx launcher chain lives
  in one place (the primary resolver and the complexity probe both call it),
  removing the duplicated branch block.
- Dropped the speculative `_summarize_findings = _summarize_ruff` back-compat
  alias — no caller or test referenced it (confirmed by grep).
- Clarified the `_detect_node` docstring (it keys off `package.json`
  *presence*, not tdd.py's parsed `_pkg_deps`).
- Verified the craft review's `_resolved_name` note: a `pipx run --spec …`
  override renders as `pipx run --spec` (the `pipx` branch takes `argv[:3]`),
  exactly as the cosmetic note above states — the deviation log was already
