**Goal:** Wire jig's own CI to run `health.py check` against jig's Python, enforcing a Ruff lint floor — closing the audit gap that motivated ADR-0017 and proving the capability on a real codebase before it ships to others.

**DoR:**
- ✅ 060-01 DONE (`health.py` + the `jig:code-health` skill exist and drive ruff).

**Acceptance Criteria:**

1. **A config-only `ruff.toml` exists at the repo root** carrying the curated starter set (`select = ["F","E","W","I","B"]`, `ignore = ["E402"]`, `line-length` set to jig's house style). It does **not** turn the repo into a pip package (no `pyproject.toml` added).

4. **Invokable locally the same way CI invokes it** (one command), mirroring how `run_tests.py` is both the CI step and the local command.

### Deviation log (after reconciliation)

- **Version pin lives in `.jig/lint-command`, not inline in `ci.yml`.** AC2 phrases the runner as "(`pipx run ruff …` / `health.py`)". The implementation routes through `health.py` for the dogfood AND pins the version reproducibly: `.jig/lint-command` = `pipx run --spec ruff==0.15.16 ruff check --output-format=json .`, and both CI and local invoke the single command `python3 skills/code-health/health.py check .` (which honors the override first). This is a faithful, arguably stronger reading — the pin is reproducible and CI exercises the actual capability, not a bypass. pipx is preinstalled on GitHub `ubuntu-latest`, so `pipx run` is ephemeral (installs nothing permanently).
- **`line-length = 100`** chosen as jig's "house style" (the spec left the number open). Recon: jig's p99 line length is 83 and only 16 lines exceed 100, vs 170 over the ruff-default 88 — so 100 reflects the real style and keeps adoption focused on genuine issues rather than mass comment-reflow.
- **Curated-set adoption cleanup.** The floor surfaced 130 findings at line-length 100; **101 auto-fixed** (`ruff check --fix`: I001 import-sort, F401 unused-import, F541 placeholder-less f-strings, E401, B905, F841, B007) and **29 hand-resolved**, applied as:
  - **E501 ×16** — long lines wrapped (string-literal splits / arg wraps; byte content preserved).
  - **E741 ×11** — ambiguous `l` renamed to `sl`/`ln` (all local comprehension / `splitlines()` bindings; no asserted strings touched).
  - **B905 ×4** — `strict=True` added to `zip()` calls over provably equal-length iterables (fixed parallel lists, or guarded by an explicit `len(...)==len(...)` assert).
  - **F841 ×4** / **B007 ×2** — removed genuinely-dead assignments; dropped an unused `enumerate` index in `migrate.py`; `args` → `_args` in `land.py`.
  - **B904 ×1** — `skills/memory-sync/memory.py`: `raise ... from None` (deliberate timeout cause-suppression).

  (The implementer brief's path/line guesses for the B-rule fixes were inaccurate — e.g. it cited `skills/spec-workflow/memory.py` for the B904, but it landed in the real `skills/memory-sync/memory.py`. The fixes themselves are correct and were verified behavior-preserving by both review passes; this log reflects the *actual* changes.)
- **One `# noqa: F401` retained deliberately.** `skills/spec-workflow/workflow.py:26` keeps `from _common import team_signal  # noqa: F401  (re-exported for test monkeypatching)` — `test_workflow.py` monkeypatches `_workflow.team_signal.count_team_contributors`, which needs the module bound at module scope (the separate `from _common.team_signal import team_context_drift` imports a symbol, not the module). The suite caught the blanket auto-removal; the `noqa` is the minimal correct fix. Two `# noqa: E402` and one `# noqa: F401 (re-export)` were likewise applied where ruff's finding is a false positive for a deliberate pattern.
- **060-01 DONE files touched (zero-behavior).** The floor runs against `.` (the whole repo, incl. `code-health` itself), so `skills/code-health/health.py` (one blank-line removal) and `test_health.py` (one import reorder) were auto-fixed. Excluding code-health from its own floor would undercut the dogfood; the 060-01 suite passes unchanged.
- **Redundant per-line `# noqa: E402` left in place.** With `E402` now globally ignored in `ruff.toml`, the pre-existing per-line `# noqa: E402` comments are dead weight (harmless — `RUF100` isn't selected). Parked as an optional follow-up (add `RUF100` to catch unused-noqa drift) rather than churned now — see `docs/refinement-todo.md`.
