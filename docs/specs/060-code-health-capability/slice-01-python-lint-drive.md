## Slice 060-01 — Python lint, detect-and-drive

**Goal:** Ship the `jig:code-health` skill + a `health.py` helper that, on a Python project, detects the installed linter (ruff), runs it, normalizes the result to a 0 / 1 / 2 exit code, and prints a tight summary — degrading to a recommendation when no linter is installed. The Tier-1 detect-and-drive MVP, end-to-end.

**DoR:**
- ✅ [ADR-0017](../../decisions/adr-0017-scaffolded-code-health.md) Accepted.
- ✅ `skills/tdd-loop/tdd.py` reviewed as the structural template (detect → run → normalize → exit codes → `.jig/*-command` override).

**Acceptance Criteria:**

1. **`health.py check` detects and drives ruff on a Python project.** Given a Python project with `ruff` resolvable (on `PATH` or via an ephemeral `pipx run` / `uvx`), `python3 health.py check <dir>` runs ruff and exits **0** when clean, **1** when findings exist. A findings count + the top rule codes appear on stdout.
2. **Normalized exit codes mirror `tdd.py`.** `0` = clean, `1` = findings, `2` = no runner available / env error. Each code is documented and has a test.
3. **Graceful degradation.** With no linter detectable and no ephemeral runner available, `health.py check` exits **2** and prints a one-line recommendation (e.g. `no Python linter found — install ruff or run via pipx`) — never a stack trace.
4. **`.jig/lint-command` override.** When a `.jig/lint-command` file is present its contents override auto-detection (mirrors `.jig/test-command`) and are honored verbatim.
5. **`jig:code-health` skill surface.** A `SKILL.md` exists with canonical frontmatter + a verb-led description (auto-trigger phrases, a "defers to a richer installed skill" clause, a "Do NOT use for…" block) and a bash recipe that calls `health.py`. A `test_*_skill_surface.py` asserts the description/structure (mirrors the other skill-surface tests).

### Deviation log (after reconciliation)

- **Empty/comment-only `.jig/lint-command` falls through to auto-detection** (vs. `tdd.py`, where an empty `.jig/test-command` is a hard error → exit 2). AC4 says "same parse semantics as `tdd.py`"; the *parsing* (first non-blank, non-comment line) is identical, but the *empty-result handling* deliberately diverges: a comment-only override resolves to the ruff auto-detection chain rather than erroring. Friendlier default, tested explicitly (`test_empty_override_falls_through`) and documented in `resolve_lint_command`'s docstring + SKILL.md. Recorded as a conscious, bounded divergence.
- **Ephemeral-runner preference `uvx` before `pipx`** (resolution order: `.jig/lint-command` → `ruff` on PATH → `uvx ruff` → `pipx run ruff`). AC1 names "`pipx run` / `uvx`" without ordering; `uvx` is preferred because it is the faster/cache-friendlier launcher. Consistent with ADR-0017's `pipx run` analogy; no behavioral risk (both run ruff ephemerally, installing nothing).
- **`cmd_check` catches `(FileNotFoundError, OSError)` on subprocess launch** (vs. `tdd.py`'s `cmd_run`, which catches only `FileNotFoundError` on the detected-runner path). Deliberate widening so a bad `.jig/lint-command` override that fails to start normalizes to exit 2 (env error), not 1 (findings). Pinned by `test_oserror_exits_2`.
- **`check` captures-and-summarizes rather than streaming** (vs. `tdd.py`, which streams the runner's stdout/stderr through to the caller). This is a principled, family-consistent design choice, not drift: the 060-05 code-health reviewer pass and spec 057's "tight envelope, not a transcript" contract require a *summary* (findings count + top rule codes), and the read-only reviewer subagent (ADR-0017 §Layering) consumes that summary — never the raw log. The non-zero-exit-with-no-parseable-findings branch surfaces ruff's stderr tail rather than crashing.
- **Skill registration touched beyond the four declared deliverables.** Adding the `code-health` skill required updating `_TIER_SKILLS["tier-1"]` in `skills/scaffold-init/scaffold.py` (source of truth) plus its restated mirrors (`scripts/scaffold_contract.py`, `scripts/install_contract.py`), the two pinning tests (`test_scaffold.py`, `test_migrate.py`), and doc-consistency resources (`docs/product-vision.md` tier-1 inventory + count 8→9, `vision-elicitation/worked-example-jig.md`), because jig's existing consistency tests assert the tier inventory stays in lockstep. Mechanical, test-required edits — not new behavior. `code-health` placed in **tier-1**, matching ADR-0017's "Tier 1 (always on): detect-and-drive" alongside `tdd-loop` / `security-review`.
- **ADR-0002 link target corrected during review.** The reviewer caught that `SKILL.md` linked `[ADR-0002](…/adr-0002-extract-helper-on-third-caller.md)` — a non-existent file (the rule-of-three decision lives in ADR-0002, whose real file is `adr-0002-contracts-stays-deferred.md`, per `adr-0003-extract-find-slice-section.md:9`).
