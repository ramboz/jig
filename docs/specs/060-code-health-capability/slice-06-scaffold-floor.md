## Slice 060-06 — Tier-2 scaffold-the-floor (opt-in)

**Resolution trigger:** Tier-1 (slices 01–05) has shipped and proven out on jig, **and** a user/project explicitly wants jig to *provision* a default code-health config rather than only drive an existing one.

**Goal:** At `scaffold-init` / `migrate` time, optionally write a language-appropriate default config (`ruff.toml` for Python, eslint + prettier for Node) plus a CI step into the target — idempotent and non-clobbering — strictly behind a tier/prompt so it is never imposed. Resolves ADR-0017 OQ3 (Tier-2) and the scaffold side of the detect-vs-scaffold fork.

**DoR:**
- ✅ 060-01 DONE.
- ✅ Tier placement settled (Tier-2 = opt-in scaffold).

**Acceptance Criteria:**

1. **Opt-in only.** A default `scaffold-init` / `migrate` run does **not** write code-health config; a tier selection / explicit prompt is required to trigger it.
2. **Language-appropriate default written** for the detected ecosystem (Python → `ruff.toml`; Node → eslint + prettier) plus a CI step that invokes the Tier-1 runner.
3. **Non-clobbering / idempotent.** An existing lint config is detected and **not** overwritten — reuse the scaffold-mode append-with-marker / refuse-on-unmanaged strategy (`UnmanagedHooksError`-style refuse + `--force` escape, per [ADR-0013](../../decisions/adr-0013-security-floor-policy.md) / spec 016-02). Re-running is a no-op.
4. **`scripts/verify_install.py` / the scaffold contract assert** the Tier-2 install when selected (and assert its absence when not).
