## Slice 060-04 — Duplication: native-first, `npx jscpd` fallback

**Goal:** Add the duplication dimension, resolving ADR-0017 OQ1: prefer the ecosystem's native duplication tool where one exists; otherwise fall back to an ephemeral `npx jscpd` (when Node is available); otherwise degrade to a recommendation. Duplication never *forces* a Node dependency, but is available everywhere Node already is.

**DoR:**
- ✅ 060-01 DONE (the runner spine + summary shape exist).

**Acceptance Criteria:**

1. **Native-first.** Where the detected ecosystem has a native duplication tool, `health.py check` drives it for the duplication dimension.
2. **`npx jscpd` fallback when Node is present.** With no native tool but `npx` available, the duplication check runs `npx jscpd` ephemerally (no install) and reports the duplication percentage.
3. **Graceful skip.** With neither a native tool nor Node, duplication is reported as `skipped (no detector)` plus a one-line recommendation — and the **overall exit code is unaffected** (duplication is advisory).
4. **Tight summary, not raw logs.** Output is a percentage + the top clones (`file:line`), honoring the spec 057 "tight envelope" discipline — never the full tool log.

### Deviation log (after reconciliation)

**`AdvisoryProbe.skip_summary` extension (no fork).** Duplication needed a
"reported even when it can't run" line, unlike complexity/prettier which stay
silent when unavailable. Added one optional field to the existing dataclass —
`skip_summary: Optional[str] = None` — and a single branch in
`_run_advisory_probes`: when `resolve()` returns `None`, append `skip_summary`
if set, else stay silent. This preserves 060-03 behavior exactly (complexity /
prettier have no `skip_summary`, so they remain silent — covered by
`AdvisoryProbeSkipSummaryTests`) and is the minimal principled extension. The
"advisory probes NEVER change the exit code" invariant is untouched.

**Empty native branch — deliberate, no native tool wired.** `_resolve_duplication`
documents a native-first order, but the native (per-ecosystem) branch is
intentionally empty/structural: no ecosystem in jig's tool set ships a distinct
native duplication detector (ruff has none; jscpd is the language-agnostic
tool). I deliberately did NOT shoehorn in a flaky native tool (e.g. pylint's
`duplicate-code`/R0801, which is noisy and config-sensitive) just to populate
the branch — that would add a flaky, low-value path. A future native tool is a
one-line addition there, mirroring 060-03's table extensibility. The
no-native-present case is asserted honestly: `DuplicationResolverTests` tests
the documented order (jscpd-when-npx, else None) and does NOT fake a native
tool for a path that doesn't exist (a comment in the test points at the
extension point).

**jscpd invocation + parsing (verified against the real CLI).** Ran
`npx jscpd --help` and a real run to confirm flags/shape. Chosen invocation:
`npx jscpd --reporters json --output <temp-dir> --silent <target>`. Key real-CLI
facts: jscpd writes its report to a **file** (`<output>/jscpd-report.json`), not
stdout — so I point `--output` at a fresh `tempfile.mkdtemp(prefix="jig-jscpd-")`
dir OUTSIDE the project (never pollutes `target`) and read `jscpd-report.json`
back in the summarizer (the temp dir's lifecycle is runner-owned — see the
hand-off note below). No `--threshold` is passed, so jscpd
**exits 0** regardless of duplication found — correct for an advisory probe that
must not gate. `--silent` suppresses progress chatter. Parsing reads
`statistics.total.{percentage,clones}` for the headline and `duplicates[].firstFile.{name,startLoc.line}`
for the top `TOP_CLONES=3` `file:line` clones; malformed/missing/shapeless input
→ `None` (report nothing), never a crash (`JscpdParsingTests`).

**Resolver→summarizer hand-off: runner-owned temp dir (`needs_workdir`).**
jscpd's report lands in a file, so the summarizer needs to know which dir the
resolver pointed `--output` at. The **first** implementation passed this via a
module-level slot (`_LAST_JSCPD_OUTPUT_DIR`) with cleanup in the summarizer's
`finally`. The craft review caught a real bug: if `subprocess.run` raised, the
runner's broad `except` skipped the summarizer, so its `finally` never ran and
the temp dir **leaked** — and the docstring's "never leaks regardless of
outcome" claim was false on that path.

**Reconciliation fix (craft-review blocker):** eliminated the module global
entirely. `AdvisoryProbe` gained a `needs_workdir: bool` flag; the runner
(`_run_advisory_probes`) now OWNS the temp dir via a `tempfile.TemporaryDirectory`
context and **threads the same `workdir` into both `resolve(target, workdir)`
and `summarize(rc, out, err, workdir)`** (a new `_run_one_probe` helper holds
the per-probe try/except). The `with` block guarantees teardown on EVERY exit
path — normal return, parse failure, AND a raising subprocess. The
probe-resolver/summarizer signatures are now uniform (`workdir: Optional[Path]`,
ignored by the stdout-only complexity/prettier probes). This removes both the
leak and the module-global smell in one move. Locked by `WorkdirLifecycleTests`:
`test_workdir_cleaned_after_normal_run`, `test_workdir_cleaned_when_subprocess_raises`
(globs `jig-jscpd-*` before/after to prove no leak), and
`test_workdir_threaded_into_resolve_and_summarize`. Also fixed the stale
`test_health.py` module docstring (060-01 → spans 060-01/03/04).

**Override path unchanged (note).** The `.jig/lint-command` override still runs
NO advisory probes (so duplication does not run under an override) — consistent
with 060-03 and the reason jig's own dogfood CI is unaffected. Verified:
`health.py check .` from the worktree root exits 0 with no duplication line.

**Deferred:** nothing punted to `docs/refinement-todo.md` — the empty native
branch is a documented design decision (recorded above), not an undefined case.
Real-CLI quirk worth noting for 060-05/future work: jscpd reports `file:line`
paths relative to its cwd, which can render as `../../tmp/...` when the target
is given as an absolute path — cosmetic for an advisory signal, not fixed here.
