## Slice 043-01 — quality-test-coverage

**Goal:** Close the documented gaps in
[skills/tdd-loop/test_quality.py](../../../skills/tdd-loop/test_quality.py)
so quality.py's signal logic is trustworthy enough to feed reviewer
prompts in slice 043-03.

**DoR:**
- ✅ quality.py exists, is stdlib-only, and its current 15-test smoke
  suite passes (`python3 -m unittest discover -s skills/tdd-loop -p
  'test_quality.py'`).
- ✅ The test file's own docstring already enumerates the gaps as
  "deeper coverage (flood / assertion-thin / mock-heavy threshold
  edges, malformed diff variants, gh fallback)" — the scope is
  pre-named.

**Acceptance Criteria:**

1. **`per-file-flood` signal fires.** A test diff with one test file
   carrying >100 added test functions fires
   `per-file-flood: true`. A second test with `new_code_files=1` and
   `new_tests=31` (ratio 31, over the 30 threshold) also fires.
   Symmetric negative tests at threshold-minus-one confirm the gate.
2. **`mock-heavy` signal fires.** A diff with ≥10 new test functions
   and mock density >5.0 fires `mock-heavy: true`. A diff with the
   same density but fewer than 10 tests stays quiet (min-test gate).
3. **`count_parametrize_cases` walker handles non-trivial argvalues.**
   Tests cover: trailing comma after the last case, nested tuples
   (`[(1, (2, 3)), (4, (5, 6))]`), a string literal containing a comma
   (`[("a,b", 1), ("c", 2)]`), and the 80-line lookahead boundary
   (decorator whose argvalues span >80 lines returns a sensible
   fallback rather than crashing).
4. **`pytest.raises` patterns count as assertions.** Both bare
   `pytest.raises(X)` and `with pytest.raises(X):` forms increment
   `new-assertions`.
5. **Malformed diff variants don't crash.** Binary-file headers
   (`Binary files a/x.png and b/x.png differ`), pure renames (no `+` /
   `-` lines), and mode-only changes all parse without exception and
   contribute zero to the test/code counters.
6. **YAML schema validates.** At least one test parses the emitted
   YAML (stdlib `yaml` is unavailable per the stdlib-only constraint,
   so use a hand-rolled minimal parser or `ast.literal_eval`-style
   shape checks) and confirms: `schema-version: 1`, `applicable: true`
   when applicable, the three signal keys present, the metrics keys in
   the declared order.
7. **`--against` ref code path is exercised.** A test invokes
   quality.py with `--against HEAD` (no `--diff-file`) inside a tmp
   git repo with a known diff, and confirms the snapshot matches the
   `--diff-file` equivalent.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Tests-only scope, no `quality.py` changes.** The slice anticipated
   "if a real bug surfaces, fix it" — none did. All seven ACs landed
   as new test coverage in
   [skills/tdd-loop/test_quality.py](../../../skills/tdd-loop/test_quality.py)
   (expanded from 233 → 720 lines, 15 → 35 tests). The implementer
   reported no inbox items and no deferred decisions.

2. **Reviewer findings folded back in.** Two cheap test-tightening
   nits flagged by both the compliance and craft reviewers were
   addressed inline before transitioning to REVIEWED:
   - `test_ratio_31_over_1_code_fires` now also asserts
     `max-it-per-file: 31`, disambiguating that the signal fired via
     the tests-per-new-code-file ratio branch (not the
     max-per-file branch). A future regression that drops one of
     the two predicates in `compute_signals` will surface here.
   - `test_eighty_line_lookahead_boundary` was tightened from
     `>= 1` to `> 1 and <= 200`. The lower bound rules out a future
     regression where the walker silently returns 1 in all
     truncation cases (the no-decorator fallback path); the upper
     bound holds the declared total as an invariant.

3. **Reviewer nits deferred as polish.** The craft pass flagged four
   additional nits judged out-of-scope for this slice:
   - Re-invoking `_load_quality()` per `setUp` instead of a
     module-level constant or `setUpClass`. Minor speed win;
     semantically harmless.
   - Redundant `git config user.email/name` in `AgainstRefTests`
     when `GIT_AUTHOR_*` / `GIT_COMMITTER_*` env vars already win.
     Dead belt-and-suspenders, not wrong.
   - Renaming `_parse_minimal_yaml` to signal its tight coupling to
     `quality.py`'s emission shape. Cosmetic.
   - The AC1 boundary test at exactly 100 maps to the AC's
     "threshold-minus-one" phrasing because `compute_signals` uses
     strict `>`. Informational only.

   None of these block correctness or future maintenance; folding them
   in would have expanded the diff without sharpening the signal.

4. **No doc updates needed.** This slice doesn't introduce a new
   skill, doesn't move a contract surface, and doesn't change any
   documented behaviour of `quality.py`. CLAUDE.md Skills table
   unchanged. `docs/refinement-todo.md` unchanged (no decisions
   deferred). Status board regen happens at slice close-out.

5. **Plan adherence.** Implementation followed the slice's stated
   approach precisely — one test class per AC, stdlib-only,
   subprocess-driven where the public CLI surface is being
   exercised, direct `_load_quality()` import where the walker is
   being exercised in isolation (AC3). No spike branch, no
   architectural rework.
