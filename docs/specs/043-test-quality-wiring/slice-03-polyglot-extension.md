## Slice 043-03 — polyglot-extension

**Goal:** Extend
[skills/tdd-loop/quality.py](../../../skills/tdd-loop/quality.py)
to recognize vitest and jest test diffs so the snapshot in slice
043-04 produces real signals on JS/TS projects, not
`applicable: false`.

**DoR:**
- ✅ Slice 043-01 DONE — quality.py's existing signal logic is
  tested. New JS/TS patterns are added on a foundation that's
  already verified.
- ✅ quality.py's threshold constants are already calibrated by
  043-02 against the Python corpus. JS/TS calibration with adopter
  data is a separate follow-up (logged in refinement-todo at this
  slice's RECONCILED → DONE transition); we accept that vitest/jest
  signals may need re-tuning when real adopter diffs exist.

**Acceptance Criteria:**

1. **Path classifier recognizes JS/TS test conventions.** The
   `TEST_PATH_REGEX` (or a sibling) matches `*.test.{js,jsx,ts,tsx,mjs}`,
   `*.spec.{js,jsx,ts,tsx,mjs}`, and any path under `__tests__/` or
   `tests/`. The `CODE_PATH_REGEX` (or sibling) extends to recognize
   `*.{js,jsx,ts,tsx,mjs}` as code paths so `test-to-code-ratio`
   computes meaningfully on JS/TS diffs.
2. **Test-block detection matches vitest/jest function shapes.** Added
   lines matching `it(`, `test(`, or `describe(` (with optional `.skip`
   / `.only` / `.each` modifiers) count toward `new-it-blocks`. `it.each`
   / `test.each` table forms expand to one block per case, mirroring how
   `@pytest.mark.parametrize` is counted for Python — reuse the existing
   `count_parametrize_cases` walker shape or extract a shared helper.
3. **Assertion vocabulary covers JS/TS idioms.** Added lines containing
   `expect(`, `assert.X(` (Node's `assert` module), and `chai.expect(`
   patterns increment `new-assertions`. The plain `assert(...)` form
   stays out — too easy to false-positive on application code that
   uses `assert` as a runtime guard.
4. **Mock vocabulary covers vitest/jest.** Added lines matching `vi.mock(`,
   `vi.fn(`, `vi.spyOn(`, `vi.stubGlobal(`, `jest.mock(`, `jest.fn(`,
   `jest.spyOn(`, and `jest.doMock(` increment `new-mocks`. Same
   anywhere-on-line pattern as the existing Python mock regex (mocks
   appear in assignments and decorators).
5. **`docs-only-or-no-test-or-code-changes` no longer fires for JS/TS
   diffs.** A diff that touches only `.ts` source + `*.test.ts` files
   produces `applicable: true` with non-zero `new-test-files` and
   `new-code-files`, where today's behavior reports
   `applicable: false`.
6. **Existing Python behavior is unchanged.** The full slice-043-01
   test suite (plus the calibration spike sample from 043-02) re-runs
   green with no metric or signal drift on Python-only diffs.
7. **Polyglot tests added.** Mirror the 043-01 coverage shape for JS/TS:
   path-classifier tests for `.test.ts` / `.spec.tsx` / `__tests__/`,
   counting tests for `it()` / `describe()` / `it.each()`, assertion
   tests for `expect()`, mock tests for `vi.mock()` and `jest.fn()`,
   and a smoke test for a mixed-language diff (Python + TS in the
   same change-set) that exercises both classifier branches.
