## Slice 043-03 — polyglot-extension

**Goal:** Extend
[skills/tdd-loop/quality.py](../../../skills/tdd-loop/quality.py)
to recognize vitest and jest test diffs so the snapshot in slice
043-04 produces real signals on JS/TS projects, not
`applicable: false`.

**DoR:**
- ✅ Slice 043-01 DONE — quality.py's existing signal logic is
  tested. New JS/TS patterns are added on a foundation that's
  already verified.
- ✅ quality.py's threshold constants are already calibrated by
  043-02 against the Python corpus. JS/TS calibration with adopter
  data is a separate follow-up (logged in refinement-todo at this
  slice's RECONCILED → DONE transition); we accept that vitest/jest
  signals may need re-tuning when real adopter diffs exist.

**Acceptance Criteria:**

1. **Path classifier recognizes JS/TS test conventions.** The
   `TEST_PATH_REGEX` (or a sibling) matches `*.test.{js,jsx,ts,tsx,mjs}`,
   `*.spec.{js,jsx,ts,tsx,mjs}`, and any path under `__tests__/` or
   `tests/`. The `CODE_PATH_REGEX` (or sibling) extends to recognize
   `*.{js,jsx,ts,tsx,mjs}` as code paths so `test-to-code-ratio`
   computes meaningfully on JS/TS diffs.
2. **Test-block detection matches vitest/jest function shapes.** Added
   lines matching `it(`, `test(`, or `describe(` (with optional `.skip`
   / `.only` / `.each` modifiers) count toward `new-it-blocks`. `it.each`
   / `test.each` table forms expand to one block per case, mirroring how
   `@pytest.mark.parametrize` is counted for Python — reuse the existing
   `count_parametrize_cases` walker shape or extract a shared helper.
3. **Assertion vocabulary covers JS/TS idioms.** Added lines containing
   `expect(`, `assert.X(` (Node's `assert` module), and `chai.expect(`
   patterns increment `new-assertions`. The plain `assert(...)` form
   stays out — too easy to false-positive on application code that
   uses `assert` as a runtime guard.
4. **Mock vocabulary covers vitest/jest.** Added lines matching `vi.mock(`,
   `vi.fn(`, `vi.spyOn(`, `vi.stubGlobal(`, `jest.mock(`, `jest.fn(`,
   `jest.spyOn(`, and `jest.doMock(` increment `new-mocks`. Same
   anywhere-on-line pattern as the existing Python mock regex (mocks
   appear in assignments and decorators).
5. **`docs-only-or-no-test-or-code-changes` no longer fires for JS/TS
   diffs.** A diff that touches only `.ts` source + `*.test.ts` files
   produces `applicable: true` with non-zero `new-test-files` and
   `new-code-files`, where today's behavior reports
   `applicable: false`.
6. **Existing Python behavior is unchanged.** The full slice-043-01
   test suite (plus the calibration spike sample from 043-02) re-runs
   green with no metric or signal drift on Python-only diffs.
7. **Polyglot tests added.** Mirror the 043-01 coverage shape for JS/TS:
   path-classifier tests for `.test.ts` / `.spec.tsx` / `__tests__/`,
   counting tests for `it()` / `describe()` / `it.each()`, assertion
   tests for `expect()`, mock tests for `vi.mock()` and `jest.fn()`,
   and a smoke test for a mixed-language diff (Python + TS in the
   same change-set) that exercises both classifier branches.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Implemented as a strict "extend" rather than a "rewrite."** The
   slice was explicit on this point. New JS-prefixed parallel
   constants (`JS_TEST_BLOCK_ADDED`, `JS_TEST_BLOCK_REMOVED`,
   `JS_EACH_ADDED`, `JS_ASSERTION_PATTERNS`, `JS_MOCK_PATTERN`) live
   alongside the existing Python ones; `classify_language()` gates
   per-file dispatch in `compute_metrics()`. Zero existing-Python
   constants or tests were modified — verified by the 35-test
   pre-existing suite running unchanged + a dedicated
   `PolyglotPythonRegressionTests` smoke test, and confirmed
   externally by re-running `quality.py` against all 61 historical
   `feat(...): NNN-NN` commits on `main`: still zero fires (same as
   post-043-02), no metric drift.

2. **`count_each_cases` is a sibling of `count_parametrize_cases`,
   not a shared helper.** AC2 allowed either route. Sibling won
   because the entry-point logic differs (`.each(` takes the array as
   its FIRST argument; `parametrize(` takes it as the SECOND), and
   the rest of the state machine differs in accepted-bracket sets and
   stop conditions. A shared helper would need a "skip-N-args"
   parameter — more code than the duplicate. Trade-off acknowledged.

3. **`it.each` template-literal-tagged form is a known limitation.**
   The array-of-arrays form (`it.each([[1,2],[3,4]])`) expands
   correctly; the tagged-template form (`` it.each`a | b\n1 | 2` ``)
   falls back to count=1. Logged in
   [docs/refinement-todo.md](../../refinement-todo.md) as a
   sub-bullet under the JS/TS calibration entry, with the implicit
   trigger "out of scope for 043-03 since it's a minority idiom" —
   the practical resolution trigger is an adopter slice using the
   tagged form. Tracked, not promoted to its own deferred-decision
   entry.

4. **Per-language gating asymmetry on `MOCK_PATTERN`.** The Python
   `MOCK_PATTERN` uses anchored `^\+.*?\b…` (one match per line); the
   `JS_MOCK_PATTERN` is anchor-free and the call site uses `findall`
   on the stripped line. Justified because vitest idioms like
   `vi.stubGlobal("fetch", vi.fn())` chain two mock invocations on
   one expression and Python's mock idioms don't. Tested directly by
   `PolyglotMockTests.test_counts_vi_spyOn_and_stubGlobal` (three
   mocks on two lines). Comment on `JS_MOCK_PATTERN` documents the
   divergence.

5. **Reviewer findings folded back in.** Two high-value nits were
   addressed inline before transitioning to REVIEWED:
   - **`EachWalkerTests` added** (mirrors `ParametrizeWalkerTests`).
     Direct walker coverage of the four edge cases (trailing comma,
     nested arrays, string-with-comma, 80-line lookahead) + a
     regression guard for the `.find(".each(")` anchor (a string
     literal containing `.each(` in the test name pins current
     correct behavior). Five new tests; suite is now 69 green.
   - **Threshold-constants comment updated** to point at the
     `docs/refinement-todo.md` entry rather than implying slice
     043-03 still owed cross-language calibration.

6. **Reviewer findings deferred as polish.** Both reviewers raised
   small craft nits that didn't justify churn:
   - `count_each_cases` accepts `{` as a depth-incrementing bracket
     in addition to `[` and `(`. Benign for the documented use case;
     object-row form (`it.each([{a:1}, {a:2}])`) gets counted
     correctly; only matters if someone embeds an object containing
     depth-1 commas under unusual nesting. Not exercised by any
     test; left as latent.
   - `classify_language` calls `re.search` with a literal pattern
     rather than a module-level compiled regex. Pure polish; called
     infrequently, no measurable cost.
   - `compute_metrics()` per-language dispatch is two parallel
     `if lang == "py" / elif lang == "js"` chains. Reviewer agreed
     this is honest at two languages; revisit when a third lands.
   - `JS_TEST_BLOCK_ADDED` has no word-boundary anchor before
     `(it|test|describe)`, so an added line `+    test(value);`
     calling a helper function literally named `test` would match.
     Vitest/jest convention discourages this; the false-positive is
     narrow.

7. **No doc updates beyond this slice body + the refinement-todo
   entries.** No new skill (no CLAUDE.md Skills-table change), no new
   contract surface, no ADR signal (extending an existing helper is
   tactical, not architectural). The status-board Notes column gets
   no new per-slice invariant — the "JS mock vocabulary excludes
   plain `assert()`" choice is documented inline in
   `JS_ASSERTION_PATTERNS` with both a comment and a dedicated
   negative test, so it doesn't need a Notes-column anchor.

8. **Plan adherence.** All seven ACs landed as specified. The
   implementation followed the slice's stated approach (extend not
   rewrite; reuse the walker shape; calibration deferred). Two
   reviewer-flagged tightenings folded in.
