## Slice 043-04 — review-prompt-injection

**Goal:** Wire quality.py's YAML snapshot into the
`build_implementation_prompt` builder in
[skills/independent-review/review.py](../../../skills/independent-review/review.py)
and add a SKILL.md mention in
[skills/tdd-loop/SKILL.md](../../../skills/tdd-loop/SKILL.md) so the
preflight stops being orphaned.

**DoR:**
- ✅ Slice 043-01 DONE — quality.py's signal logic is tested.
- ✅ Slice 043-02 DONE — thresholds confirmed (or tuned with data).
- ✅ Slice 043-03 DONE — quality.py recognizes vitest/jest diffs so
  the snapshot is meaningful on JS/TS jig adopters, not just on
  jig itself.
- ✅ The existing precedent for prompt fragments
  (`_contract_surface_check_block()`, `_principles_check_block()`,
  `_practices_check_block()`) is well-established; this slice
  follows the same shape.

**Acceptance Criteria:**

1. **`build_implementation_prompt` runs quality.py and embeds the
   YAML.** A new helper (e.g., `_test_quality_snapshot_block(spec_path)`)
   computes the slice's merge-base against `main`, invokes
   `quality.py --diff-file <tmp>` against `git diff
   <merge-base>...HEAD` output, and returns a string of the form
   `## Test-quality snapshot (deterministic)\n\n```yaml\n<output>\n```\n`
   appended to the prompt between the `## Evaluate` block and the
   `_principles_check_block`. The block is appended UNCONDITIONALLY
   for the implementation pass.
2. **The reviewer prompt instructs cite-or-stay-silent.** Two
   sentences are appended after the YAML: (a) "When raising a
   test-quality finding, cite the fired signal by name." (b) "When
   all signals read false, do not invent test-quality concerns —
   absence of a signal is evidence of nothing-to-flag." Both
   sentences are inside the snapshot block so a reviewer reads them
   in context.
3. **Failure modes degrade gracefully.** If quality.py exits non-zero,
   the `git diff` returns empty, the merge-base can't be computed, or
   the snapshot's `applicable: false`, the block is replaced with a
   single line: `_Test-quality snapshot unavailable: <reason>._`
   The prompt builder must not crash, and the reviewer is told to
   proceed on judgment alone.
4. **Snapshot block does NOT land in pr-review or arch-review or
   reconciliation prompts.** Only `build_implementation_prompt` gets
   the injection. The other three builders are untouched (covered
   by a regression test asserting the string `test-quality-snapshot`
   appears in implementation-prompt output and is absent from the
   other three).
5. **SKILL.md mention in tdd-loop.** One paragraph in
   [skills/tdd-loop/SKILL.md](../../../skills/tdd-loop/SKILL.md)
   describes quality.py, names it as sibling-to-tdd.py, and points
   at "after the loop, see independent-review for how the snapshot
   feeds the implementation-review prompt." No skill-router
   changes — quality.py is a helper, not a SKILL.
6. **`docs/workflow.md` updated.** The post-implementation review
   section (step 4 of the session workflow) mentions that the
   implementation pass now embeds a deterministic test-quality
   snapshot.
7. **Scaffold-mode copies quality.py + test_quality.py.** scaffold.py's
   copy-machinery list (the same surface that today copies
   `skills/_common/` per slice 032's hotfix) extends to include
   `skills/tdd-loop/quality.py` and `skills/tdd-loop/test_quality.py`.
   A scaffolded project's `review.py` can import / shell out to
   `quality.py` and produce the snapshot block with no extra setup.
   Tested via the existing scaffold-mode fixture or an extension of
   it (a fresh scaffold-init has quality.py reachable at the
   expected path).

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Snapshot helper landed as `_test_quality_snapshot_block(spec_path)`
   in [review.py](../../../skills/independent-review/review.py).** Same
   shape as the existing `_contract_surface_check_block` /
   `_principles_check_block` / `_practices_check_block` helpers
   (per AC1 design constraint). Helper computes `git merge-base main
   HEAD`, runs `git diff <merge-base>...HEAD`, writes to a tempfile,
   shells out to `quality.py --diff-file`, wraps the YAML in a fenced
   block with the cite-or-stay-silent sentences (AC2). All four AC3
   failure modes route to the same `_Test-quality snapshot
   unavailable: <reason>._` single-line fallback.

2. **AC3 coverage gap closed at review.** The initial implementation
   tested only two of the four AC3 failure modes (empty-diff,
   no-merge-base). The compliance reviewer flagged this against the
   DoD's "edge cases covered explicitly" line. Two dedicated tests
   were added before transitioning to REVIEWED:
   - `test_helper_fallback_when_applicable_false` — drives a real
     docs-only diff through quality.py to trigger the
     `applicable: false` branch; asserts the inline reason
     (`docs-only`) is surfaced in the unavailable line.
   - `test_helper_fallback_when_quality_py_exits_nonzero` — uses
     `unittest.mock.patch` on `subprocess.run` to selectively return
     `returncode=2` for the quality.py call (passing git calls
     through); asserts the `quality.py exited non-zero` message.

   Total snapshot-helper tests: 6 (was 4); full suite: 110 review
   tests green.

3. **Prompt placement fixed: orphan-bullet issue resolved.** The
   initial implementation placed the snapshot as an `## H2` directly
   between the Evaluate bullets and the principles+practices bullets,
   leaving those two bullets as visual orphans under the snapshot H2.
   Both reviewers flagged this. Fix: added a `## Cross-cutting
   checks` H2 above the principles+practices bullets so they're
   properly parented. The snapshot retains its own H2 and the
   `snapshot-lands-before-principles` invariant still holds. Verified
   by rendering a real prompt:
   `Evaluate → snapshot → Cross-cutting checks → Output`.

4. **AC7 scaffold-mode: `_RETAINED_TEST_FILES` allow-list.** Rather
   than relaxing the general `test_*.py` exclusion rule in scaffold
   mode, the implementer added a narrow per-skill allow-list
   (`tdd-loop` → `{test_quality.py}`). Both reviewers identified this
   as the right shape — it scales: future quality-helper-style test
   files can be opted in explicitly without changing the general
   exclusion. Three scaffold-mode tests guard the contract.

5. **Reviewer findings deferred as polish.** The two reviewers
   converged on three small nits left in the code:
   - `_find_project_root(spec_path)` is called twice per
     implementation-prompt build (once in the snapshot helper, once
     in the builder). Micro-optimization; passing the resolved root
     in would shave one filesystem walk per prompt. Not load-bearing.
   - `applicable: false` reason-extraction regex doesn't anchor the
     indent. A future YAML schema-version bump that nested the field
     or quoted the value would silently miss-match; current shape is
     fine for schema-version 1.
   - The reason-extraction itself is "beyond AC text" — AC3 asks
     only for a single-line fallback, but surfacing the underlying
     reason (`not applicable (docs-only-...)`) is a useful
     enhancement that the reviewers explicitly endorsed.

6. **One observation worth flagging.** Running the live snapshot
   helper against this slice on this worktree produces
   `per-file-flood: true` because the diff between `main` and `HEAD`
   includes `test_quality.py` (980 LoC, added by slice 043-03 still
   sitting on this branch). Expected merge-base behavior, not a
   wiring bug — the reviewer is told to cite the fired signal by
   name and judge whether it applies. Surfaced here so future readers
   don't mistake it for a quality.py regression.

7. **No new ADR.** Cross-skill wiring (review.py shelling out to a
   sibling helper at a known path) is small and follows the existing
   `_contract_surface_check_block` precedent. Slice rationale is
   sufficient documentation. Confirmed by both reviewers.

8. **Plan adherence.** All seven ACs landed. The implementation
   followed the slice's stated approach (helper shape, placement
   intent, four-mode degradation, exclusion from sibling prompts,
   SKILL.md + workflow.md prose, scaffold-mode parity). Two
   reviewer-flagged tightenings folded in before REVIEWED.
