## Slice 041-02 — routing-stats-helper

**Goal:** `workflow.py routing-stats [--days N]` reads the routing trace and
prints a categorized histogram of which skills fired — jig baseline vs. richer
("other") skill per category — so the deferral pattern (spec 031) becomes
*measurable* instead of unobservable. Stdout-only; never writes.

**DoR:**
- ✅ Slice 041-01 landed: `.claude/skill-usage.jsonl` carries
  `event: "skill_invoked"` rows with verbatim `skill_name`, so there is a
  trace to summarize.

**Acceptance Criteria:**

1. **Per-category histogram.** `workflow.py routing-stats [--project-dir D]
   [--days N]` reads `D/.claude/skill-usage.jsonl` and prints one row per
   category — the invoked skill's name with any leading `jig:` plugin scope
   stripped — showing the jig-baseline count, the "other" (non-jig) count, and
   the total. Rows are sorted by total descending, then category ascending.
2. **Baseline-vs-richer split.** Within a category, a `jig:<name>` invocation
   counts toward the `jig` column and a bare `<name>` toward `other`. A
   category with `other > 0` and `jig = 0` is the observable signal that
   routing chose a richer skill over jig's baseline. A legend explains the
   columns.
3. **Filters the shared file.** Only `event == "skill_invoked"` rows are
   counted; the `Task`-spawn rows written by `jig-telemetry.sh` (no `event` /
   `skill_name`) are excluded.
4. **Windowed.** `--days N` (default 30) excludes entries older than N days,
   and the count of out-of-window entries is surfaced in the summary line.
5. **Robust, stdout-only, never gates.** A missing log prints a friendly
   "no routing data" message; an empty or all-filtered log prints "no skill
   invocations"; malformed JSON lines and unparseable timestamps are skipped
   without crashing; the command always exits 0 and never writes.

### Deviation log (after reconciliation)

The original slice spec is preserved above. Implementation notes:

**§1 — Plan adherence.** The helper landed as the drafted shape: a read-only
`workflow.py routing-stats [--project-dir D] [--days N]` that reads
`.claude/skill-usage.jsonl`, filters `event == "skill_invoked"`, buckets by
`jig:`-stripped category, and prints a histogram to stdout. It mirrors the
sibling `stale()` idiom (informational, never gates, never writes). No
deviation from the slice's stated approach. (The cross-spec deviation — the
trace shipping as a `PreToolUse`/`Skill` hook rather than a `UserPromptSubmit`
extension — belongs to slice 041-01 and is logged there.)

**§2 — Histogram design: category-split (jig baseline vs. "other"), resolving
spec open-question Q2.** The spec's Q2 tentatively leaned "jig only." That was
overridden by an explicit product decision to the **category-split** design:
strip the `jig:` scope to form a category, then within each category count
jig-baseline (`jig:<name>`) vs. non-jig ("other") invocations. Rationale: the
spec's whole purpose is observing whether *deferral* routed away from jig's
baseline — and deferral is invisible unless the richer (non-jig) skill is shown
(`other > 0`, `jig = 0` is the deferral signal). A jig-only histogram could not
answer the question it exists to answer.

**§3 — Reviewer findings folded in.** Both review passes returned `pass` (no
blockers). The two craft nits with real value were addressed in this
reconciliation, not deferred:
- *Discoverability:* added a `routing-stats` bullet to
  `skills/spec-workflow/SKILL.md` § "What this skill does" (and the subcommand
  is listed in the CLAUDE.md spec-workflow row), matching the precedent that
  operator subcommands are advertised on the skill's discovery surface.
- *AC #5 robustness:* hardened the trace read to
  `read_text(encoding="utf-8", errors="replace")` so a non-UTF-8 byte cannot
  escape the per-line `try` and break the "always exits 0" contract; pinned by
  the new `test_non_utf8_bytes_do_not_crash`. The legend's hard line breaks
  (a cosmetic nit both reviewers rated noise-floor) were left as-is — the
  rendered output is fine and `test_legend_explains_jig_vs_other` pins it.

**§4 — Strengths worth repeating (craft pass).** The `test_malformed_line_skipped`
case exercises both a syntactically-broken line *and* a valid-JSON-but-non-dict
line (`"12345"`), covering the `isinstance(entry, dict)` guard a lazier test
would miss; and `_parse_iso_utc` is a small, single-purpose helper that
normalizes tolerated formats (trailing `Z`, naive stamps) to aware UTC before
the `dt < cutoff` window comparison, so the windowing math can't misbehave on
a tz-naive value.

**§5 — Spec open-questions Q1/Q3 + the `--days` default.** Q1 (is
`UserPromptSubmit` rich enough for *implicit* routing?) was answered NO during
slice 041-01 — `PreToolUse`/`Skill` is the routable surface that carries
`skill_name`. Q3 (fold both refinement-todo entries?) is resolved YES: this
spec closes **both** "Skill telemetry granularity" and "Skill-routing
observability" together, since they share the one measurement mechanism (hook
+ histogram). The `--days` default is 30 (the spec left it unspecified); 30
days suits routing's higher event frequency, vs. `stale`'s 90-day doc-freshness
window. No retention/rotation logic was added (explicit spec non-goal).

**§6 — No new deferred decisions.** Nothing was added to
`docs/refinement-todo.md` or `docs/inbox.md`; on the contrary, two entries are
struck by this spec's close-out.
