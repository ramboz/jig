## Slice 096-04 — codex-orchestrator-visibility

**Goal:** Settle whether the Codex orchestrator can see and select among
installed skill descriptions — the one unverified premise the zero-config path
rests on for Codex — before any Codex selection code is written.

**Question:** Does the Codex orchestrating agent receive installed skills'
`name` + `description` in its context such that it can name the best candidate
for a category when asked, the way the Claude orchestrator can?

**Time-box:** 4 hours. If unresolved at the box, record `abandoned
(inconclusive)` and Codex stays config-only — that is a shipped, working state
(096-01), not a gap.

**Why a spike is justified here** (SPIDR's S is last-resort): P/I/D/R cannot
apply — there is no rule, path, interface, or data subset to split. The unknown
is a factual property of another vendor's runtime that no amount of
decomposition resolves, and it is cheap to probe and expensive to assume. It is
sequenced *after* the Claude path ships so it blocks nothing.

**DoR:**
- ✅ 096-03 DONE — the Claude selection path exists and defines exactly what the
  Codex equivalent would need to do.
- ✅ `codex-cli` installed locally (verified 0.133.0).
- ✅ Prior art to reuse: `scripts/codex_agent_discovery_probe.py` and
  `scripts/codex_role_capability_probe.py` build a temp marketplace and run
  Codex under an isolated `CODEX_HOME`.

**Acceptance Criteria:**

1. **A reproducible probe exists and has been run.** Following the existing
   Codex probe scripts' pattern (isolated `CODEX_HOME`, temp marketplace), a
   probe installs ≥2 distinguishable skills under a Codex user-scope skills dir
   and asks a Codex agent, non-interactively, to name the best candidate for a
   review category **without** naming the skills in the prompt.
2. **The result is recorded as evidence, not as a claim.** The probe's raw
   output is captured in `Findings:` above, with the exact command and Codex
   version. A `PASS`/`FAIL`/`UNAVAILABLE` outcome mirrors the existing probes'
   vocabulary.
3. **The spec's SECOND-HAND assumption is resolved or explicitly abandoned.**
   The spec's `## Assumptions` entry for ADR-0039 OQ6 is updated to VERIFIED or
   REFUTED with a pointer to this slice — no assumption is left dangling in the
   second-hand state.
4. **The outcome decides a written next step.** On PASS: a follow-up slice
   (096-06) is reserved for the Codex selection path. On FAIL/inconclusive:
   ADR-0039's Consequences "Codex is config-only" branch is confirmed in prose
   and the follow-up is explicitly *not* reserved.
