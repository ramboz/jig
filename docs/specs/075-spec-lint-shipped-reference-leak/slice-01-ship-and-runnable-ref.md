## Slice 075-01 — ship spec_lint and fix the runnable reference

**Goal:** Ship `scripts/spec_lint.py` in the release artifact and correct
the one actively-executed reference (migrate's runnable command) so a
consuming project can actually run the lint the workflow tells it to run.

**DoR:**
- ✅ Verified `spec_lint.py` is pure-stdlib (ships with no dependency
  drag) — see spec `## Overview` § Current state.
- ✅ Verified `RELEASE_INCLUDE_SCRIPT_FILES` in
  `scripts/install_contract.py` is the allowlist that re-includes
  individual `scripts/*.py` files into the release.

**Acceptance Criteria:**

1. **`spec_lint.py` is in the release artifact.** After a release build,
   `scripts/spec_lint.py` is present in the zip (and therefore resolvable
   at `${CLAUDE_PLUGIN_ROOT}/scripts/spec_lint.py` in an installed
   plugin). Achieved by adding `"scripts/spec_lint.py"` to
   `RELEASE_INCLUDE_SCRIPT_FILES`.
2. **A regression test fails without the inclusion.** A test in the
   build / install-contract suite asserts `scripts/spec_lint.py` is among
   the shipped script files — i.e. removing the tuple entry turns the
   test red.
3. **Migrate's runnable command resolves in a consuming project.** The
   `python3 scripts/spec_lint.py …` invocation in
   `skills/migrate/SKILL.md` is rewritten to the plugin-root form
   (`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/spec_lint.py" …`), matching
   how sibling skills invoke `workflow.py` / `review.py`. The
   `docs/specs/NNN-mM-slug/spec.md` argument (a path in the consuming
   project, relative to the project CWD) is unchanged.
