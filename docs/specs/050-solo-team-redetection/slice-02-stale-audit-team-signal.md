## Slice 050-02 — stale-audit-team-signal

**Goal:** Extend `workflow.py stale` to surface "team signal fires
but `docs/memory/people.md` is absent" as a freshness audit row.
Gives the user a way to discover the team-context drift outside the
`memory-sync` cadence — same shape as the existing `last_verified`
drift surfacing.

**DoR:**
- ✅ Slice 050-01 in production: team-signal re-check helper exists
  and is importable from `workflow.py`.
- ✅ `workflow.py stale` exists and emits a structured list of
  findings (slice 015-03).

**Acceptance Criteria:**

1. **`stale` includes team-signal finding.** When the project's
   team signal fires AND `docs/memory/people.md` is absent AND
   `.jig/no-people-md` is absent, `stale` emits a finding row:
   `team-signal: project has N contributors but people.md is
   absent. Run /jig:memory-sync to bootstrap.`
2. **Read-only.** The finding does not auto-bootstrap or mutate
   any files. Same posture as the rest of `stale`.
3. **Opt-out respected.** When `.jig/no-people-md` is present, the
   finding is suppressed. Parity with slice 050-01.
4. **Exit code unchanged when only this finding fires.** `stale`'s
   exit code semantics (0 = clean, non-zero = findings present)
   apply uniformly. A team-signal-only finding is a real finding;
   exits non-zero.
5. **Distinct finding category.** The row carries a `category:
   team-context` tag so downstream filters (CI, scripts) can
   differentiate it from `last_verified` drift rows.
6. **No double-walk.** The check reuses the team-signal helper's
   cached result if `stale` already ran the detection in the same
   invocation. Avoid redundant `git shortlog` calls.
7. **Tests.** Fixtures cover: team-signal-fires-no-people-md,
   team-signal-fires-people-md-exists (no finding), opt-out-marker
   (no finding), solo-project (no finding), monorepo-parent (no
   finding).
