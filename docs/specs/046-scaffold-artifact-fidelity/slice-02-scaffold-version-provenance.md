## Slice 046-02 - scaffold-version-provenance

**Goal:** Record the real source plugin version in scaffold metadata
instead of the stale hard-coded `0.1.0` value.

**DoR:**
- The canonical version source is agreed to be
  `.claude-plugin/plugin.json`.
- Tests can run scaffold generation from a checkout without requiring a
  packaged release zip.

**Acceptance Criteria:**

1. **Version is read from the manifest.** `scaffold.py` derives
   `jig_version` from `.claude-plugin/plugin.json` or an equivalent
   single source of truth, and no production code hard-codes the release
   version.
2. **Generated metadata matches source.** A temporary scaffold writes
   `scaffold.json.jig_version` equal to the source manifest version.
3. **Missing or malformed version fails clearly.** If the manifest is
   absent, malformed, or missing `version`, scaffold generation fails
   with an actionable error instead of silently writing an invented
   version.
4. **Version tests cover release drift.** A regression test would fail
   if the plugin manifest version changed without scaffold metadata
   following it.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Version derived from the manifest.** Removed the hard-coded
  `JIG_VERSION = "0.1.0"` constant. Added `_read_plugin_version(plugin)`
  (reads `plugin/.claude-plugin/plugin.json`) + a `PluginManifestError`
  (`RuntimeError` subclass, mirroring `AlreadyScaffoldedError` et al.).
  `scaffold()` reads the version **before** building `subs` — i.e. before
  the first file write (CLAUDE.md) — so a bad manifest fails fast and
  leaves no partial scaffold. The value flows through the shared
  `{{JIG_VERSION}}` placeholder into BOTH `scaffold.json.jig_version` and
  `brief.md`.
- **`main()` exit code = 1 (deliberate).** `PluginManifestError` is routed
  through `main()`'s generic `except Exception` (exit 1, "scaffold failed"),
  NOT a dedicated exit-3 branch like the sibling refusal errors. Rationale
  (endorsed by both review passes): a missing/malformed plugin manifest is
  an environment/packaging fault the user cannot resolve with `--force`,
  unlike the exit-3 "pre-existing recoverable state" refusals. A future
  reader should not "fix" this by adding a redundant exit-3 branch.
- **No architecture/ADR impact.** Adds an internal helper + exception and
  wires an existing field to its real source — no module boundary or public
  contract changed.
- **Non-blocking review items (deferred, not fixed — all outside the four ACs):**
  - _Robustness (compliance pass):_ the `if not version` guard rejects
    absent/empty/`null` but would accept a non-string truthy `version`
    (e.g. a JSON number `1.8`), which would then fail in `render()`'s
    `str.replace`. Out of AC scope — jig's own manifest version is always a
    string — but `not isinstance(version, str)` would close it. Promoted to
    `docs/refinement-todo.md` as a deferred hardening decision (it has a
    clear resolution trigger), per the 046-02 reconciliation review.
  - _Craft nits:_ (1) `PluginManifestError` / `_read_plugin_version` sit near
    the top of `scaffold.py` rather than with the other `RuntimeError`
    subclasses (~lines 168–191) — discoverability only; docstring
    cross-references make it defensible. (2) `test_scaffold.py` uses
    `hash(payload)` for a temp-dir name where `enumerate()` would read as
    more obviously deterministic. (3) `test_brief_mentions_source_version`
    asserts the literal `"Generated by jig {version} "` (trailing space),
    coupling it to `brief.md.template`'s exact phrasing.
- **Review outcome.** Compliance pass: PASS. Craft pass: PASS (no `[blocker]`
