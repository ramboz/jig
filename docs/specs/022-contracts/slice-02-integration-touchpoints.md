## Slice 022-02 — integration-touchpoints

**Goal:** Wire the contracts skill into the wider jig flow at three touchpoints so drift detection has structural support: (a) `vision-elicitation` (017) Appendix A asks about external surfaces at init, (b) `independent-review` (004) reviewer prompt gains a contract-surface check, (c) `migrate.py report` output flags detected contract surfaces. After this slice, the spec-author is nudged to declare surfaces at project birth + spec-time, and the reviewer catches missed updates at review-time.

**DoR:**
- ✅ Slice 022-01 (contracts SKILL.md active) is DONE.
- ✅ Spec 017 (vision-elicitation) is DONE and Appendix A is the documented integration point per ADR-0005.
- ✅ `review.py` builds the reviewer prompt from a template (slices 004-01 + 011-02) — extending it is a documented integration shape.
- ✅ `migrate.py report` has the section-based output format established by slice 008-01 — adding a section follows the existing convention.

**Acceptance Criteria:**

1. **Vision-elicitation Appendix A grows a contract-surfaces section.** A new question section in `skills/vision-elicitation/questions.md` asks "What external surfaces does this project expose?" with a multi-select / short-answer hand-off that lists the per-surface recommendations (or links into `skills/contracts/SKILL.md`'s table). The elicitation produces a written stanza in `docs/architecture.md` (or a new `docs/contracts.md`, TBD) declaring the surfaces and recommended artifacts. The dev's chosen artifacts are recorded for later reviewer-prompt use.
2. **Reviewer prompt template extends with a contract-surface check.** `skills/independent-review/review.py` (or its template) appends a check: "Does this slice touch a declared contract surface? If yes, is the corresponding artifact (OpenAPI / JSON Schema / etc.) updated in the same change-set?" The check is conditional — only fires when the project has declared at least one contract surface (i.e., the AC #1 stanza exists). When no surfaces are declared, no check is added (no noise).
3. **`migrate.py report` grows a "Contract surfaces detected" section.** Detects: (a) existing schema artifacts on disk (`openapi.yaml`, `*.schema.json`, `*.proto`, `schema.graphql`, `asyncapi.yaml`, etc.); (b) prose API contracts in `docs/architecture.md` (sections matching the pattern "endpoint table + request/response shapes" — heuristic, not strict); (c) env-contract-style patterns (`docs/env-contract.md` + `.env.example` + a sibling checker); (d) hand-typed boundary types in code that suggest a missing schema (`problem-details.ts`-style files matching RFC 7807 shape, hand-typed request/response types under `src/types/`). Each detected surface gets a one-line classification + recommendation per the contracts skill table. "No contract surfaces detected" is an explicit prose line when the section is empty.
4. **Nudge wording is consistent across all three touchpoints.** None of the integration points refuse, block, or fail — they recommend, surface, or check. Wording audit: spec-author can opt out of declaring surfaces (017 wizard skips on empty answer); reviewer flags a *suggestion* not a *blocker*; migrate report *recommends* not *requires*. This audit is a DoD step.
5. **Tests for each integration point.**
   (a) `test_vision_elicitation.py` (or equivalent surface-test file) gains tests pinning the new question section + the produced-stanza shape.
   (b) `test_review.py` gains tests for the conditional contract-surface check (fires when surfaces declared; absent when none).
   (c) `test_migrate.py` gains tests for the new "Contract surfaces detected" section covering each detection type (a)-(d) above with at least one fixture per type.
6. **End-to-end dogfood.** Run the full flow against aso-shallow-validator: `migrate.py report` should detect the env-contract + the prose API §5 + the hand-typed `problem-details.ts`. Capture the output in the deviation log to confirm the detection heuristics work on real material.
