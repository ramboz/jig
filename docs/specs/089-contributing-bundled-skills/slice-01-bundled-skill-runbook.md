## Slice 089-01 — bundled-skill contributor runbook

**Goal:** A first-time contributor can decide whether a capability belongs in
jig and, when it does, follow one complete author-register-validate flow without
reverse-engineering failed tests or internal memory notes.

**DoR:**
- ✅ GitHub issue 92 records a real first-time-contributor failure while adding
  a Tier-1 skill.
- ✅ The maintainer has decided bundled skills remain exceptional, jig stays
  lean, and justified workflow-native additions are still supported.
- ✅ `docs/conventions.md`, the tier registry, validator mirrors, routing eval,
  generated host-package flow, and CI-equivalent command have been verified in
  the current tree.

**Acceptance Criteria:**

1. **The guide frames bundled skills as an exception.** `CONTRIBUTING.md` says
   jig is intentionally lean and asks contributors to establish recurring user
   pain, fit with jig's workflow, and the absence of an existing owner before
   expanding the bundled set; otherwise it recommends a standalone skill.
2. **The authoring source is discoverable.** The new section links
   `docs/conventions.md`, names the canonical `skills/<name>/SKILL.md` source,
   reminds contributors that generated `hosts/` files are never hand-edited,
   and points at the existing globally-unique test-file naming rule.
3. **The registration surface is complete and current.** The runbook names the
   canonical `scaffold._TIER_SKILLS` table, the two stdlib-only validator
   mirrors, the two pinned inventory/upgrade test lists, the per-skill routing
   eval, and the product/count prose that must be reconciled.
4. **The final verification path is unambiguous.** The guide distinguishes
   `scripts/run_tests.py` for iteration from the final host-package regeneration
   plus `scripts/ci_check.py` gate.
5. **There is one live checklist.** The historical learning retains its
   provenance and rationale but points to the CONTRIBUTING section instead of
   carrying a second, already-stale checklist.

### Deviation log (after reconciliation)

1. **Planned shape:** No implementation deviation. The change adds the planned
   contributor-facing admission gate and author-register-validate runbook, then
   compresses the historical memory entry into rationale, provenance, and a
   pointer to that canonical source.
2. **Review findings:** The compliance and craft passes both returned `pass`
   without blockers or nits. The craft reviewer called out the direct lean
   admission framing, executable source-to-CI ordering, and single-source-of-
   truth treatment as strengths.
3. **Current-main integration:** Before reconciliation, the branch rebased onto
   `origin/main` through bug 007 / PR 93, which made the public skill install
   contract exact rather than subset-only. The documented canonical registry
   and validator-mirror steps already cover that guard, so no scope or wording
   change was required.
4. **Verification:** `scripts/spec_lint.py` reports no contradictions;
   `scripts/build_host_packages.py` produced no tracked drift; and
   `scripts/ci_check.py` passed against the integrated base with 3,455 tests
   (6 skipped), clean Pyright, clean routing, valid manifests, and synchronized
   host packages. An earlier sandboxed run passed all tests but could not read
   uv's external cache for Pyright; the approved unsandboxed rerun resolved that
   environment-only failure.
5. **Deferred work:** None. No product decision or follow-up was moved to
   `docs/refinement-todo.md`.
