## Slice 105-01 — quarantine state, attempts counter, and attest-only ingest

**Goal:** Give the bug-fix lifecycle a durable anti-thrash boundary: after N
failed fix attempts a bug record moves to a terminal `QUARANTINED` state with its
evidence frozen and its claim released, reopening only on new diagnostic
evidence — and servo can drive that same transition attest-only.

**DoR:**
- ✅ [ADR-0050](../../decisions/adr-0050-durable-failure-quarantine.md) is the governing record.
- ⬜ Confirm against live `skills/bug-fix/bug.py` the exact names the design
  assumes: `VALID_BUG_STATUSES`, `TERMINAL_NON_DONE_STATUSES`,
  `_BUG_TERMINAL_STATUSES`, `_record_text`, `_diagnosis_gaps`, and the
  `REVIEWED → DIAGNOSING` fix-failure re-entry point. Correct the ACs if any name
  or seam differs.
- ⬜ Decide (in AC) whether `attempts` increments on `ESCALATED` paths or only on
  the fix-failure re-entry (ADR-0050 open question).

**Acceptance Criteria:**

1. **`QUARANTINED` is a first-class terminal non-DONE state.** It appears in
   `VALID_BUG_STATUSES` and `TERMINAL_NON_DONE_STATUSES`; a quarantined record is
   segregated on the bug board like other terminals and clears its in-progress
   marker via `_BUG_TERMINAL_STATUSES`. Observable: `transition <record>
   QUARANTINED` succeeds and the board renders it in the terminal grouping.
2. **`attempts:` counter is persisted and incremented.** The bug record carries an
   `attempts:` frontmatter field (via `_record_text`); it increments by exactly 1
   at each fix-failure re-entry (`REVIEWED → DIAGNOSING`) and at the red-gate
   `→ FIXING`. Observable: the field's integer value rises across simulated
   failure cycles in a fixture.
3. **Auto-quarantine at threshold.** When `attempts ≥ N` (default 3, overridable),
   the next failing transition routes to `QUARANTINED`, **freezes** the
   `## Already tried` / `## Evidence` / `## Proof` sections (snapshots them), and
   releases the slice claim (spec 049 pickup-queue release). Observable: a fixture
   at `attempts = N` lands `QUARANTINED` with a frozen-evidence marker and no
   active claim.
4. **Release requires new diagnostic evidence.** A `QUARANTINED → DIAGNOSING`
   reopen is refused (non-zero exit, actionable message) unless the current
   `## Evidence` pointer differs from the frozen snapshot — reusing the
   `_diagnosis_gaps` evidence-pointer check. Observable: reopen with an unchanged
   pointer is refused; reopen after supplying a new pointer succeeds.
5. **Attest-only ingest from servo.** Given a servo quarantine artifact for a
   finding that maps to a jig bug (finding_id ↔ record), `bug-fix` can advance the
   bug to `QUARANTINED` recording *that* servo plateaued and *where* the evidence
   lives, **without** re-running or re-deriving any oracle score (ADR-0022:
   filesystem read + subprocess only, no servo import). Observable: the ingest
   path never invokes a scorer; the record cites the servo evidence pointer.
