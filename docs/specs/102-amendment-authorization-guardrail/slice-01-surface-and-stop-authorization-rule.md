## Slice 102-01 — surface-and-stop-authorization-rule

**Goal:** Add the surface-and-stop authorization rule to the two skill surfaces
the maintainer approved on issue #125, so an agent walking the ceremony meets
"an amendment to a closed record requires explicit owner approval" before it can
self-adjudicate a canon-artifact conflict, and the drift detector's contract
says it surfaces drift and hands off rather than resolving it.

**DoR:**
- ✅ Both edit sites read: `skills/spec-workflow/SKILL.md` closed-spec-drift
  reconciliation-checklist step (the ADR-0010 gate) and `skills/analyze/SKILL.md`
  output-contract + gotchas.
- ✅ Maintainer ruling recorded in `spec.md` (items 1 & 2 approved, item 3
  deferred).
- ✅ Host-package build/drift flow understood
  (`scripts/build_host_packages.py` regenerate + `--check` drift guard, wired
  into `scripts/ci_check.py`).

**Acceptance Criteria:**

1. **The closed-spec-drift checklist step in `skills/spec-workflow/SKILL.md`
   carries the authorization rule.** Within the reconciliation-checklist
   closed-spec-drift item (the one that links ADR-0010), the prose states, in
   substance: (a) amending a closed record requires **explicit owner approval**;
   (b) when two canon artifacts disagree, **surface the conflict and stop** —
   propose the amendment as text and write it only after the owner agrees; (c)
   approval of a **behaviour is a separate grant** from authority over the record
   — never write the resolution in the same turn as discovering the conflict,
   *including* when the underlying behaviour was already approved; (d) before
   asserting artifact X contradicts criterion Y, read **all** of Y's sibling
   criteria, because another may already satisfy X. Observable: the phrases
   appear inside the closed-spec-drift checklist item, above the `**Commit**`
   gate.

2. **The rule is scoped to closed *records*, not live prose.** The new text does
   not contradict ADR-0010's records-vs-live-prose split: it governs amendments
   to closed specs/slices (records), and does not tell agents that correcting
   live operational prose (SKILL.md / workflow.md / README) inline needs owner
   sign-off. (Live-prose inline correction is git-history-audited per ADR-0010
   and stays as-is.)

3. **The `analyze` output contract states findings are surfaced, never
   auto-resolved.** `skills/analyze/SKILL.md`'s output section (or an adjacent
   contract/gotcha it owns) states that the skill **reports drift and hands
   off** — when two canon artifacts disagree it does **not** pick a winner or
   write a resolution; it surfaces the finding for the owner to adjudicate.
   Observable: the "surfaced, never auto-resolved" / "reports drift and hands
   off, does not amend" posture is present in the output contract, reinforcing
   the existing non-destructive framing rather than merely restating "no file
   writes."

4. **Host packages carry the same text and the drift guard is green.** After
   regeneration, `python3 scripts/build_host_packages.py --check` exits 0 (the
   committed `hosts/` mirror matches the edited sources).
