# Plan: Slice 007-01 — land-prepare

## Approach

Same shape as `workflow.py` / `review.py` / `adr.py` / `tdd.py`:
deterministic Python 3 helper, SKILL.md drives judgment.

The helper performs four readiness checks and emits a markdown
report. It does NOT mutate git state. Mode-specific next-steps
are appended as **suggested commands** the user copy-pastes.

## `land.py` CLI surface

```bash
python3 land.py prepare <spec.md> <slice-fragment> [--mode {direct,pr}]
```

- `spec.md` — path to the spec file.
- `slice-fragment` — lenient substring match against `## Slice X — Y`
  headings (same shape as `workflow.py find_slice_section`).
- `--mode` — optional. Without it, no "Next steps" section is
  appended.

Exit codes:
- `0` — all four checks pass (slice is ready to land).
- `1` — at least one check fails (report still emits; user sees
  the blockers).
- `2` — user error (missing spec.md, ambiguous fragment, invalid
  `--mode`).

## Readiness checks

Four checks, each producing one line in the "Readiness" section:

1. **Status check.** Read the `**STATUS: X**` line under the slice
   heading. Pass iff `X == "DONE"`.
2. **Test check.** Shell out to
   `python3 ${CLAUDE_PLUGIN_ROOT}/skills/tdd-loop/tdd.py run <target>`.
   - `target` defaults to the cwd from which `land.py` runs.
   - Pass on exit 0. Fail on exit 1 (red tests). **Warn** (yellow,
     not blocker) on exit 2 (no runner / missing binary). Some
     slices are doc-only and have no executable tests.
3. **Deviation log check.** Look for a `### Deviation log` (or
   case-variant) subsection between this slice's heading and the
   next `## Slice` (or EOF). Pass iff present.
4. **DoD checkbox check.** Within the slice section, find all
   `- [ ]` and `- [x]` lines. Pass iff there are no `- [ ]`
   unchecked boxes AND at least one `- [x]` checked box.

## Report format

```markdown
# Landing readiness — slice <full-label>

## Readiness checks

- [x] Status: DONE
- [x] Tests: green (3 passed via pytest)
- [x] Deviation log: present
- [x] DoD: 8/8 boxes ticked

## Next steps (mode: direct)

Run these from the project root (NOT inside this worktree):

    git checkout main
    git merge claude/eager-zhukovsky-34ebb0 --ff-only
    git push origin main
    git worktree remove .claude/worktrees/eager-zhukovsky-34ebb0
```

On any failure, the readiness item shows `- [ ]` with a short
"because:" suffix, and "Next steps" is preceded by a "**Blockers:**"
section enumerating what needs fixing first.

## PR body generation (mode=pr)

Write to `/tmp/jig-slice-<NNN-NN>-pr-body.md`. Content:

```markdown
# <slice-label>

## Context

<first paragraph of slice section, up to the **Goal:** line>

## Acceptance criteria

- AC 1 — <text from numbered AC list, first line only>
- AC 2 — ...
- ...

## Deviation log

<first 500 chars of the Deviation log subsection, ellipsized>

## Test plan

- [x] All ACs pass (NN tests green)
- [x] Reviewed by `reviewer` subagent
- [x] Reconciliation review pass

🤖 Generated by [jig slice-land](https://github.com/example/jig)
```

## Branch / worktree detection

For `--mode direct`'s git commands, the helper needs the current
branch and worktree path. Use:
- Branch: `git rev-parse --abbrev-ref HEAD`
- Worktree path: `os.getcwd()` (canonical path)

Both via `subprocess.run` with `capture_output=True`. Failure to
detect either degrades gracefully — the commands print with
`<BRANCH>` / `<WORKTREE>` placeholders instead.

## Coupling note (fourth-and-counting moment)

`land.py` needs:
- Lenient slice-fragment matching (workflow.py / review.py / adr.py
  precedent — three callers using different regexes).
- Spec.md section parsing (workflow.py / review.py / adr.py for
  status lines + slice bounds).

Per ADR-0002 + slice 004-01 / 005-01 / 006-01 precedent: **duplicate**.
The regex shapes (slice fragment is `## Slice X` for workflow/review/
adr/land; status line is `**STATUS: X**`; deviation log is `###
Deviation log`) all differ from what a shared `_common/parsing.py`
would have to abstract. Continuing to defer is the right call.

If this slice produces a *fifth* duplicated pattern (e.g. a "find
the AC list" regex used by both `land.py` and a future `adr-helper`
update), that's the trigger to reconsider.

## Test strategy

`PrepareReportTests`:
- Fixture: minimal spec.md with one slice; STATUS=DONE; deviation
  log section; all DoD `- [x]`; small unittest fixture available
  for the test check. → exit 0, four green readiness items.
- Fixture: STATUS=REVIEWED instead of DONE. → exit 1, status check
  red, Blockers section names "status must be DONE".
- Fixture: STATUS=DONE but no Deviation log subsection. → exit 1.
- Fixture: STATUS=DONE, deviation log present, but 2 of 8 DoD boxes
  unticked. → exit 1, DoD line reports "6/8 boxes ticked".

`ModeTests`:
- `--mode direct` → "Next steps" section has 4 git commands;
  branch name appears in the merge command.
- `--mode pr` → "Next steps" section has 2 lines (push + gh pr
  create); PR body file path appears.
- No `--mode` flag → no "Next steps" section in the report.
- `--mode foo` → exit 2 with stderr "invalid --mode".

`PrBodyTests`:
- `--mode pr` writes a markdown file at the expected path.
- File contains: slice label, Context excerpt, AC items (parsed
  from the spec), deviation-log excerpt.
- AC items are numbered and one-line each.
- Deviation-log excerpt is bounded at 500 chars.

`ErrorTests`:
- Missing spec.md → exit 2 with stderr.
- Ambiguous fragment (matches 2+ headings) → exit 2 with stderr.
- No matching fragment → exit 2 with stderr.

`SafetyTests`:
- `land.py` imports do not include `subprocess` calls to `git`
  or `gh` in any code path EXCEPT the test-runner shell-out and
  the branch-detection helpers. Static-analysis style — grep the
  source for forbidden patterns.

`SkillSurfaceTests`:
- Frontmatter has no `disable-model-invocation`; `user-invocable: true`.
- Description contains all six trigger phrases.
- Body references `land.py prepare` and the `--mode` flag.

## Risks

- **Test-runner side effects in the readiness check.** Calling
  `tdd.py run` runs the entire test suite. For a large project
  this could be slow. Mitigation: AC #1 doesn't require running
  the suite from cwd-root — it runs against the current dir. The
  user / SKILL.md can pass `target=skills/<changed-skill>` for
  focus. Documented in SKILL.md gotchas.
- **`git worktree remove` is destructive.** The "Next steps" section
  SUGGESTS it but doesn't run it. Slice 007-02 will need an
  explicit confirm-before-destroy flow.
- **Branch / worktree autodetection on non-worktree checkouts.**
  If the user runs `land.py prepare` from a regular branch (not a
  worktree), `git worktree remove` becomes inappropriate. Mitigation:
  detect via `git rev-parse --git-common-dir` differing from
  `--git-dir` (worktrees have a separate gitdir under `.git/worktrees`).
  Document the heuristic in SKILL.md gotchas.
