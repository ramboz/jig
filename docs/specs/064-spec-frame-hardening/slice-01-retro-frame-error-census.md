## Slice 01 — retro-frame-error-census

**Goal:** Determine empirically whether bad-frame errors recur in jig's own
spec/ADR history, and whether grounding + adversarial frame-critique would
plausibly have caught them — producing a documented **go/no-go** that gates the
rest of spec 064.

**DoR:**
- ✅ [ADR-0020](../../decisions/adr-0020-spec-frame-hardening.md) filed (Proposed).
- ✅ OQ1 (retro depth: full census vs stratified sample) resolved with the human.

**Question:** Do bad-frame errors (wrong-premise specs/ADRs that propagated and
were caught late, or shipped) occur in jig at a rate that justifies the
frame-hardening machinery — and would grounding/frame-critique plausibly have
caught them early?

**Time-box:** 1 day.

**Acceptance Criteria:**

1. **A documented census exists** (in this slice's Findings, or a linked
   `docs/specs/064-spec-frame-hardening/retro.md`) listing each
   spec/ADR examined and classifying it: *no frame issue* / *frame issue caught
   late* / *frame issue shipped*. Scope per OQ1.
2. **Each identified frame issue is tagged** with whether (a) a probe-first
   grounding requirement and/or (b) an adversarial frame-critique pass would
   *plausibly* have caught it early — with a one-line rationale, not a bare
   yes/no.
3. **A go/no-go recommendation is recorded** in the Outcome block, tied
   explicitly to ADR-0020's kill criterion ("no catchable frame errors → shelve
   the ADR").

**DoD:**
- [ ] All ACs pass; census artifact on disk.
- [ ] Findings + Outcome blocks filled.
- [ ] Reviewed by `reviewer` subagent (read-only; judges the census reasoning,
      not code). Reviewer prompt built by `review.py`.
- [ ] Implementation review passed.
- [ ] Deviation log produced under this slice heading.
- [ ] Reconciliation review passed.
- [ ] `docs/refinement-todo.md` updated if any decisions were deferred.

**Findings:** _Filled during IN_PROGRESS — the census + per-issue catchability
tags + any surprises (e.g. frame errors of a kind neither mechanism would catch)._

**Outcome:** _Set at DONE. One of: `spec 064-02 unblocked (go)` /
`ADR-0020 shelved (no-go — premise §A1 false)`; with the supporting count._

### Close-out (post-DONE)

- [ ] `docs/specs/README.md` regenerated by `workflow.py status-board`.
- [ ] If **no-go**: ADR-0020 marked accordingly; spec 064 slices 02–04 set
      DEFERRED with this spike as the resolution trigger; CLAUDE.md not touched.
- [ ] If **go**: 064-02 promoted to READY_FOR_IMPLEMENTATION.

**Anti-horizontal-phasing check:** The observable value is a recorded,
evidence-backed go/no-go decision that prevents (or green-lights) downstream
investment — decision-useful on its own, regardless of what follows.
