## Slice 064-04 — derived-trigger

**Goal:** Make `frame_review` set itself — the spec-author / `clarify` step
derives the flag mechanically from the grounding output (064-02), so the
adversarial pass auto-triggers exactly when there is an unverified frame to
attack and stays silent otherwise, with no per-author judgment call.

> **Carried-forward from 064-03 arch review (2026-06-07):** this slice must also
> **close the spawner/gate dispatch gap**. 064-03 added the READY_FOR_REVIEW
> gate, but `session-plan` (`workflow.py session-plan`, 057-01) does **not** read
> `frame_review` or emit a pre-implementation frame-critique phase — so a flagged
> spec would hit a gate it was never dispatched to satisfy (the dead-loop ADR-0020
> warns against). When this slice derives the flag, it must also surface the
> frame-critique pass on the dispatch surface the orchestrator follows
> (`session-plan` and/or the `clarify`/spec-author guidance) so the pass actually
> fires. Add an AC + test for it.

**DoR:**

- ✅ OQ3 resolved (2026-06-07): **ADRs always-on** (`frame_review: true`
      unconditional — set mechanically for any ADR); **specs** get the derived

      ≥1 unverified load-bearing assumption, OR new external dependency / asserted

**Acceptance Criteria:**

1. **A documented, mechanical trigger rule** is implemented in the author/
   `clarify` path: set `frame_review: true` when grounding leaves ≥1 unverified
   load-bearing assumption, OR the artifact is an ADR / will spawn one, OR it
   introduces a new external dependency / asserts external library/API/version/
   perf behavior. Otherwise leave default-off.
2. **The trigger fires on a positive fixture and stays off on a negative one** —
   a spec with an unverified assumption gets flagged; an inline-mirror/refactor
   spec with none does not. Observable via the flag value the step emits.
3. **It's a derivation, not a prompt for a human decision** — the contributor is
   not asked "is frame-review needed?"; the surfaced assumptions decide. Provable
   by reading the contract/skill prose + the helper behavior.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Two parts shipped:** (A) the derived trigger — `derive_frame_review` +
  `workflow.py frame-review-needed` CLI (mirrors `arch-review-needed`'s wiring
  but DERIVES rather than reads) — and (B) the dispatch-gap closure carried
  forward from 064-03's arch review — `session_plan` now emits a conditional
  `frame-critique` phase **first** (pre-implementation) iff the slice declares
  `frame_review: true`, so a flagged spec is dispatched, not just gated.
- **Author contract (AC3):** spec-workflow `SKILL.md` "Creating a new spec" step
  frames the flag as a derivation — the surfaced `## Assumptions` decide; the
  contributor is not asked "is frame-review needed?". ADRs always-on (OQ3).
- **Meta-frame-error caught pre-review by orchestrator probing (the spec
  dogfooding itself):** the first implementation read the **slice section's**
  `## Assumptions`, but 064-02 deliberately places `## Assumptions` at the
  **spec.md** level (the slice template only *points* at it). Reading the slice
  would make the trigger a permanent dead loop on every real spec — the exact
  failure 064-04 exists to prevent. Fixed: `derive_frame_review` reads the
  **spec-level** `## Assumptions` as the primary signal, with a slice-level
  defensive fallback; added `test_true_for_spec_level_assumption` (realistic
  fixture: slice has no assumptions, spec does).
- **Craft-review [blocker] → fixed:** `_assumptions_are_real` used a *first-token*
  placeholder check (split on `[\s—:.-]`), so a genuine assumption beginning with
  a placeholder word ("None of the dates are tz-aware", "TBD-style configs…") was
  misclassified as a placeholder → trigger silently suppressed (same false-negative
  failure mode). Fixed with a **dual rule**: (a) a fully emphasis-wrapped line
  (`_..._`/`*...*`) is the template stub → placeholder; (b) a **whole-line** bare
  placeholder token (trailing punctuation tolerated) → placeholder; anything else
  is a real assumption. Added `test_true_for_assumption_starting_with_placeholder_word`;
  existing negatives (none / bullet-none / italic stubs / empty) still assert False.
  An independent focused craft re-review confirmed the fix (no new issue; the only
  conservative edge — a fully-italicized real assumption — is acceptable).
- **`frame-review-needed` nit (considered, kept):** requires a `slice` positional
  even for an ADR target (the ADR path short-circuits before slice lookup); kept
  for parity with `arch-review-needed`, docstring notes the short-circuit.
- **Scope:** `adr.py` untouched (the ADR-side accept-gate is 064-05);
  `conventions.md` untouched; the deriver is pure (no frontmatter mutation,
  stdout/return only — like `session_plan`). No stray files.
- **Spec 064 is NOT closed by this slice** — [064-05](slice-05-adr-accept-gate.md)
  (ADR-side accept-gate) remains DRAFT (not deferred), so the CLAUDE.md
  Active-specs compression (025-01) is deferred to 064-05's close-out, not done here.
