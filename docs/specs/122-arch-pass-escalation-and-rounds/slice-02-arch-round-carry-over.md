## Slice 122-02 — arch-round-carry-over

**Goal:** a re-run arch pass reads the slice's previous arch record from disk,
after reviewing the current deliverables, and gives each earlier finding a
status, so rounds converge instead of starting over.

**Decision:** spec 122 D3 — arch pass only, on-disk record only; the ban on
conversation context and the implementer's reasoning stays.

**DoR:**
- ✅ The previous verdict for `(slice, arch)` lives at
  `<spec-dir>/reviews/slice-NN-arch.md` (`review_evidence.evidence_path`,
  ADR-0014 §1), overwritten in place each round (§4).
- ✅ Every reviewer prompt opens with `_PREAMBLE` and carries `_PROHIBITIONS`
  (`skills/independent-review/review.py`); `agents/reviewer.md` repeats both.

**Assumptions:** None beyond spec A3.

**Acceptance Criteria:**

1. **A previous record turns on the carry-over.** When
   `reviews/slice-NN-arch.md` exists for the slice, the `review.py arch-review`
   prompt:
   - opens without "You are seeing this work for the first time", saying
     instead that earlier rounds exist only as files;
   - keeps the ban on prior conversation and the implementer's reasoning, with
     the previous arch record named as the one exception;
   - has a "Previous round" section, after the "Evaluate" section, that names
     the record's path and tells the reviewer to read it only after reviewing
     the current deliverables, to give each earlier finding a status (resolved,
     still open, or withdrawn with a reason), and to continue the round count
     from the record's last `REASONING` line
     (`round: N · open: <ids> · searched: <anchors>`; with no such line, the
     earlier round was round 1).
2. **No record, no change.** With no previous arch record, the arch prompt
   keeps today's preamble and prohibitions and has no "Previous round" section.
3. **Every arch round writes the line.** In both cases the arch prompt asks the
   reviewer to end `REASONING` with
   `round: N · open: <ids or none> · searched: <anchors or none>`.
4. **Other passes are untouched.** The implementation, pr-review, bug-review,
   code-health, reconciliation, frame-critique and design-review prompts are
   byte-identical with and without an arch record on disk.
5. **The agent definition agrees.** `agents/reviewer.md` states the same
   exception (a previous review record the prompt points to, read after the
   current deliverables, as evidence on disk), and the generated host packages
   are rebuilt so `build_host_packages.py --check` passes.

**Edge cases to cover explicitly:**
- The slice fragment resolves to an embedded `## Slice` section (no slice file,
  so no evidence path): the prompt builds as if no record exists.
- A record exists for another pass (e.g. `slice-NN-craft.md`) but not for arch:
  no carry-over.

### Deviation log (after reconciliation)

The original slice is preserved above. Implementation notes:

1. **`docs/conventions.md` changed (owner-approved, 2026-11-17).** The
   round-1 arch pass blocked on it: the convention required "You are seeing
   this work for the first time" in every reviewer prompt, which a round-2 arch
   prompt leaves out by design (AC1). The slice did not list the file. With the
   owner's explicit approval (jig's CLAUDE.md requires it for this file), the
   rule now names the one exception — an arch pass whose prompt names the
   slice's previous arch record — and keeps the ban on prior conversation and
   the implementer's reasoning.
2. **The slice reviewed itself.** The round-1 arch verdict (`needs-changes`)
   was recorded, so the round-2 arch prompt came from this slice's own code:
   it named `reviews/slice-02-arch.md`, and the reviewer gave both open
   findings a status (resolved), withdrew one nit with a reason, and ended
   with `round: 2 · open: none · searched: …`. The recorded arch body is that
   round-2 envelope.
3. **Additions beyond the ACs.** The round-line block defines an id ("a short
   stable name for a finding — what is wrong and the path it anchors to, no
   line number") so a later round can match it (spec A3 leaves the format to
   the skill; this is jig's minimum). `agents/reviewer.md`'s opening line also
   gained "(unless your prompt names an earlier review record on disk)", beyond
   AC5's prohibitions-only exception, so the agent's first sentence does not
   contradict its own carve-out. The record path is printed as given (relative
   or absolute, following the spec path passed to `review.py`).
4. **Changes after the compliance and craft verdicts** (both `pass`; their
   recorded bodies predate these): the round-line wording no longer says the
   record is "named below" (it renders above); the AC1 test now asserts the
   replacement prohibition bullet itself, not a phrase the "Previous round"
   block also contains; the AC4 test asserts each of the six other prompts
   builds (exit 0) before comparing bytes; a redundant `sys.path`-leaking test
   was removed; and both SKILL.md files now say to record the reviewer's
   envelope as returned, since a summary drops the `round:` line. Only the
   round-2 arch pass saw these edits; the compliance and craft verdicts were
   recorded afterwards (so their `reviewed_at` postdates the edits) over
   bodies that predate them. The craft record shows `applied_skill: unknown`
   because the candidate step was re-run after its prompt was built, which
   reset the recorded pick; the prompt itself applied `pr-review`.
5. **bug-review left out of the AC4 test on purpose.** Its builder takes a bug
   record, not a slice, so a slice's arch record cannot reach it; the test says
   so in a comment.
6. **Guard tests that passed before the feature.** Four were green before the
   implementation because they pin unchanged behaviour:
   `test_no_record_keeps_todays_preamble_and_prohibitions`,
   `test_another_pass_record_does_not_turn_it_on`,
   `test_embedded_slice_builds_as_round_one` and
   `test_other_passes_unchanged_by_an_arch_record`. They fail if the carry-over
   leaks into a first round, another pass's record, an embedded slice, or
   another pass's prompt. The three tests that assert the new behaviour were
   red before the implementation.
7. **Verification.** Full suite (`scripts/run_tests.py`) after the
   reconciliation edits: 5,219 tests green (8 skipped), pyright gate clean.
   Host packages rebuilt with `build_host_packages.py --check` clean; ruff
   floor clean.
