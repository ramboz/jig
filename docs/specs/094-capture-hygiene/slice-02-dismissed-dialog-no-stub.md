## Slice 094-02 — a dismissed dialog produces no stub

**Goal:** When an `AskUserQuestion` dialog yields no answer, capture records
nothing — instead of falling back to saving the agent's own question as though
the owner had said it.

**DoR:**
- ✅ `decision_scratch.extract_askuserquestion_answer:247-259` falls back to
  `tool_input` when the response carries no text, and documents the fallback as
  deliberate ("Over-permissive on purpose") — read on 2026-07-16, upstream `main`.
- ✅ `test_decision_scratch.py:151` (`test_falls_back_to_input_when_response_empty`)
  pins that behaviour, so the reversal is witnessed by an existing test changing.
- ✅ Field evidence exists and is counted:
  [#108](https://github.com/ramboz/jig/issues/108) records 17 of 27 unique
  scratch entries as the agent's own dialog, the reported one quoting a dialog
  the owner explicitly dismissed.

**The premise being reversed (stated, not assumed):** the fallback's own comment
argues *"the surfacing is owner-gated, so a noisy stub is cheap; a missed one is
not."* The asymmetry is real but points the other way once measured. The stub is
not merely noisy — it is **wrong about who spoke**, it is durable (083-07
re-surfaces un-recorded stubs until something covering them is written), and at
17-of-27 it is the *majority* of what the log contains. A dismissed dialog is
also not a missed decision: dismissal is the owner declining to decide, so there
is nothing to miss. The cost of the noise lands on agent attention every Stop,
which specs 055/057 price as the dominant cost. Cheap × 17 × every session is not
cheap.

**Acceptance Criteria:**

1. **No answer → no text.** `extract_askuserquestion_answer` returns `""` when the
   tool response carries no answer text, whatever `tool_input` holds. The question
   is never substituted for the answer.
2. **No text → no stub.** The `PostToolUse(AskUserQuestion)` hook path writes
   nothing to the scratch log for a dismissed dialog (via `append_stub`'s existing
   blank-quote guard — no new suppression mechanism).
3. **Answered dialogs are unaffected.** A response carrying the owner's selection
   still yields that selection's text, still stubs, still `source:
   "askuserquestion"` / `who: "user"`, at Tier 1.
4. **The reversed premise is recorded where the old one lived.** The
   "over-permissive on purpose" docstring is replaced by the reasoning above, so
   the next reader sees why the asymmetry flipped rather than re-deriving it.

**Anti-horizontal-phasing check:** After this slice, dismissing a dialog leaves
no trace — the owner stops being quoted saying things the agent asked, and the
largest single category in #108's count (17 of 27) disappears.

**Scope boundary (deliberate):** this slice deletes the fallback; it does not
narrow *where* in the response answer text is looked for (e.g. keying on
`answers`). The dismissed-response shape is not probeable from this repo, so
pattern-matching it would be an unverified assumption (ADR-0020); removing the
fallback fixes the evidenced defect without depending on that shape.
