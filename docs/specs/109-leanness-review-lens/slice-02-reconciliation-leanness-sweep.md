## Slice 109-02 — reconciliation-leanness-sweep

**Goal:** The reconciliation review retrospectively sweeps for **over-build** —
code or abstraction added beyond what the spec's acceptance criteria need — so
the leanness lens closes the loop at reconciliation as well as at arch review.

**DoR:**
- ✅ 109-01 done (establishes the shared leanness wording the reconciliation
  sweep reuses for consistency).
- ✅ Insertion points confirmed: `build_reconciliation_prompt`
  ([review.py:1463](../../../skills/independent-review/review.py)) and the
  Reconciliation checklist in `skills/spec-workflow/SKILL.md`.

**Acceptance Criteria:**

1. **The reconciliation prompt sweeps for over-build.** `build_reconciliation_prompt`'s
   emitted prompt gains a directive to check whether the implementation added
   abstraction, indirection, or generality beyond what the ACs required, and to
   report any such over-build as a reconciliation finding — consistent in
   wording with the 109-01 arch-pass lens.
2. **The reconciliation checklist names it.** `skills/spec-workflow/SKILL.md`'s
   `## Reconciliation checklist` gains a **leanness sweep** item (a
   non-duplicating addition alongside the existing Architecture-impact and
   Load-bearing-decision items) directing the reconciler to confirm nothing was
   over-built relative to the spec's needs.
3. **Advisory, not a new gate.** The sweep produces ordinary reconciliation
   findings within the existing verdict envelope; it introduces no new blocking
   condition, evidence file, or frontmatter flag beyond the reconciliation pass
   that already gates `RECONCILED`.
4. **Anchored to spec needs.** The wording ties "over-build" to the spec's ACs
   (added-beyond-need), so it cannot be read as pressure to remove behavior the
   spec required.
