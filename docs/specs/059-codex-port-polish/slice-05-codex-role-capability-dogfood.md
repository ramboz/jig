### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- Re-checked the current official Codex manual during implementation. Codex
  documents custom agents as TOML files under project-local `.codex/agents/`
  or user-local `~/.codex/agents/`, with `sandbox_mode` as an optional custom
  agent config key; subagents are spawned only when explicitly requested and
  inspected through `/agent`.
- Added `scripts/codex_role_capability_probe.py`, a repeatable diagnostic that
  installs the generated `jig-implementer`, `jig-reviewer`, and `jig-architect`
  TOML files into a scratch Codex project, validates the generated role
  metadata, and probes deterministic local Codex CLI surfaces.
- The stable role mapping is now documented and tested:
  `jig-implementer` uses `sandbox_mode = "workspace-write"` while
  `jig-reviewer` and `jig-architect` use `sandbox_mode = "read-only"`.
- Local dogfood on 2026-06-05 with `codex-cli 0.133.0` observed that
  `codex sandbox macos --permissions-profile :read-only` blocks a scratch
  write with `PermissionError: [Errno 1] Operation not permitted`, while
  `--permissions-profile :workspace` allows the same write inside the scratch
  project. The same probe reports nested sandbox setup failures as
  `UNAVAILABLE` rather than false failures when run inside an already-sandboxed
  Codex session.
- Compliance and craft reviews found that the original denial matcher was too
  broad: output containing the word `sandbox` could be misclassified as a
  read-only enforcement pass. The matcher now treats unsupported sandbox
  command output as `UNAVAILABLE`, and
  `test_unsupported_sandbox_command_is_unavailable_not_denial` covers the
  regression.
- `codex debug prompt-input` exposes generated jig skills but did not expose
  project custom-agent entries. The docs therefore record named role-agent
  invocation as an interactive dogfood path (`/agent` for inspection) and keep
  noninteractive review automation on generated `review.py` prompts plus a
  read-only runner.
- Added `docs/codex-role-capability.md` and README / CONTRIBUTING /
  architecture pointers for the role probe, interactive dogfood prompt, and
  post-implementation fallback.
- Focused checks passed:

  `python3 -m unittest scripts.test_codex_install_smoke scripts.test_codex_role_capability_probe scripts.test_codex_plugin_packaging`,
  `python3 scripts/codex_role_capability_probe.py --skip-live-codex`,
