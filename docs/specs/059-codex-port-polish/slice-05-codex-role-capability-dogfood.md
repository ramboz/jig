## Slice 059-05 - codex-role-capability-dogfood

**Goal:** Exercise jig's Codex role agents and record the precise
capability semantics users can rely on.

**DoR:**
- Codex TOML custom-agent rendering from 033-07 is DONE.
- Local Codex CLI version and custom-agent behavior have been checked.
- The test plan distinguishes enforceable Codex behavior from prose-only
  role intent.

**Acceptance Criteria:**

1. **All three roles are exercised.** `jig-implementer`,
   `jig-reviewer`, and `jig-architect` are invoked in a real Codex
   session or closest supported local diagnostic flow.
2. **Write/read behavior is observed.** The dogfood records whether each
   role can write, whether read-only sandboxing is enforced, and what
   failure mode users see when enforcement blocks an action.
3. **Post-implementation flow is tested in Codex.** The review workflow
   is run far enough to prove Codex can use the rendered role agents or
   to document the exact fallback required.
4. **Docs reflect observed semantics.** README, architecture docs, or
   generated agent notes are updated if the observed behavior differs
   from the current closest-supported `sandbox_mode` assumption.
5. **Regression guard exists where practical.** Stable parts of the
   dogfood are encoded as tests or a repeatable script; inherently
   interactive parts are documented with exact commands and expected
   observations.
