### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- Re-checked the current official Codex manual on 2026-06-04. The
  documented hook contract says plugin-bundled hooks use the same trust
  review flow as other non-managed hooks: Codex skips changed or untrusted
  command hooks until the user reviews and trusts them through `/hooks`.
- README's Codex plugin install flow now places the `/hooks` review/trust
  step immediately after `codex plugin add jig@jig`, before describing the
  rest of the package contents. The wording says skills can load after
  install, but jig hook gates do not run until trust is recorded against the
  current hook definition hash.
- `.codex-plugin/plugin.json` now carries the same caveat in its
  Codex-facing long description so plugin detail/onboarding surfaces do not
  imply hooks execute automatically after install.
- `docs/architecture.md` records the same runtime caveat in the Codex
  plugin packaging section.
- Added `scripts/test_codex_plugin_packaging.py` coverage for the README
  placement, generated plugin README copy, Codex manifest description,
  architecture note, and separation from the Claude plugin install docs.
