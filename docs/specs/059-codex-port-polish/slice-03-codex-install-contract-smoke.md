## Slice 059-03 - codex-install-contract-smoke

**Goal:** Add Codex-specific install smoke coverage for the generated
plugin package and explicit custom-agent install helper.

**DoR:**
- Slice 059-02 has documented the hook trust step that the smoke test
  needs to account for.
- Spec 047 has been checked so this slice does not duplicate generic
  release/scaffold contract validation.
- Local Codex CLI availability and sandbox constraints have been
  assessed.

**Acceptance Criteria:**

1. **Smoke builds the generated Codex package.** The validator builds
   `dist/codex-plugin/plugins/jig` or an isolated equivalent from the
   shared source tree before probing it.
2. **Smoke probes Codex plugin surfaces when available.** When a usable
   Codex CLI exists, the validator exercises marketplace add, plugin add
   or the closest non-mutating equivalent, skill visibility, hook config
   visibility, and hook trust state.
3. **Smoke verifies role-agent install.** The same run executes
   `--install-codex-agents` against an isolated agents directory and
   parses the resulting `jig-*.toml` files.
4. **Unavailable Codex is reported distinctly.** If the Codex CLI or
   live plugin surface is unavailable in CI, the validator emits a clear
   skipped/unavailable result rather than passing silently.
5. **Docs describe how to run it locally.** Release or contributor docs
   name the Codex smoke command and any environment variables it uses to
   isolate `CODEX_HOME` / plugin state.
