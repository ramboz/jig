## Slice 059-03 - codex-install-contract-smoke

**Goal:** Add Codex-specific install smoke coverage for the generated
plugin package and explicit custom-agent install helper.

**DoR:**
- Slice 059-02 has documented the hook trust step that the smoke test
  needs to account for.
- Spec 047 has been checked so this slice does not duplicate generic
  release/scaffold contract validation.
- Local Codex CLI availability and sandbox constraints have been
  assessed.

**Acceptance Criteria:**

1. **Smoke builds the generated Codex package.** The validator builds
   `dist/codex-plugin/plugins/jig` or an isolated equivalent from the
   shared source tree before probing it.
2. **Smoke probes Codex plugin surfaces when available.** When a usable
   Codex CLI exists, the validator exercises marketplace add, plugin add
   or the closest non-mutating equivalent, skill visibility, hook config
   visibility, and hook trust state.
3. **Smoke verifies role-agent install.** The same run executes
   `--install-codex-agents` against an isolated agents directory and
   parses the resulting `jig-*.toml` files.
4. **Unavailable Codex is reported distinctly.** If the Codex CLI or
   live plugin surface is unavailable in CI, the validator emits a clear
   skipped/unavailable result rather than passing silently.
5. **Docs describe how to run it locally.** Release or contributor docs
   name the Codex smoke command and any environment variables it uses to
   isolate `CODEX_HOME` / plugin state.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- Added `scripts/codex_install_smoke.py`, a Codex-specific smoke command
  that builds an isolated `codex-plugin/plugins/jig` package from the
  shared source tree, validates the generated Codex manifest, rendered
  skills, hook config/scripts, and local marketplace descriptor, then runs
  the generated `--install-codex-agents` helper against an isolated agents
  directory and parses the resulting `jig-*.toml` files.
- The live probe uses an isolated child `CODEX_HOME` by default and
  exercises the current local Codex CLI (`0.133.0` on 2026-06-04) through
  `codex plugin marketplace add`, `codex plugin list`, `codex plugin add`,
  `codex debug prompt-input`, `codex features list`, and `codex --help`.
  Missing Codex or missing live-only subcommands report `UNAVAILABLE`
  instead of counting as a silent pass; `--require-live-codex` turns those
  unavailable rows into exit code `2`.
- Live skill visibility intentionally checks representative model-visible
  jig skills through `codex debug prompt-input`; full 15-skill package
  presence remains a static generated-package assertion. Current Codex
  prompt rendering is relevance/budget filtered and does not dump every
  installed skill at once, so requiring all 15 in the live prompt would
  false-fail a valid install.
- Hook trust state is probed through the current non-interactive surface:
  the CLI help exposes `--dangerously-bypass-hook-trust`, `features list`
  exposes `hooks` / `plugin_hooks`, and the isolated config carries no
  persisted hook-trust metadata after plugin install, so the smoke reports
  jig hooks as pending `/hooks` review.
- Implementation review caught and resolved two edge cases: strict live mode
  now preserves missing Codex as an `UNAVAILABLE` row with exit code `2`
  instead of converting it to `FAIL`, and hook feature detection now checks
  `hooks` / `plugin_hooks` as distinct feature tokens so `plugin_hooks` alone
  cannot satisfy the standalone `hooks` check.
- The craft pass also flagged timeout reporting as a structured-output nit;
  `_run_command` now converts `subprocess.TimeoutExpired` into a named
  `CompletedProcess` result with return code `124`, keeping smoke output in
  the normal `PASS` / `FAIL` / `UNAVAILABLE` row format.
- README and CONTRIBUTING now document `python3 scripts/codex_install_smoke.py`,
  the isolated `CODEX_HOME` behavior, `JIG_CODEX_SMOKE_CODEX_HOME`,
  `JIG_CODEX_SMOKE_CODEX_BIN`, `--keep-work`, and `--require-live-codex`.
  No new deferred decisions were added to `docs/refinement-todo.md`.
- Verification: `python3 -B scripts/codex_install_smoke.py` passed locally
  with 9/9 checks;
  `python3 -B scripts/codex_install_smoke.py --skip-live-codex` passed
