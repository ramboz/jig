## Slice 059-01 - host-aware-migrate-machinery

**Goal:** Make migrated project machinery operations behave coherently when
invoked from a Codex scaffolded runtime.

**DoR:**
- Spec 033 is DONE and Codex scaffold output is stable.
- The existing `docs/refinement-todo.md` host-aware migrate decision is
  treated as this slice's source gap.
- Current `migrate.py` command behavior has been audited for Claude-only
  paths, primer names, and scan roots.

**Acceptance Criteria:**

1. **`copy-machinery` is host-aware.** A Codex-invoked machinery copy can
   install/update `.codex/` runtime files without writing `.claude/`
   files, while Claude behavior remains unchanged.
2. **`rename-decisions` scans Codex paths.** In Codex mode, decision
   rename rewrites references in `AGENTS.md`, `.codex/`, and shared docs
   where appropriate, rather than scanning only `CLAUDE.md` and
   `.claude/`.
3. **The generated Codex migrate skill is honest.** Rendered
   `.codex/skills/jig-migrate/SKILL.md` advertises only the Codex paths
   that the helper actually supports.
4. **Host selection is explicit and testable.** The implementation has a
   stable way to select or infer `claude` vs. `codex`, and tests cover
   both paths.
5. **Existing migration tests stay green.** Claude migrate fixtures and
   self-migration behavior do not regress.
