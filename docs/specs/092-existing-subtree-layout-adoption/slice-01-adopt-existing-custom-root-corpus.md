## Slice 092-01 — adopt an existing custom-root corpus

**Goal:** Let an existing track-local spec corpus opt into jig's configured
layout and immediately use normal status/transition helpers without moving or
overwriting its artifacts.

**DoR:**
- ✅ Spec 084 and ADR-0033 are DONE/Accepted.
- ✅ The CWV corpus shape is reproduced by a local fixture.

**Acceptance Criteria:**

1. **Layout-aware report.** `migrate.py report <subproject> --docs-root .`
   inventories `specs/`, `decisions/`, `workflow.md`, and `architecture.md`
   under the requested root and classifies the CWV-like fixture as adoptable.
2. **Safe configuration migration.** `migrate.py adopt-layout <subproject>
   --docs-root . --dry-run` reports the exact manifest operation and writes
   nothing; apply writes a valid plugin-only `scaffold.json` sentinel while
   preserving every existing artifact byte-for-byte.
3. **Refusal before mutation.** Invalid/escaping roots, an incomplete corpus,
   and malformed/existing conflicting manifests all return non-zero without
   writes.
4. **Transition proof.** After adoption, `workflow.py status-board` and a
   reversible lifecycle transition resolve the subtree sentinel and mutate the
   track-local spec rather than the enclosing repo's corpus.
5. **Live guidance.** migrate/scaffold/spec workflow docs explain existing
   subtree adoption; spec 084 receives an Amendment recording that its named
   adoption trigger occurred.

### For `kind: spike` slices

When the slice's frontmatter has `kind: spike`, the body carries four
extra labelled blocks alongside the standard Goal / DoR / AC / DoD
scaffolding. Spike slices are timeboxed investigation, not feature
work — they reduce an unknown before committing to a design.

```markdown
**Question:** _One sentence stating the open question. Set at DRAFT._

**Time-box:** _Explicit budget — e.g., "1 day", "4 hours". Set at DRAFT._

**Findings:** _Bullet evidence collected during the spike. Filled
during IN_PROGRESS._

**Outcome:** _One of: `ADR-NNNN created` / `spec NNN-NN unblocked` /
`abandoned (reason)`. Multiple outcomes separated by `;`
(e.g., `ADR-0007 created; spec 030-02 unblocked`). Set at DONE._
```

`spec_lint.py` validates the `kind:` enum (allowed values: `spike`,
`feature`) and soft-warns when a `kind: spike` slice is missing any of
the four labels. Mid-flight spikes legitimately have empty Findings /
Outcome, so this is a warning, not a hard error.

See `skills/spec-workflow/SKILL.md` (Spike slices subsection) and
`docs/spec-workflow/spidr-primer.md` for the always-nested rule (spike
slices live inside a real spec, never as standalone `docs/spikes/`
artifacts) and the abandoned-outcome manual-reshape failure mode.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Lifecycle provenance (honest note).** This slice shipped as a single
   commit on `codex/jig-workflow-closure` (PR #104), not through jig's
   step-by-step gated transitions. The independent review is the PR's own
   review. These records — DoD ticks, this deviation log, and the
   reconciliation sweep — were reconstructed during a post-implementation
   docs-alignment pass; the affected suites were re-verified green on
   2026-07-15 (`test_migrate.py` + `test_scaffold*.py`: 169 + 156 local tests
   OK) before marking DONE.

2. **Manifest builder extracted, not duplicated.** Instead of giving the
   adoption path its own manifest assembly, `scaffold.py` factored the shared
   logic into `_scaffold_manifest(...)` and layered `adoption_manifest(...)`
   on top. Greenfield scaffold and `adopt-layout` now emit the same sentinel
   from one definition (AC #2); a default `scaffold.json` stays byte-identical.

3. **Root validation reuses spec 084's helper.** `migrate.py` loads
   `_common/project_layout.py` via `importlib` and calls `validate_docs_root`,
   so `report --docs-root` and `adopt-layout --docs-root` share 084's
   sentinel-anchored path safety and subtree-escape refusal (AC #3) rather than
   re-implementing validation.

4. **`adopt-layout` is verdict-guarded.** Apply refuses unless the corpus scans
   as `adoptable` and no `scaffold.json` pre-exists; `--dry-run` reports the
   write without mutating. It writes only `scaffold.json` and never touches the
   existing artifacts (AC #2, #3).

5. **Report/operations output is layout-aware.** Rendered paths route through
   `_docs_label`/`_docs_base`; the operations section suggests `adopt-layout`
   (and suppresses the `copy-machinery` suggestion) for a non-default root
   (AC #1, #5).

6. **Docs updated.** `skills/migrate/SKILL.md` (five-subcommand list, adopt
   section, `--docs-root` on `report`), the Codex `CodexScaffoldRenderer`
   mirror, and spec 084's `## Amendments` recording that its named adoption
   trigger occurred (AC #5).
