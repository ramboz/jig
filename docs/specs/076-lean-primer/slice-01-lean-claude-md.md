## Slice 076-01 — relocate + compress the Hot Cache

**Goal:** Re-partition `CLAUDE.md`'s Hot Cache — relocate definitional
ADR-prose entries to `docs/memory/glossary.md` / `_common/lexicon.json`
(reachable via `/jig:explain`), compress the remainder to a one-line
index, and add a budget-guard test — so jig's always-loaded primer stops
paying per-turn tokens for reference prose the agent only needs on demand.

**DoR:**
- ✅ spec 065 (`/jig:explain` + lexicon loader + `glossary.md` overlay)
  is DONE — the on-demand home exists.
- ✅ `AGENTS.md` exists as the lean target shape to calibrate against.
- ✅ A budget number is chosen (see AC #4 — settle during DRAFT review).

**Acceptance Criteria:**

1. **Every Hot Cache entry is classified** as `always-on` (one-line
   claim + link, stays in `CLAUDE.md`) or `on-demand` (body relocated).
   The classification rule is recorded in the deviation log / a short
   comment, not left implicit.
2. **No information is lost.** Each relocated entry resolves via
   `/jig:explain <term>` against the merged lexicon (`lexicon.json` +
   `glossary.md`). A test asserts every relocated term key is resolvable
   by the loader.
3. **`CLAUDE.md` Hot Cache is the index shape** — no entry's body exceeds
   the agreed one-line-plus-link form; the dense multi-sentence ADR
   paragraphs are gone from the always-loaded file.
4. **A budget guard fails CI when `CLAUDE.md` regrows** past the chosen
   cap (line or byte/token budget). The cap is a constant with a comment
   citing spec 055's dumb-zone rationale.
5. **Keep-inline set preserved:** the every-turn facts (active-work / v2
   routing, PARKED-don't-re-propose guards, do-not-modify-`conventions.md`)
   remain present in `CLAUDE.md` (test asserts their presence).
