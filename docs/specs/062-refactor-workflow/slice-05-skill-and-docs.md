## Slice 062-05 — `jig:refactor` skill + plugin wiring + workflow.md routing

**Goal:** ship the `jig:refactor` skill that orchestrates the lifecycle,
wire it into the plugin manifest + scaffold/migrate copy, and add the
three-way routing rule (`spec-workflow` vs `jig:bug-fix` vs `jig:refactor`)
to `docs/workflow.md`. This closes the spec.

**DoR:**
- ✅ 062-01..04 landed (`refactor.py` core + gates + review + carve-out/
  close all work from the CLI).
- ✅ The plugin manifest, `scaffold.py` skill-copy, and `migrate.py
  copy-machinery` patterns exist for adding a skill to the pack.

**Acceptance Criteria:**

1. **`jig:refactor` skill** with SKILL.md frontmatter (auto + explicit
   triggers: "refactor this", "migrate X to Y", "restructure without
   changing behaviour"; **do-not-use** routing to `jig:bug-fix` for
   broken behaviour and `spec-workflow` for new behaviour). The skill
   orchestrates the `refactor.py` lifecycle (it owns orchestration — does
   **not** defer; only the reused commodity review steps keep their
   defer-to-richer behaviour, per ADR-0019 Option D / ADR-0016 §"deferral").
2. **Plugin wiring** — the skill is registered in the manifest and copied
   by `scaffold.py` (tier-appropriate) and `migrate.py copy-machinery`;
   `scripts/verify_install.py` asserts its presence (mirrors how the other
   skills are asserted).
3. **`docs/workflow.md` routing** — a clear three-way rule: new behaviour
   → `spec-workflow`; broken behaviour → `jig:bug-fix`; behaviour-
   preserving structural change / migration → `jig:refactor`; plus the
   carve-out seam note (migrations split: preserved part here, new-
   behaviour part to a spec).
4. **CLAUDE.md "Skills in this repo" row** added; the spec's "Active
   specs" entry is **compressed** per the spec 025-01 close-out rule, with
   any load-bearing per-slice invariants migrated to the status-board
   Notes column.
