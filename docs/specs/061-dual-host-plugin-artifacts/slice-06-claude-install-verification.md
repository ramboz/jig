## Slice 061-06 - Claude install verification

**Goal:** Prove the committed `hosts/claude` package and the
`jig-claude-vX.Y.Z.zip` archive install and run correctly in a real or
closest-available Claude environment, independent of Codex.

**DoR:**
- Slices 061-01..05 are DONE.
- A Claude CLI/Desktop environment is available, or the slice records the
  exact unavailable surface and runs the closest deterministic substitute.

**Acceptance Criteria:**

1. **Committed package is verified as Claude-shaped.** `hosts/claude/`
   passes `install_contract.py` and contains only Claude-appropriate
   manifest/runtime paths (no root marketplace.json, no `.codex-plugin/`,
   no `scripts/`/`docs/`/tests).
2. **Remote-install pointer is verified.** The root
   `.claude-plugin/marketplace.json` resolves the `jig` plugin to
   `hosts/claude` (not `path: "."`), and the resolution is asserted.
3. **Claude release archive is verified.** `jig-claude-vX.Y.Z.zip`
   extracts to the expected flat Claude plugin shape and passes the same
   contract as the committed package.
4. **Real Claude install surface is exercised when available.** The slice
   runs the smallest safe Claude CLI/Desktop install or local plugin
   probe available and records the command, version/surface, and result.
5. **Fallback is honest when Claude is unavailable.** If no real Claude
   surface can be exercised, the slice records why and runs a
   deterministic substitute validating package shape, manifest coherence,
   hooks, skills, agents, and scaffold-helper execution from
   `hosts/claude/`.
6. **Failure diagnostics name the host.** Any smoke/probe failure clearly
   identifies the Claude package/archive under test so it cannot be
   mistaken for a Codex failure.

**This is the Claude-side validation pass** (run in a Claude environment;
its Codex sibling is 061-07).

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **New `scripts/claude_install_smoke.py`** — the Claude-side sibling of
  `scripts/codex_install_smoke.py`, mirroring its structure (`SmokeResult`,
  `PASS`/`FAIL`/`UNAVAILABLE`, `_run_command`, `_looks_surface_unavailable`,
  `run_smoke`/`exit_code`/`_build_parser`/`main`, exit 0 iff no FAIL —
  UNAVAILABLE is not a failure). Each check is a `claude-`-prefixed
  `SmokeResult` (AC6). Coverage:
  - **AC1** `claude-committed-package` — `install_contract.validate_claude_package(hosts/claude)`
    + a `_DEV_ONLY_DIRS` guard (no in-package `marketplace.json`, no
    `.codex-plugin/`, no `scripts/`/`docs/`/tests).
  - **AC2** `claude-remote-pointer` — validates the **repo-root**
    `.claude-plugin/marketplace.json` and asserts the `jig` plugin's
    `source.path == "hosts/claude"` (and `!= "."`).
  - **AC3** `claude-release-archive` — builds `jig-claude-v<version>.zip` via
    `build_release_zip.build` into a tempdir, extracts, and asserts the **flat**
    shape (`.claude-plugin/plugin.json` at the extract root) + the package
    contract.
  - **AC5 substitute** `claude-scaffold-helper` — runs
    `hosts/claude/skills/scaffold-init/scaffold.py --help` as a subprocess
    (exit 0), proving the helper executes from within the committed package.
  - **AC4 live** `claude-cli` / `claude-validate-{package,marketplace,archive}`
    — records `claude --version` then runs three **read-only**
    `claude plugin validate <path>` probes (committed package, repo-root
    marketplace manifest, extracted archive). **No `marketplace add` /
    `plugin install`** — nothing mutates global Claude config (the smallest
    safe surface; mirrors the Codex smoke's isolation caution).

- **Live validation actually exercised (not just stubbed).** A real `claude`
  CLI (**v2.1.142**) was present, so AC4 ran live end-to-end:
  `summary: 8 passed, 0 unavailable, 0 failed` (exit 0). The
  `claude-validate-marketplace` probe surfaces a benign "no marketplace
  description" warning but still exits 0 (PASS) per the read-only `validate`
  contract. AC5's UNAVAILABLE fallback is verified by tests (stub CLI absent),
  not by the live run.

- **Tests** `scripts/test_claude_install_smoke.py` (19 tests) — one+ fixture
  per AC + edge cases (injected `.codex-plugin/` / in-package marketplace /
  dev-dir fail; `path:"."` fail; non-flat zip fail; fake-`claude`-bin live PASS
  records version; absent CLI → UNAVAILABLE + substitute still runs;
  unrecognized subcommand → UNAVAILABLE; timeout; missing scaffold helper
  fails). Tests **stub** the CLI via an injected runner — they never invoke the
  real `claude` binary and never mutate global config.

- **Deliberate divergence from the Codex sibling (not a copy slip).**
  `_run_command` uses `env=dict(env) if env else None` (vs the Codex sibling's
  `env=dict(env)`), so an empty `{}` inherits the parent environment rather
  than running with a truly empty env — more robust for the scaffold-helper
  subprocess probe. Intentional; recorded here so the asymmetry reads as
  deliberate.

- **Known benign nit (inherited).** `run_smoke` accepts a `require_live_claude`
  parameter it does not consume in-body (the gating lives in `exit_code`);
  faithfully mirrored from the Codex sibling's identical dead parameter.
  Non-blocking; a candidate for a future cleanup in BOTH files (would need to
  touch `codex_install_smoke.py` too, out of scope here).
