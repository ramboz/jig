## Slice 061-02 - committed Codex package peer

**Goal:** Promote the generated Codex marketplace tree from
`dist/codex-plugin/` to a committed peer at `hosts/codex/`, so Claude and
Codex have parallel committed packages built from the same canonical
source.

**DoR:**
- Slice 061-01 is DONE (committed-package pattern established).
- `scripts/build_codex_plugin.py` can produce the Codex marketplace root
  with its descriptor + nested plugin + host rewrite.

**Acceptance Criteria:**

1. **Codex package builds to the committed peer.**
   `build_codex_plugin.py` targets `hosts/codex/` (default output),
   producing the marketplace descriptor at
   `hosts/codex/.agents/plugins/marketplace.json` and the nested plugin
   at `hosts/codex/plugins/jig/.codex-plugin/plugin.json`.
2. **The package is the full Codex install payload.** It contains the
   rendered Codex skills (`render_codex_plugin_skill_body`), the generated
   role-agent TOML templates, hooks, and templates — the same footprint
   `codex_install_smoke.py` validates today against `dist/codex-plugin/`.
3. **Marketplace path is package-relative.** The descriptor's plugin
   `source.path` resolves correctly from `hosts/codex/` (so
   `codex plugin marketplace add hosts/codex` then
   `codex plugin add jig@jig` works against the committed tree).
4. **Safe-output guards still hold.** `_validate_output_dir` accepts the
   committed `hosts/codex/` target and still refuses the source root,
   source-owned runtime paths, and ancestors of the source root.
5. **Both packages share one build entry point.** The Claude builder
   (061-01) and the Codex builder are invocable together (a single
   `build_host_packages` entry point or documented pair) so 061-03 can
   regenerate both in one step.

**Edge cases:**
- A stale pre-existing `hosts/codex/` is fully replaced, not merged.
- `codex_install_smoke.py` is retargeted/parameterized to the committed
  package without losing its live-CLI probe path.

**DoD:**
