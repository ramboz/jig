## Slice 061-04 - host-explicit release zips

**Goal:** Release host-explicit archives `jig-claude-vX.Y.Z.zip` and
`jig-codex-vX.Y.Z.zip`, built from the committed host packages, and make
the release workflow build, smoke-test, and upload both.

**DoR:**
- Slice 061-01 is DONE.
- Slice 061-02 is DONE.
- Slice 061-03 is DONE (committed packages are guaranteed fresh in CI).

**Acceptance Criteria:**

1. **Claude zip is `hosts/claude/` flat at root.**
   `jig-claude-vX.Y.Z.zip` places `.claude-plugin/plugin.json` at the zip
   root, so it stays directly drag-droppable into Claude Desktop and
   loadable via `--plugin-dir`.
2. **Codex zip is the `hosts/codex/` marketplace root.**
   `jig-codex-vX.Y.Z.zip` contains `.agents/plugins/marketplace.json` and
   `plugins/jig/.codex-plugin/plugin.json`.
3. **Codex zip language is exact.** Builder output, smoke-test output, and
   release notes call the Codex zip an **extract-then-add** marketplace
   bundle, never a directly-installable Codex plugin zip.
4. **Version coherence is enforced.** Each zip's pinned version matches
   the committed package it was built from; a mismatch refuses to produce
   a mislabeled artifact (parity with the existing release-zip version
   check). The release-please bump regenerates the committed packages
   (061-03) before zipping — coordinated with Spec 013.
5. **Release workflow uploads both.** `.github/workflows/release.yml`
   builds, smoke-tests, and uploads both host zips. The legacy
   `jig-vX.Y.Z.zip`: either kept one cycle as an explicit alias mapped to
   the Claude zip, or removed with README/release-note guidance — the
   choice is recorded in the deviation log.

**Edge cases:**
- A release built before `hosts/` is regenerated must fail the version
  coherence check, not ship a stale package.
- Smoke tests are per host and name the host on failure (handed to
  061-06 / 061-07 for the full probe).

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Per-host zip model.** `scripts/build_release_zip.py` was refactored from a
  single host-neutral source-walk into a `--host {claude,codex}` archiver that
  zips the committed `hosts/<host>/` package with arcnames relative to that
  package root. Claude → flat (`.claude-plugin/plugin.json` at root); Codex →
  marketplace root (`.agents/plugins/marketplace.json` +
  `plugins/jig/.codex-plugin/plugin.json`). Default output
  `dist/jig-<host>-v<version>.zip`. Deterministic-zip machinery
  (`_add_entry` / `_DETERMINISTIC_MTIME` / `create_system=3` / sorted entries)
  reused verbatim (AC1, AC2).

- **Version coherence (AC4).** Reads each host's OWN committed manifest
  (Claude `.claude-plugin/plugin.json`; Codex
  `plugins/jig/.codex-plugin/plugin.json`); a mismatch with `--version` exits
  **2** with "Refusing to produce a mislabeled artifact" and writes no zip. The
  stale-`hosts/` edge case is covered by a test that bumps a copied package
  manifest and requests the old version (exits 2, no artifact).

- **Legacy `jig-vX.Y.Z.zip` — DECISION:** kept **one cycle** as an explicit,
  byte-identical **alias of the Claude zip** (`cp` the Claude zip to the legacy
  name and upload it too), since the legacy artifact was always Claude-shaped.
  Gentle-deprecation path; the release note flags it deprecated and "removed
  next release". (Chosen over outright removal per the AC5 either/or.)

- **Release-notes mechanism (AC3).** A new `release.yml` step appends a fixed
  "Install artifacts" block to the GitHub release body via fetch-then-append
  (`gh release view <tag> --json body -q .body` → `gh release edit <tag>
  --notes "<existing><appended>"`), so release-please's generated changelog is
  never overwritten. The block names both host zips, calls the Codex zip an
  extract-then-add marketplace bundle (extract, then `codex plugin marketplace
  add <extracted-dir>`), and flags the legacy alias deprecated.

- **DEVIATION — Claude smoke validator.** The prompt/AC said the Claude smoke
  uses `verify_install.run_headless` "as today". That validator requires
  `.claude-plugin/marketplace.json`, which the committed `hosts/claude/`
  package deliberately omits (the remote-install pointer stays at the repo
  root, per 061-01). The Claude smoke therefore validates the extracted flat
  tree with `install_contract.validate_claude_package` instead — the spec's own
  coordination note (Spec 047) names this as the committed-Claude-package
  validator. Same intent (the extracted Claude tree is a valid install tree),
  correct validator for the post-061-01 package shape. The Codex smoke reuses
  `codex_install_smoke._validate_generated_package` as specified. Both smoke
  messages name the host; the full live-CLI probe stays deferred to 061-06/07.

- **Codex exact language (AC3).** Builder and smoke messages describe the Codex
  artifact as an "extract-then-add marketplace bundle" and never claim it is a
  directly-installable / drag-droppable Codex plugin zip (the Claude messages
  keep drag-droppable phrasing). Negation phrasing in messages/notes was
  reworded to avoid even the substring "directly-installable", so a naive scan
  can't false-positive.

- **Shared source-walk constants preserved.** `_INCLUDE_ROOTS`,
  `_INCLUDE_FILES`, `_EXCLUDE_DIR_NAMES` (incl. `fixtures`), and the
  `test_*.py` exclusion in `_is_excluded_file` are kept in
  `build_release_zip.py` because `build_claude_plugin.py` (061-01) reuses them
  by reference and `install_contract`'s consistency test pins against them.
  They now document the source→committed-package contract; the zip path
  consumes the already-filtered `hosts/` tree.

- **No new deferred decisions** → `docs/refinement-todo.md` unchanged.
