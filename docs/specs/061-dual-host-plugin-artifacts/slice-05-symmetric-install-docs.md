## Slice 061-05 - symmetric install + scaffold docs

**Goal:** Update README and maintainer/scaffold docs so the three-peer
layout reads symmetrically: canonical source root, committed
`hosts/claude` package, committed `hosts/codex` package — each with its
native install path.

**DoR:**
- Slices 061-01..04 are DONE.
- Spec 059 has documented Codex hook trust and explicit agent-install
  semantics.

**Acceptance Criteria:**

1. **README documents both remote one-command installs.** Claude:
   `/plugin marketplace add ramboz/jig` → `/plugin install jig@jig`
   (resolving to `hosts/claude`). Codex: `codex plugin marketplace add`
   against `hosts/codex` → `codex plugin add jig@jig`, with hook trust and
   explicit Codex agent install where appropriate.
2. **The layout is explained, not implied.** Docs name the three peers
   (source root / `hosts/claude` / `hosts/codex`) and state that the host
   packages are committed, source-derived build outputs kept fresh by the
   drift guard — and that they are NOT hand-edited.
3. **Scaffold examples run from the host packages.** Local scaffold
   commands point at `hosts/claude/skills/scaffold-init/scaffold.py` and
   `hosts/codex/plugins/jig/skills/scaffold-init/scaffold.py` — never the
   repo root.
4. **Release-zip docs use host-explicit names.** Public install docs
   reference `jig-claude-vX.Y.Z.zip` (drag-drop) and
   `jig-codex-vX.Y.Z.zip` (unzip → `marketplace add` → `plugin add`),
   honest that Codex has no direct zip-drop.
5. **Docs leave room for host-specific verification.** README/maintainer
   docs point to the dedicated Claude and Codex verification
   commands/slices rather than implying one host's check proves the other.

**Edge cases:**
- The structural asymmetry between the packages (flat Claude plugin vs
  Codex marketplace-wrapped `plugins/jig/...`) is stated plainly so a
  reader is not surprised by the different internal shapes.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Docs rewritten (AC1–AC5 + edge case).** `README.md` — Install-shapes table
  reshaped to per-host rows (host-explicit zip names `jig-claude-vX.Y.Z.zip`
  flat/drag-drop + `jig-codex-vX.Y.Z.zip` extract-then-add, no direct
  zip-drop); "Codex Distribution" scaffold/agent-install examples retargeted
  from repo-root / `dist/codex-plugin/...` to the committed host-package paths
  (`hosts/claude/skills/scaffold-init/scaffold.py`,
  `hosts/codex/plugins/jig/skills/scaffold-init/scaffold.py`); a new "Verifying
  a host install" subsection points at the per-host checks (Claude
  `verify_install.py` / `--host claude --smoke-test`, 061-06; Codex
  `codex_install_smoke.py`, 061-07); "Repository structure" now names the three
  peers + the `hosts/` tree + gitignored `dist/`, and states the flat-vs-
  marketplace-wrapped asymmetry. `CONTRIBUTING.md` — release-zip section uses
  host-explicit names + the now-required `--host` flag + drift-guard framing.

- **DEVIATION — Codex install is `hosts/codex`, NOT a bare-repo `ramboz/jig`
  one-liner (doc-honesty correction).** The first implementer draft rendered
  the Codex remote install as `codex plugin marketplace add ramboz/jig`,
  mirroring Claude's one-liner. That is **wrong**: Claude's bare-repo shorthand
  works only because the **repo-root** `.claude-plugin/marketplace.json` points
  `source.path` at `hosts/claude`; there is **no** repo-root
  `.agents/plugins/marketplace.json` for Codex (its descriptor lives only at
  `hosts/codex/.agents/plugins/marketplace.json`), so the bare-repo form would
  not resolve. Corrected to the proven form `codex plugin marketplace add
  hosts/codex` (matches slice 061-02's documented invocation and
  `scripts/codex_install_smoke.py`), with prose explaining the asymmetry: you
  point Codex at the committed `hosts/codex` package on disk (a repo checkout
  or the extracted `jig-codex` zip) — there is no build step because the
  package is committed. This is consistent with Spec 061 Goal 2, which repoints
  only the **Claude** root pointer and keeps "Codex's marketplace add flow
  against `hosts/codex`". An inverse guard
  (`test_codex_install_does_not_claim_bare_repo_shorthand`) prevents the
  over-claim from returning.

- **Host-package READMEs regenerated, not hand-edited.** The source `README.md`
  is embedded in both committed host packages (`hosts/claude/README.md`,
  `hosts/codex/plugins/jig/README.md`), so editing it drifts them. Resolved the
  drift the sanctioned way (per 061-03): `python3
  scripts/build_host_packages.py` regenerates the copies; `--check` then passes.
  No hand-edits to `hosts/`.

- **Tests.** New `scripts/test_symmetric_install_docs.py` — per-AC positive
  guards + edge-case guard + inverse/regression guards (no install-from
  `dist/codex-plugin`; `hosts/` listed in the repo-structure block; no bare
  repo-root scaffold invocation; no host-neutral `jig-vX.Y.Z.zip` as primary;
  no bare-repo Codex shorthand) over `README.md` + `CONTRIBUTING.md`. Confirmed
  red against the stale docs before the edits. Full suite green (2386 tests),
  drift clean.
