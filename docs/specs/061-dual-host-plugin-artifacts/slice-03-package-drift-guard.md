## Slice 061-03 - host-package drift guard

**Goal:** Make the committed `hosts/claude` and `hosts/codex` packages
safe to keep in git by adding a single regenerator and a CI check that
fails when the committed packages are stale relative to source.

**DoR:**
- Slice 061-01 is DONE (Claude package builder).
- Slice 061-02 is DONE (Codex package builder + shared entry point).

**Acceptance Criteria:**

1. **One command regenerates both packages.** A
   `scripts/build_host_packages.py` (or equivalent entry point) rebuilds
   `hosts/claude/` and `hosts/codex/` from canonical source in a single
   invocation, deterministically (stable file ordering, no spurious diffs
   on re-run).
2. **A drift check exists.** A check (script subcommand and/or test)
   regenerates into a scratch location (or in place) and compares against
   the committed packages, exiting non-zero with an actionable diff
   summary when they differ — naming the stale path and the regenerate
   command.
3. **CI enforces the guard.** A CI job runs the regenerator and fails on
   a dirty `git diff` of `hosts/`, so a PR that edits source without
   regenerating cannot merge silently.
4. **Determinism is verified.** A test asserts that regenerating twice
   produces byte-identical output (no timestamp/order nondeterminism),
   mirroring the release-zip deterministic-mtime convention.
5. **Guidance is discoverable.** Contributor docs (`docs/workflow.md` or
   `docs/conventions.md` pointer, plus the failure message) state: edit
   source, then run the regenerator, then commit `hosts/`.

**Edge cases:**
- Version-only change in a source manifest must reflect into both
  committed packages (anticipates the 061-04 / Spec 013 release-please
  coordination).
- A partially-built `hosts/` from an interrupted run is fully replaced on
  the next regenerate, not merged.
