## Slice 061-07 - Codex install verification

**Goal:** Prove the committed `hosts/codex` marketplace package and the
`jig-codex-vX.Y.Z.zip` archive install and run correctly in a real or
closest-available Codex environment, independent of Claude. This is the
final, Codex-side validation pass for the spec.

**DoR:**
- Slices 061-01..06 are DONE.
- A Codex CLI is available, or the slice records the exact unavailable
  surface and runs the closest deterministic substitute.

**Acceptance Criteria:**

1. **Committed package is verified as Codex-shaped.** `hosts/codex/`
   passes Codex package validation, including the marketplace descriptor
   at `.agents/plugins/marketplace.json` and the nested plugin at
   `plugins/jig/.codex-plugin/plugin.json`.
2. **Codex release archive is verified.** `jig-codex-vX.Y.Z.zip` extracts
   to the expected marketplace-root shape and passes the same validation
   as the committed package.
3. **Real Codex install surface is exercised when available.** The slice
   runs a safe `codex plugin marketplace add` + `plugin add` probe against
   the committed package with an isolated `CODEX_HOME`, records the Codex
   CLI version/surface, and confirms skill visibility, hook trust
   guidance, and explicit Codex agent installation behavior.
4. **Fallback is honest when Codex is unavailable.** If no real Codex CLI
   surface can be exercised, the slice records why and runs the
   deterministic `codex_install_smoke.py` substitute validating
   marketplace shape, manifest coherence, rendered Codex skills, hooks,
   generated TOML agent templates, and scaffold-helper execution from
   `hosts/codex/plugins/jig/`.
5. **Failure diagnostics name the host.** Any smoke/probe failure clearly
   identifies the Codex package/archive under test so it cannot be
   mistaken for a Claude failure.

**Note (workflow):** with slices 061-01..06 implemented and reviewed in
Claude, run this slice in a Codex environment so its live-CLI probe (AC3)
actually fires rather than collapsing to the substitute.
