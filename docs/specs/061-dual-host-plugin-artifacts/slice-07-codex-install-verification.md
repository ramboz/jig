## Slice 061-07 - Codex install verification

**Goal:** Prove the committed `hosts/codex` marketplace package and the
`jig-codex-vX.Y.Z.zip` archive install and run correctly in a real or
closest-available Codex environment, independent of Claude. This is the
final, Codex-side validation pass for the spec.

**DoR:**
- Slices 061-01..06 are DONE.
- A Codex CLI is available, or the slice records the exact unavailable
  surface and runs the closest deterministic substitute.

**Acceptance Criteria:**

1. **Committed package is verified as Codex-shaped.** `hosts/codex/`
   passes Codex package validation, including the marketplace descriptor
   at `.agents/plugins/marketplace.json` and the nested plugin at
   `plugins/jig/.codex-plugin/plugin.json`.
2. **Codex release archive is verified.** `jig-codex-vX.Y.Z.zip` extracts
   to the expected marketplace-root shape and passes the same validation
   as the committed package.
3. **Real Codex install surface is exercised when available.** The slice
   runs a safe `codex plugin marketplace add` + `plugin add` probe against
   the committed package with an isolated `CODEX_HOME`, records the Codex
   CLI version/surface, and confirms skill visibility, hook trust
   guidance, and explicit Codex agent installation behavior.
4. **Fallback is honest when Codex is unavailable.** If no real Codex CLI
   surface can be exercised, the slice records why and runs the
   deterministic `codex_install_smoke.py` substitute validating
   marketplace shape, manifest coherence, rendered Codex skills, hooks,
   generated TOML agent templates, and scaffold-helper execution from
   `hosts/codex/plugins/jig/`.
5. **Failure diagnostics name the host.** Any smoke/probe failure clearly
   identifies the Codex package/archive under test so it cannot be
   mistaken for a Claude failure.

Claude, run this slice in a Codex environment so its live-CLI probe (AC3)
actually fires rather than collapsing to the substitute.

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

- **Live Codex install exercised from Codex.** In a clean export of `v2`,
  `python3 scripts/codex_install_smoke.py --use-committed-package
  --require-live-codex --keep-work --timeout 60` ran against a real Codex
  CLI (`codex-cli 0.133.0`) with an isolated `CODEX_HOME`:
  `summary: 9 passed, 0 unavailable, 0 failed` (exit 0). The probe covered
  the committed `hosts/codex/plugins/jig` package, the marketplace descriptor,
  `codex plugin marketplace add hosts/codex`, `codex plugin add jig@jig`,
  installed-cache hook validation, representative skill visibility through
  `codex debug prompt-input`, and hook-trust surface detection.

- **Codex hook trust is documented and verified.** The live smoke reported
  `codex-hook-trust-state: PASS` with the expected outcome: the hook-trust
  enforcement surface is present, but a fresh isolated config has no persisted
  hook trust, so jig hooks remain pending `/hooks` review. The user-facing docs
  already say this explicitly in `README.md` and the packaged
  `hosts/codex/plugins/jig/README.md`: after `codex plugin add`, start or
  restart Codex, open `/hooks`, and trust the plugin-bundled hook definitions
  before they run. The source and packaged `.codex-plugin/plugin.json`
  `longDescription` also says to review and trust bundled hooks via `/hooks`
  before they run. This is important: before trust, Codex can load the plugin
  skills but skips jig's hook gates.

- **RC hook metadata follow-up.** During local RC validation on 2026-06-12,
  Codex loaded the plugin but warned that async command hooks are unsupported
  and showed unnamed `/hooks` rows as `Hook 1`, `Hook 2`, etc. The Codex
  renderer now adapts source hooks before package/scaffold output: it strips
  `async` from Codex hook definitions and adds stable `statusMessage` labels
  such as `jig: record task telemetry`. The canonical source hooks and Claude
  package keep their async metadata; Codex package smoke validation now fails
  if a command hook declares `async` or omits `statusMessage`.

- **Codex release archive verified separately.** Built
  `/private/tmp/jig-v2-review.9kAkux/jig-codex-v1.12.0.zip` with
  `python3 scripts/build_release_zip.py --host codex --version 1.12.0`
  (90 entries, extract-then-add marketplace bundle), then validated the
  extracted archive with
  `python3 scripts/build_release_zip.py --host codex --smoke-test <zip>`:
  `PASS smoke[codex]: extract-then-add marketplace bundle ... Codex manifest,
  rendered skills, hook config, hook scripts, and local marketplace descriptor
  are coherent`.

- **Explicit Codex agent install verified from the installed plugin cache.**
  After the live `codex plugin add` probe, running
  `skills/scaffold-init/scaffold.py --install-codex-agents` from the actual
  Codex-installed plugin cache copied the three expected global agent TOML
  files (`jig-architect.toml`, `jig-implementer.toml`, `jig-reviewer.toml`);
  `jig-reviewer.toml` preserved `sandbox_mode = "read-only"`.

- **Regression evidence.** Focused package/archive tests passed:
  `python3 -m unittest scripts.test_codex_install_smoke
