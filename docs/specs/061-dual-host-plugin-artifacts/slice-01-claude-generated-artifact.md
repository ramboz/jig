## Slice 061-01 - `dist/claude-plugin` generated artifact

**Goal:** Add a generated Claude plugin artifact at
`dist/claude-plugin/` so Claude and Codex both install from host-specific
build output instead of treating the source root as Claude's install
tree.

**DoR:**
- Spec 013 release zip builder exists.
- Spec 047 install contract validator exists.
- `scripts/build_codex_plugin.py` already establishes the generated
  artifact pattern for Codex.

**Acceptance Criteria:**

1. **A Claude artifact builder exists.** A script or shared build helper
   materializes `dist/claude-plugin/` from the canonical source tree,
   including `.claude-plugin/`, `agents/`, `skills/`, `hooks/`,
   `templates/`, `README.md`, and `LICENSE` when present.
2. **Generated output matches the Claude runtime contract.** The artifact
   excludes source-only paths (`scripts/`, `docs/`, `.github/`, tests,
   fixtures, caches) while preserving runtime paths such as
   `hooks/scripts/` and `templates/docs/`.
3. **Build safety mirrors Codex.** The builder refuses unsafe output
   directories such as the source root, source-owned runtime paths, or
   ancestors of the source root; output under `dist/` is accepted and
   replaced atomically enough for repeatable local builds.
4. **Validation targets the generated artifact.** Existing release/plugin
   contract checks can run against `dist/claude-plugin/` and no longer
   need to treat the source root as the Claude install artifact.
5. **Codex packaging stays unchanged.** `scripts/build_codex_plugin.py`
   continues to produce `dist/codex-plugin/plugins/jig/` plus the
   marketplace descriptor at `dist/codex-plugin/.agents/plugins/marketplace.json`.
