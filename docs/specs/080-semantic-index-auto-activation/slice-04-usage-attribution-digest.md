## Slice 080-04 - usage attribution digest

**Goal:** Extend jig's usage reporting so maintainers can compare sessions
where semantic-index activation was available/used against sessions that fell
back to raw Grep/Read exploration, separated by public provider profile vs.
internal overlay provider.

**DoR:**
- ✅ 080-01 is DONE and emits content-free activation telemetry.
- ✅ `scripts/usage.py` current report/top/read-attribution surfaces are
  re-read so the new digest fits the existing vocabulary.

**Acceptance Criteria:**

1. **Activation telemetry is summarized.** `usage.py` can report activation
   attempts by provider, provider profile (public/internal-overlay), outcome,
   repo-root class, and host adapter over a configurable time window.
2. **Indexed vs. fallback sessions are distinguishable.** The digest groups
   sessions into index-ready, recommended-but-not-opted-in, provider-missing,
   activation-failed, and overlay-disabled buckets.
3. **Read/search proxies are included.** Where existing transcript data allows
   it, the digest reports raw Read nudges, large/duplicate read events,
   context-growth bands, and broad Grep/Search fallback counts alongside the
   activation bucket.
4. **No content leakage.** The report never prints search queries, file bodies,
   diffs, or provider command output. It prints counts and small status labels.
5. **Works without provider installed.** Tests use synthetic JSONL fixtures and
   do not require Scout, tokensave, another public provider, Codex, or Claude
   Code.

### Deviation log (after reconciliation)

- Implemented the usage digest as a new `usage.py semantic-index` subcommand
  rather than folding it into `top` or `read-attribution`, preserving the
  existing command vocabulary while keeping semantic-index activation as its own
  report surface.
- The digest deliberately compares activation telemetry and transcript/read
  proxies as aggregate counts over the same configurable window. It does not
  join activation events to sessions because the 080-01 telemetry schema is
  content-free and session-id-free by design.
- Added privacy-focused fixture coverage for mixed public/internal-overlay
  providers, host adapters, repo-root classes, overlay-disabled rows, malformed
  rows, missing transcript data, time-window filtering, read/search proxy
  counts, and output that omits queries, file bodies, diffs, provider output,
  and read paths.
- Compliance and craft review passed. The craft reviewer noted strengths in the
  scoped read-only integration, explicit aggregate-only framing, and
  fixture-friendly privacy/robustness coverage.
- No architecture, conventions, or deferred-decision updates were required.
