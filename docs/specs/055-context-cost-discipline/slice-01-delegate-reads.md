## Slice 055-01 — Delegate file-heavy reading to isolated subagents

**Goal:** Establish the thin-orchestrator principle in jig's workflow so a
developer doing file-heavy reading/analysis has a sanctioned, documented path
to delegate it to an isolated read-only subagent (the built-in `Explore` /
`general-purpose`) — keeping that content out of the orchestrator's re-read
loop. This is the workstream's biggest lever (Read+Edit+Write ≈ 52% of
orchestrator context).

**DoR:**
- ✅ Delegation target decided: reuse built-in `Explore` / `general-purpose`
  (spec Decisions §1).
- ✅ `docs/workflow.md` reviewed for where the "Context-cost discipline"
  section belongs.

**Acceptance Criteria:**

1. **`docs/workflow.md` gains a "Context-cost discipline" section** stating
   the design principle (the orchestrator's context is the most expensive
   real estate — keep it lean) and the delegate-reads rule with a concrete
   trigger (e.g., "when a step will read more than a couple of files, or scan
   a large/unknown area, delegate it to a read-only subagent and keep only
   the summary").
2. **The section names the built-in `Explore` / `general-purpose` agents** as
   the delegation target and specifies the expected return shape — a compact
   structured summary, never raw file contents.
3. **The reuse decision is recorded inline** in that section: jig
   deliberately reuses the built-in agents rather than shipping its own
   explorer/analyst, with the one-line rationale (avoid duplicating a capable
   built-in; revisit only if the return contract proves insufficient). No new
   `agents/*.md` file is added.
4. **The CLAUDE.md template** (`templates/CLAUDE.md.template`) gains a
   Hot-Cache pointer to the discipline section.
5. **The $540 anti-pattern is captured** as a worked do/don't example in the
   section (gap-review run in the orchestrator vs. delegated reading).
