## Slice 068-03 — reconcile-coverage-grounding

**Goal:** At reconcile, a **bidirectional** coverage check reports use cases with
no implementing spec (**coverage gap**) and specs with no parent use case
(**scope creep**) — a **deterministic set-difference** over slice 02's trace
links (no reviewer subagent), surfaced at the reconcile checkpoint as the
**backstop** to slice 02's primary framing-time grounding. Advisory by default.

**DoR:**
- ✅ 068-02 DONE — specs carry machine-resolvable `use_cases:` trace links and use
  cases carry stable ids.
- ✅ Host decision grounded (ADR-0025 §A4): this is a **new** project-wide query —
  neither the per-slice reconciliation reviewer (deviation-log-scoped, never reads
  the vision) nor one-spec-at-a-time `/jig:analyze` (cross-spec unsupported in MVP)
  provides the reach. The arch-review settles where it lives (a `workflow.py`
  helper vs. a cross-spec `/jig:analyze` extension).

**Acceptance Criteria:**

1. **Bidirectional coverage.** The check enumerates the vision's use cases and
   the project's specs and reports **both** directions: a use case with no
   implementing spec (coverage gap) and a spec with no parent use case (scope
   creep). Observable: on a fixture with one known gap + one orphan spec, both
   findings appear.
2. **Resolves via trace links (query, not re-read).** Coverage is computed from
   slice 02's `use_cases:` links + use-case ids, not by re-scanning spec prose.
   Observable: the check reads the link metadata.
3. **Runs at reconcile, advisory by default.** It surfaces at the reconcile phase
   and **warns** rather than blocks — a coverage gap or scope-creep finding does
   **not** fail the RECONCILED / DONE transition by default (OQ3: a gate is a
   later escalation), per ADR-0011. Observable: a fixture with a gap reconciles
   without a hard block.
4. **No new reviewer subagent.** The check is a **deterministic helper**
   (set-difference over use-case ids ↔ trace links), not an LLM reviewer pass.
   Observable: no new `agents/*.md` is added, and the finding is *surfaced at* the
   reconcile checkpoint, **not** folded into the per-slice reconciliation
   reviewer's prompt (ADR-0025 §A4 / the ADR-0020 convergence is a shared
   checkpoint + human, not a shared mechanism).

### Deviation log (after reconciliation)

1. **Arch boundary settled (the `arch_review` question).** The project-wide
   coverage check lives as a **`workflow.py coverage`** subcommand, **not** a
   `/jig:analyze` extension. Decisive reason: `/jig:analyze` is a judgment-only
   skill with **no `.py` helper**, so a deterministic set-difference has no home
   there; `workflow.py` already hosts the read-only project-wide query family
   (`stale` / `routing-stats` / `amendments`), and `coverage` is a fourth sibling
   with the identical shape (`--project-dir`, stdout, always exit 0). Reuses slice
   02's `_common/use_cases.py` (`parse_use_cases` / `resolve_use_cases` /
   `has_use_cases_section`) unchanged. Confirmed by the arch-review pass
   ([reviews/slice-03-arch.md](reviews/slice-03-arch.md), verdict: pass).
2. **Third report category — intentional forward-shaping beyond AC1's two
   directions.** AC1 names gap + creep; `resolve_use_cases` already separates
   *unresolvable* cited ids (a spec citing a `UC-N` absent from the vision), and
   dropping them silently would hide a data error. They are surfaced as a
   clearly-**subordinate third** section ("Unresolvable trace links"), kept below
   the two headline directions. All three reviewers endorsed this as sound honesty,
   not scope creep — consistent with ADR-0025 §A4's "reported, never raised" stance.
3. **Review nits addressed inline at reconciliation** (ADR-0010 live prose /
   the slice-02 #7 convention):
   - **Double-glob removed** (flagged by all three reviewers): `docs/specs/*/spec.md`
     is globbed **once** into `spec_paths`; `n_specs = len(spec_paths)`; the
     asymmetric `is_dir()` guard is gone (a glob on a missing dir yields `[]`).
   - **Report rows made directly-openable** (arch nit): scope-creep / unresolvable
     rows emit `docs/specs/<dir>/spec.md` rather than the bare directory.
4. **Review nits deliberately NOT applied, with reasons:**
   - **Per-spec vision re-parse** (`resolve_use_cases` re-parses the vision on each
     call, though `vision_ucs` is already parsed): left as-is. Fixing cleanly would
     touch slice 02's raw-text `use_cases.py` API; the cost is negligible at jig's
     scale (a handful of specs, at a reconcile-time advisory). The craft reviewer
     explicitly advised leaving it.
   - **In-method `import shutil`** in `CoverageTests.tearDown`: **kept**. It matches
     the file's pervasive established convention — 40+ test classes use an in-method
     `import shutil` and `shutil` is intentionally not imported at module top;
     moving only this one would make it the inconsistent outlier. (The craft
     reviewer flagged it without whole-file context.)
   - **Test section-slicing** (assertions slice on lowercased heading substrings):
     left — low priority; behavior is correctly pinned today.
5. **Tooling footgun captured as a learning.** `workflow.py transition` must be
   invoked with the **`spec.md`** path + a slice fragment, **not** the slice-file
   path. Passing the slice file makes the post-write `_write_spec_rollup(spec_md)`
   treat the slice file as `spec.md`, recompute a single-slice rollup (→ IN_PROGRESS
   for any active state), and **clobber the slice's own just-written status**. This
   silently reverted REVIEWED → IN_PROGRESS on the first attempt; re-running with
   `spec.md` fixed it. Filed to [learnings](../../memory/learnings.md); a defensive
   guard in `transition` is a candidate follow-up (out of scope here).
