## Slice 068-04 — mid-flight-triage

**Resolution trigger:** (a) slice 02's trace links exist and are populated across a real spec corpus, AND (b) a genuine mid-flight use-case addition that intersects existing specs has been observed (a real conflict/reframe event), so the triage classifier can be validated against an actual case rather than an imagined one. Mirrors [ADR-0025](../../decisions/adr-0025-use-cases-breadth-layer.md) Option C's revisit trigger.

**Status note — DEFERRED by design, not parked work.** This slice is the
documented direction for handling a use case added *after* N specs exist. It is
deferred for the same reasons [ADR-0020](../../decisions/adr-0020-spec-frame-hardening.md)
deferred best-of-N drafting: it is **load-bearing on slices 02–03's trace links
being real and populated**, and it is the **thinnest-evidence part** of this work
(the rare reframe class — one user, *zero* observed mid-flight reframe events).
Building a triage classifier now would be designing against imagined trace data.
**Record the direction; do not build until the trigger fires.**

**Goal (when un-deferred):** When a use case is added mid-project, classify its
**blast radius** and handle each class proportionally — *not* a fixed reframe
flow, and *not* "just a new spec":

- **Additive** (no intersection): capture + confirm into the vision, spawn
  spec(s). Frictionless; project size irrelevant.
- **Conflicting** (intersects existing specs/assumptions): flag **only the
  specific intersecting specs** (a bounded trace-link query, not a re-read),
  surface to the human, decide per-spec.
- **Reframing** (contradicts the vision's framing): escalate as an **ADR-grade**
  decision, human-driven. **Never** auto-re-review all N specs (that is
  shallow-analysis-at-scale and burns the 055/057 cost ceiling).

**DoR (when un-deferred):**
- ✅ 068-02 + 068-03 DONE — trace links real + populated, coverage check live.
- ✅ Real trace data of a mid-flight conflict/reframe event exists to validate the
  classifier against.

**Acceptance Criteria (designed, not yet built):**

1. **Classification by trace-query.** An added use case is classified additive /
   conflicting / reframing by querying slice 02's trace links for intersection
   with existing specs/assumptions — bounded to the intersection, never a full
   re-read.
2. **Additive path** captures + confirms + spawns spec(s), frictionless,
   regardless of project size.
3. **Conflicting path** flags only the specific intersecting specs and surfaces
   them per-spec to the human.
4. **Reframing path** escalates to an ADR-grade, human-driven decision and does
   **not** auto-re-review the whole project.
5. **Asymmetric default.** When classification is unsure, treat as a
   **conflict-candidate** and surface to the human; **never** wave through as
   additive. (Misclassifying a conflict *as* additive is the silent-corruption
   failure mode.)
