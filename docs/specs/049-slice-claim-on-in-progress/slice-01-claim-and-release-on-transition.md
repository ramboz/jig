## Slice 049-01 — claim-and-release-on-transition

**Goal:** Teach `workflow.py transition <slice> IN_PROGRESS` to stamp
a `claimed_by:` identifier in slice frontmatter and reserve the
transition on `origin/main` (with PR fallback). Two parallel
worktrees calling `transition <same-slice> IN_PROGRESS` simultaneously
get one success and one structured refusal naming the existing claim.

**DoR:**
- ✅ Spec 028-01's reserve-on-main + race-on-push + PR-fallback
  primitives are in production in `adr.py` and `workflow.py new`.
- ✅ Slice frontmatter parser (slice 015-01) supports adding/removing
  arbitrary keys.
- ✅ `_SubprocessRecorder` mock pattern (spec 003-03 / 028-01)
  available for tests.

**Acceptance Criteria:**

1. **`transition <slice> IN_PROGRESS` stamps `claimed_by:`.** The
   helper derives the identifier from `git rev-parse --abbrev-ref
   HEAD` (or `JIG_CLAIM_ID` env override if set) and writes it to
   the slice frontmatter alongside the `status:` flip.
2. **Reserve-on-main with PR fallback.** Commits the frontmatter
   change to `origin/main`. Push-refused-by-policy → PR fallback
   branch + `gh pr create`. Push-refused-by-race → instruct re-run.
   Mirrors spec 028-01 classifier verbatim.
3. **Collision refusal.** If the on-disk slice already has
   `claimed_by:` set to a different identifier AND `status: IN_PROGRESS`,
   the helper refuses with a structured error naming the existing
   `claimed_by:` and pointing to `--release` as the escape hatch.
4. **Claim cleared on forward transition.** `transition <slice>
   REVIEWED` clears `claimed_by:` from frontmatter. Same for any
   back-transition to `READY_FOR_IMPLEMENTATION` / `DRAFT`.
5. **`--release` flag.** `workflow.py transition <slice>
   READY_FOR_IMPLEMENTATION --release --reason "<text>"` clears
   `claimed_by:` and resets `status:`. Refuses without `--reason`.
   The reason is appended to a `## Release log` section in the slice
   for audit.
6. **`--no-push` parity.** Local-only claim path, same shape as
   `workflow.py new --no-push`. Default refuses if origin is
   unreachable; `--no-push` opts into local stamping with a warning.
7. **Subprocess-mocked tests.** No real `git push` exercised in the
   suite. Use `_SubprocessRecorder` to assert the helper invokes
   `git fetch origin main`, computes the next state, commits, and
   pushes in the expected order.
8. **Live-remote dogfood.** Documented in the deviation log:
   transition this slice itself to `IN_PROGRESS` and verify the
   commit lands on `origin/main` and a parallel worktree's
   `transition` call sees the existing claim.
