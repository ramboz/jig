## Slice 038-01 — policy-adr

**Goal:** Record the tier-meaning policy as an accepted ADR so the
implementation slices build against a fixed, citable contract instead
of re-litigating "real vs. informational tiers" mid-build.

**DoR:**
- ✅ Spec 038 clarified; the (a) real-tiers vs. (b) informational-tiers
  decision made by the maintainer (chosen: real gated tiers + first-class
  upgradeability, 2026-05-29).
- ✅ Q2 context-cost evidence gathered (all-14 descriptions ≈ 2,674
  always-in-context tokens; gating saves ≈ 1,218) so the ADR can state
  the true rationale (promise integrity / wizard correctness / routing
  surface) rather than a token-budget claim the evidence doesn't support.

**Acceptance Criteria:**

1. **ADR file exists** at `docs/decisions/adr-0012-scaffold-tier-gated-install.md`
   with all house-style sections: Status, Decision Options Considered
   (≥2 options with pros/cons), Recommended Decision, Consequences,
   Scope, Relationship to other decisions, Open questions.
2. **The ADR records the chosen policy:** tiers gate the scaffold-init
   copy step (real, not informational); post-scaffold tier upgrade is a
   committed, additive capability; and the code's `_TIER_SKILLS` table is
   the source of truth that the vision/README docs are reconciled *to*.
3. **The ADR Status is flipped `Proposed` → `Accepted`** (via
   `adr.py accept 0010`) after maintainer approval, and
   `docs/decisions/README.md`'s `## Index` is regenerated to list it
   (`adr.py index docs/decisions`).

### Deviation log (after reconciliation)

1. **ADR number not formally reserved on `origin/main`.** `adr.py new`
   refuses off-`main`, and reserving from the primary `main` checkout
   would have required stashing unrelated untracked files there +
   pushing to shared `main` for a not-yet-accepted draft. Created
   `adr-0010` locally in this worktree (next free number) instead;
   accepted via `adr.py accept 0010` + `index`. Collision risk with a
   parallel worktree is low and renumbering an unaccepted ADR is cheap.
   No deviation from the *decision content*.
2. **Upgrade-vehicle framing revised mid-draft.** Maintainer flagged
   that `migrate.py copy-machinery` (spec 021) already provides additive
   machinery-copy into a set-up project. ADR-0012's Recommended Decision /
   Consequences / Relationships were updated to name copy-machinery as
   the leading upgrade vehicle (vs. a net-new entry point) before
   acceptance. This also surfaced that `_copy_skills_and_agents` has two
   callers (`scaffold()` + `copy_machinery()`), folded into slice 038-02.
3. **No other deviations.** ADR accepted as drafted; maintainer approved
   the prose 2026-05-29.
