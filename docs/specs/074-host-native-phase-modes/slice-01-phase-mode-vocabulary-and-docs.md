## Slice 074-01 - phase-mode vocabulary and docs

**Goal:** Define jig's host-neutral phase-mode vocabulary and document how it
maps onto the existing lifecycle without becoming lifecycle state.

**Resolution trigger:** Resume when Codex host-adapter work from spec 033 is
picked back up, or when at least two real sessions show user friction around
"when should I plan vs. edit" in jig's current prompt cookbook.

**DoR:**
- [x] ADR-0027 is accepted or explicitly amended.
- [x] Current Codex and Claude planning / implementation surfaces have been
      re-verified for wording and limitations.

**Grounding notes (2026-06-22):**

- Codex: verified against the current OpenAI Codex manual fetched by
  `openai-docs/scripts/fetch-codex-manual.mjs`. Relevant surfaces: Codex
  documents `/plan` / Plan mode as the planning-before-implementation path and
  separately documents permissions modes for execution control.
- Claude Code: verified against official Claude Code docs. `plan` mode is
  documented as read/explore/plan before edits; `acceptEdits` and `auto` are
  separate execution-permission modes.
- ADR-0027 was accepted after a passing frame-critique review was recorded at
  `docs/decisions/reviews/adr-0027-frame-critique.md`.

**Acceptance Criteria:**

1. **Vocabulary is host-neutral.** Docs define the portable phases `plan`,
   `implement`, `review`, `reconcile`, and `land`, with one-sentence meanings
   tied to jig lifecycle checkpoints.
2. **Artifact primacy is explicit.** The docs say host modes are advisory UX
   affordances, while specs, slices, ADRs, and review evidence remain the
   canonical workflow record.
3. **Prompt cookbook updated.** `docs/prompts.md` gains concise guidance for
   using host planning mode during clarify/spec/session-plan work and
   implementation mode during slice execution.
4. **No gate language.** No doc says a host mode satisfies a transition,
   review, or human approval requirement.
