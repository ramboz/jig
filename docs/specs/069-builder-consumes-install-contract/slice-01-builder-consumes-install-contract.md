## Slice 069-01 — builder-consumes-install-contract

**Goal:** Make `build_release_zip.py` derive its include/exclude rules from
`install_contract.py` (the single source of truth) instead of its own
module-level constants, eliminating the build-vs-verify duplication that a
consistency test currently guards. End-to-end value: the release zip's file
set has exactly one definition; changing what ships is a one-place edit.

**DoR:**

- Spec 047 DONE (`install_contract.py` is the validator-facing contract).
- Release build + smoke tests green before the slice starts.
- The current guard
  (`test_install_contract.py::test_exclusion_predicate_matches_build_release_zip`)
  is identified as the test to retire.

**Acceptance Criteria:**

1. **Contract owns the release file set.** `install_contract.py` exposes the
   release-zip include roots/files (including the runtime `scripts/*.py`
   allowlist) and the exclude rules as data, with a pure enumerator/helper
   in its existing stdlib-only, side-effect-free style. Each deliberate
   oddity keeps its rationale comment.
2. **Builder consumes the contract.** `build_release_zip.py` builds its
   entry set from `install_contract.py`; it no longer defines
   `_INCLUDE_ROOTS` / `_INCLUDE_FILES` / `_INCLUDE_SCRIPT_FILES` /
   `_EXCLUDE_*` of its own. No parallel list remains in the builder.
3. **Guard retired.** `test_exclusion_predicate_matches_build_release_zip`
   is removed or repurposed — there is nothing left to keep in sync.
4. **Artifact unchanged.** The built zip contains the identical sorted entry
   set as before the refactor, with deterministic mtime / order / contents
   preserved. A test asserts entry-set (ideally byte) stability across the
   change.
5. **Suite green.** Full test suite green, including the existing build +
   smoke tests and the contract validators.

### Deviation log (after reconciliation)

1. **Artifact before/after equality — proven, with two *intended* content
   deltas (DoD item 2).** A release zip built from `HEAD` pre-refactor and one
   built post-refactor were diffed entry-by-entry: **identical 91-entry
   namelist, identical write order, identical deterministic mtimes.** Content
   is byte-identical for **89 of 91** entries. The two changed entries are
   both deliberate: (a) `scripts/install_contract.py` — it *ships* in the
   runtime-scripts trio and now carries the new `iter_release_files`
   enumerator + include data, so its shipped bytes necessarily change; (b)
   `skills/scaffold-init/scaffold.py` — the reconciliation comment fix in #2.
   All other 89 entries are byte-for-byte unchanged. **Subtlety worth
   recording:** a naive whole-zip `sha256` comparison "fails" here for a
   logically necessary reason — you cannot add code to a source file that
   ships *inside* the artifact and keep that file's shipped bytes constant.
   AC4's substantive guarantee (identical entry set / order / mtime / every
   *non-edited* file byte-identical) holds. The pre-refactor build reproduced
   the captured golden digest `218f39fb…` exactly, confirming the baseline.
2. **Stale-comment inline correction in a 5th file (`scaffold.py`), beyond the
   four named deliverables.** Both review passes flagged
   `skills/scaffold-init/scaffold.py:1594`, which named the removed
   `build_release_zip.py::_INCLUDE_SCRIPT_FILES`. Corrected inline to point at
   `install_contract.RELEASE_INCLUDE_SCRIPT_FILES` + the `iter_release_files`
   enumerator. This is collateral the symbol-move created; leaving it would
   preserve exactly the cross-module drift this spec exists to eliminate.
   Treated as **live operational prose corrected inline** per
   [ADR-0010](../../decisions/adr-0010-amendment-scope-records-vs-live-prose.md)
   (git history is the audit trail). The implementer deliberately left it to
   keep the diff scoped; the orchestrator folded it in during reconciliation
   on both reviewers' recommendation.
3. **Enumerator uses the unified `is_excluded_release_path` predicate, not the
   old split logic.** `iter_release_files` applies the single combined
   predicate (`is_excluded_release_path(rel.as_posix())`) instead of the old
   builder's split "exclude-dir on parent parts + exclude-file on basename."
   Behaviourally equivalent for real files (proven by the identical entry set)
   and strictly more consistent — it is now the *same* predicate the smoke
   test (`test_no_excluded_path_leaked`) applies to a built zip. The old
   `_is_excluded_dir` / `_is_excluded_file` split is gone.
4. **Approach matched the spec.** Data (`RELEASE_INCLUDE_ROOTS` /
   `RELEASE_INCLUDE_FILES` / `RELEASE_INCLUDE_SCRIPT_FILES`) + a pure,
   side-effect-free `iter_release_files()` enumerator live in
   `install_contract.py`; the builder imports it via the **same
   `sys.path.insert` + `import install_contract` pattern `verify_install.py`
   already uses** (non-circular). No JSON externalization (Non-goal honored);
   rationale comments carried over verbatim. A `test_iter_release_files_is_pure`
   test pins the side-effect-free claim (asserts the source tree is byte-for-
   byte unchanged across enumeration).
5. **Historical references intentionally untouched.** Mentions of the old
   builder symbols in **closed records** (`docs/specs/035-*`, `013-*`,
   `047-*`, `docs/memory/learnings.md:387`) are preserved per ADR-0010
   (records keep the original; git history is the trail). Only the one *live*
   code reference (`scaffold.py`, #2) was corrected. A test **method name**,
   `test_iter_files_skips_fixtures_at_any_depth`, keeps "iter_files" as a
   plain-English description (not a symbol reference) — left as-is; both
   reviewers concurred.
6. **No ADR, no conventions change, nothing parked.** `adr_required: false`
   and none needed — the slice borrows the single-source *principle* from
   servo specs 009–010 without adopting servo's JSON format (per the spec's
   Non-goals). `docs/conventions.md` untouched; `docs/refinement-todo.md`
   unchanged (no decisions deferred); nothing added to `docs/inbox.md`.
