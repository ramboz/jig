## Slice 069-01 — builder-consumes-install-contract

**Goal:** Make `build_release_zip.py` derive its include/exclude rules from
`install_contract.py` (the single source of truth) instead of its own
module-level constants, eliminating the build-vs-verify duplication that a
consistency test currently guards. End-to-end value: the release zip's file
set has exactly one definition; changing what ships is a one-place edit.

**DoR:**

- Spec 047 DONE (`install_contract.py` is the validator-facing contract).
- Release build + smoke tests green before the slice starts.
- The current guard
  (`test_install_contract.py::test_exclusion_predicate_matches_build_release_zip`)
  is identified as the test to retire.

**Acceptance Criteria:**

1. **Contract owns the release file set.** `install_contract.py` exposes the
   release-zip include roots/files (including the runtime `scripts/*.py`
   allowlist) and the exclude rules as data, with a pure enumerator/helper
   in its existing stdlib-only, side-effect-free style. Each deliberate
   oddity keeps its rationale comment.
2. **Builder consumes the contract.** `build_release_zip.py` builds its
   entry set from `install_contract.py`; it no longer defines
   `_INCLUDE_ROOTS` / `_INCLUDE_FILES` / `_INCLUDE_SCRIPT_FILES` /
   `_EXCLUDE_*` of its own. No parallel list remains in the builder.
3. **Guard retired.** `test_exclusion_predicate_matches_build_release_zip`
   is removed or repurposed — there is nothing left to keep in sync.
4. **Artifact unchanged.** The built zip contains the identical sorted entry
   set as before the refactor, with deterministic mtime / order / contents
   preserved. A test asserts entry-set (ideally byte) stability across the
   change.
5. **Suite green.** Full test suite green, including the existing build +
   smoke tests and the contract validators.
