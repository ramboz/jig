- [2026-05-28] **RTK (Rust Token Killer) — evaluated, not adopted (spike 044).** v0.42.0 measured against jig's command corpus + filter-customization sub-experiment. Default hook-rewrite mode is misaligned with jig: (a) `rg → grep` rewrite is a correctness regression (rejects rg flags); (b) `git diff` rewrite is `--stat`-only, loses hunks; (c) all `python3` invocations pass through unchanged — and `python3` is jig's hot path (`workflow.py`, `review.py`, `adr.py`, `tdd.py`, `run_tests.py`). Custom `.rtk/filters.toml` is a real mechanism (requires `rtk trust` per project, SHA256 content-hashed), but in v0.42.0 the TOML filters did not appear to apply to transparent hook-rewritten output; the `rtk pipe -f pytest` built-in filter silently discarded jig's custom test-runner output as "no tests collected" (data-loss failure mode on format mismatch). Install also appends `@RTK.md` to user's *global* `~/.claude/CLAUDE.md` — not just hooks. **One genuine lever discovered**: `rtk test python3 scripts/run_tests.py` compresses 8,257 → 200 bytes losslessly (last-5-lines + error detection). But this requires explicit invocation (not auto-rewritten by the hook), and the cost-equivalent native fix is a `--quiet` / `--summary-only` flag on `run_tests.py` itself — same compression, no RTK dependency. If test-output context volume ever becomes a measured bottleneck, file a separate follow-up for that flag, not RTK. **Trigger to re-evaluate RTK itself:** future release that (a) ships first-class `rtk rg` (or stops force-rewriting ripgrep to GNU grep), (b) supports project-local `.claude/settings.json` registration without touching the user-global config, (c) applies `.rtk/filters.toml` to transparent hook rewrites (not just `rtk pipe` mode), (d) labels compressed outputs as such so silent lossy compression is visible, (e) auto-rewrites `python3` invocations via `rtk test` / `rtk smart` (currently `python3` is untouched by the default hook), AND (f) the hook learns to pass `--level minimal` or `--level aggressive` selectively for `rtk read` (currently default is `--level none` = 0% savings on file reads despite the hook firing; aggressive mode delivers 86% on Python source by stubbing function bodies, but is wrong for spec/markdown/review tasks).
