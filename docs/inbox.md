- [2026-05-14] **`land.py` dry-run mode runs the `main`-branch pre-flight unconditionally.** Surfaced when CI fired for the first time on PR [#1](https://github.com/ramboz/jig/pull/1) (slice 013 work). The `ExecuteDryRunTests` in `skills/slice-land/test_land.py` invoke `land.py execute --mode direct --dry-run` from the repo root; the helper calls `git rev-parse --verify main` even though dry-run never actually merges. On GitHub Actions, `actions/checkout@v4` leaves HEAD on the PR's branch and `main` exists only as `origin/main`, so the pre-flight fails with `branch 'main' not found in this repo` and three dry-run tests crash. Worked around in `ci.yml` by `git branch main origin/main` after checkout. **Underlying brittleness remains** — dry-run shouldn't need a real `main`; it should print the *would-be* commands without verifying any branch state. Two fix candidates: (a) gate the main-existence check behind `if not dry_run` so dry-run becomes truly side-effect-free, (b) leave the check but emit a `[dry-run] git rev-parse --verify main (skipped)` line. Either is fine.

- [2026-05-14] **Methodology lesson — direct-inventory > behavioral-introspection for skill-routing tests.** Surfaced during slice 012-01's routing-dogfood (deviation §9). When testing whether a skill router prefers one skill over another, asking the model to *behave* and then *self-report* its routing decision conflates three layers of potential unreliability: routing decision, output production, and metacognitive accuracy. Three independent test sessions all produced the same wrong answer about the available descriptions — looked like signal, was actually three samples of the same hallucination pattern. **Use direct-inventory questions instead**: "list the skills you have access to with X in the name and paste their full description fields verbatim." Harder for the model to confabulate against because it asks for ground-truth enumeration of static metadata rather than introspection of dynamic decisions. Secondary lesson: when LLM-based tests give a suspicious answer, **disambiguate with non-LLM evidence** (terminal `cat`, filesystem inspection, direct API enumeration) before concluding a system bug. The implementer almost applied an AC #9 fallback based on the confabulated reports — only the eventual direct-inventory question pinned the truth. Possible spec implication for future dogfood-style ACs: prefer enumeration-based verification over behavioral-self-report verification.
