- [2026-05-12] `tdd.py` exit-code rule for missing runner modules. Slice 006-01 dogfood surfaced that `python3 -m pytest` exits 1 with stderr `No module named pytest` when pytest isn't installed — indistinguishable from "tests ran and failed." `tdd.py`'s `FileNotFoundError → exit 2` path only catches missing launcher binaries (e.g. `npx`), not missing runner modules. Fixing requires runner-specific stderr parsing (detect `No module named <runner>` and route to exit 2). Out of scope for 006-01 per the slice's "no runner-specific glue" rule; revisit when we hit a real "ambiguous exit 1" incident in the wild.

- [2026-05-12] Dogfood install of jig as a local plugin so subagents register as `subagent_type` values. Today, `agents/implementer.md` and `agents/reviewer.md` live at the correct plugin-root location (per `docs/architecture.md`'s plugin structure), but because jig isn't installed in any dev environment, the runtime never reads them — `subagent_type: "implementer"` is unavailable and every caller falls back to `subagent_type: "general-purpose"` (see `skills/independent-review/SKILL.md`, which already encodes this fallback). The workaround used in sessions today — "I'll follow the implementer.md protocol myself" — silently loses the fresh-context and tool-restriction guarantees that are the whole point of a subagent (especially the reviewer, which exists to be read-only with no prior reasoning). Two directions: (a) **mirror to `.claude/agents/`** in this worktree as a dev convenience — lowest friction, but creates a parallel location to keep in sync and conflicts with the "no shadow copies" spirit of `docs/conventions.md`; (b) **install jig as a local plugin** via a local marketplace pointing at this repo — true dogfood, validates the plugin's published surface (manifest, file layout, install copy) against what the docs claim, catches plugin-install-only bugs we'd otherwise miss until first external user. Strong preference for (b) — it's the only path that exercises the production surface. Likely surfaces a few related questions worth specifying together: how to express "jig is installed locally for development" in `scaffold.json` (or whether it shouldn't show up there at all since jig develops itself), whether `SubagentStart` becomes reachable once agents are real (currently parked as a deferred open question in `docs/architecture.md`), and whether `independent-review`'s `subagent_type: "general-purpose"` fallback should be replaced with `"reviewer"` once available (with graceful degradation when the plugin isn't installed). Candidate spec name: `008-plugin-self-install` or similar.
