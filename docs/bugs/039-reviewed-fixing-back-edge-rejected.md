# Bug 039: reviewed-fixing-back-edge-rejected

Reported: GitHub issue 235 (against v2.16.0). Re-confirmed on `origin/main@5cdfe032`.

## Symptom

ADR-0016 §1 (line 151) and `skills/bug-fix/SKILL.md` (Lifecycle) document
`REVIEWED → FIXING` as an ungated back-edge ("review needs changes"), but
`bug.py transition <id> FIXING` from `REVIEWED` fails with
`invalid transition: REVIEWED -> FIXING`. The only way back is
`REVIEWED → DIAGNOSING → ROOT_CAUSED → FIXING`, which re-runs the diagnose gate
and needs a new red witness — impossible without reverting the fix.

## Repro

Scratch harness (temp project, record at `REVIEWED`, `JIG_TDD_HELPER` → exit 0,
passing `bug-review` + `craft` verdicts dated 2026-06-30) calling
`bug.transition_bug(root, "001", "FIXING")`:

```
(a) REJECTED: invalid transition: REVIEWED -> FIXING
(b) naive edge: REJECTED: the regression test passes without a fix — it does not capture the bug
(c) second REVIEWED cleared by OLD 2026-06-30 verdicts
```

(b) = the same call with `"FIXING"` patched into `_ORDERED_TRANSITIONS["REVIEWED"]`.
(c) = record set back to `FIXING`, then `transition_bug(..., "REVIEWED")` with
the untouched first-round verdicts.

## Evidence

- `skills/bug-fix/bug.py:84` — `"REVIEWED": {"VERIFIED", "DONE", "DIAGNOSING"}`;
  unchanged since it was introduced in 31cbcb4e (2026-06-23, "add transition
  gates") — the doc/code split is original, not a regression.
- `skills/bug-fix/bug.py:897` — the FIXING entry gates are keyed on
  `new_status == "FIXING"` only, not on `current`; they include the
  red-test gate, which necessarily fails once the fix is in (repro (b)).
- `skills/_common/review_evidence.py:610` `validate_bug_evidence` checks
  presence + `verdict: pass` only; `reviewed_at` is required but never compared
  against anything (repro (c)). The module docstring (lines 27-33) and
  `docs/refinement-todo.md:219` record general code-staleness gating as DEFERRED.
- No test in `skills/bug-fix/test_bug.py` exercises `REVIEWED → FIXING` either way.

## Hypotheses

- [ ] H1: the stricter path (`REVIEWED → DIAGNOSING`) is intended and the docs are
  wrong. Falsify by: ADR-0016 explicitly names the back-edge with its rationale
  ("review needs changes") and the strict path cannot be walked without
  reverting the fix (new red witness required) — falsified; owner also chose
  code-matches-docs on 2026-10-04.
- [ ] H2: the edge is allowed but blocked elsewhere (e.g. a claim/marker guard).
  Falsify by: `_validate_order` raises before any other gate — falsified by
  repro (a) message and `bug.py:871`.
- [x] H3 (leading): omission in `_ORDERED_TRANSITIONS` at authoring time, and the
  FIXING gate block was written assuming the only entry is `ROOT_CAUSED`.
  Confirmed by repro (a) + (b) and the single-commit history.

## Root cause

Process, not output: `bug.py` models FIXING-entry gates as properties of the
*target* state, but they are really properties of the forward edge
`ROOT_CAUSED → FIXING` (diagnosis-time checks: fresh-main recheck, fix_class,
closure inventory, red witness). Because the gates were bound to the target,
the documented back-edge could not be added without tripping them, and the
edge was simply left out of `_ORDERED_TRANSITIONS`. The same
target-not-edge framing leaves the `REVIEWED` evidence gate blind to *when* a
verdict was produced, so a re-entry after a back-edge would be cleared by the
previous round's verdicts.

Grounding (ADR-0052): `_ORDERED_TRANSITIONS` is read at exactly one site
(`bug.py:871`), and `validate_bug_evidence` is called at exactly two
(`bug.py:987` REVIEWED, `bug.py:1007` DONE) — `git grep` over `skills/` +
`scripts/`; these are plain module-level names with no reflection/codegen
indirection, and `hosts/` holds generated byte-copies (regenerated by
`scripts/build_host_packages.py`), so the search closes the set.

## Fix class

`structural_fix` — rebinds the FIXING entry gates to the forward edge and makes review evidence event-fresh after a back-edge.

## Fix

Owner decisions (2026-10-04): code matches docs; re-entry needs verdicts newer
than the back-edge; fix spec-workflow's convergent back-edges in the same change.

- `skills/bug-fix/bug.py` — `"FIXING"` added to `_ORDERED_TRANSITIONS["REVIEWED"]`;
  the FIXING entry gates run only when `current != "REVIEWED"` (forward edge);
  every review back-edge (`REVIEWED → FIXING`, `FIXING`/`REVIEWED`/`VERIFIED →
  DIAGNOSING`, and the failed-green-check route to `DIAGNOSING`) stamps `review_reopened_at`
  (UTC, seconds).
- `skills/_common/review_evidence.py` — `REOPENED_FIELD`, `now_iso8601()`,
  `stale_after_reopen_problem()` (strictly-newer; malformed stamp or
  `reviewed_at` fails closed). Wired into `validate_bug_evidence` (REVIEWED +
  DONE) and `validate_evidence` (every stage except the one-time
  pre-implementation `READY_FOR_REVIEW` frame-critique). `_review_flag`
  refactored onto a shared `_slice_field` reader.
- `skills/spec-workflow/workflow.py` — any exit from `REVIEWED`/`RECONCILED`/`DONE`
  to a non-review state stamps `review_reopened_at` on frontmatter slices.
- `skills/independent-review/review.py` — `_now_iso8601` delegates to the shared
  `review_evidence.now_iso8601`, so the verdict writer and the stamp share one
  format.

- Docs: `skills/bug-fix/SKILL.md` (lifecycle + gate table), `docs/workflow.md`,
  ADR-0016 `## Amendments` (owner-approved), `docs/refinement-todo.md`
  code-staleness item marked partial; `hosts/` regenerated.

Known residuals (intentional): moves within the review family
(e.g. `RECONCILED → REVIEWED`) don't stamp — no implementation work, target
itself gated. Legacy prose-only slices have no frontmatter to
carry the stamp — unenforced. Second precision means a verdict recorded in the
same second as the reopen is refused (fails closed; re-record). The stamp is
never cleared after a successful re-review — harmless, later verdicts are
newer. ADR-0014 (Accepted) is not amended; the partial resolution of its
deferred code-staleness item is noted in `docs/refinement-todo.md`.
